"Walk me through a Modbus RTU request, from the first byte to the reply, including how a slave decides to stay silent." Answer out loud, then compare.

Model answer

The slave waits for a silence of 3.5 character times, then treats the bytes as one frame. It checks the length, the address, and the CRC-16/MODBUS over everything but the last two bytes. A bad CRC or another slave's address gets no reply. For a valid request the slave builds the response: for function 03, the address, function, byte count and registers big-endian; for function 06, an echo. If it cannot honour the request, it sends an exception with the high bit of the function code set.

"How does a bootloader validate a new image and hand over to it, and how does a device recover from a bad update?" Answer out loud, then compare.

Model answer

The bootloader reads the image header: the magic, the vector offset and the image end. It checks the stack pointer points into SRAM, the reset address has the Thumb bit set and lies inside the image. To hand over, it disables interrupts, sets VTOR to the application's table, loads the stack pointer from word zero, and branches to the reset handler. For a bad update, a trial counter runs the new image in test mode. If it does not confirm itself before the counter runs out, the bootloader reverts to the old image.

"How would you threat-model a connected sensor, and what would you do first on the chip?" Answer out loud, then compare.

Model answer

I would list the assets, the interfaces (debug, update path, bus messages, commands) and the trust boundaries, then tag each threat by STRIDE: tampering with the image, information disclosure through the debug port, spoofing of the server, denial of service from a malformed frame, and elevation of privilege from a command. On the chip, the first step is a chain of trust from a root of trust that cannot change, through a bootloader that verifies a signed image against a fingerprint in one-time memory, then closing the debug port. I would not rely on a CRC, which anyone can recompute.
