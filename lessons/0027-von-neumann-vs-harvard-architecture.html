Von Neumann vs Harvard architecture

Every instruction is fetched from memory and most of them also touch memory. How many paths the core has to memory decides what a loop costs.

By the end of this lesson you can say whether a Cortex-M core can fetch an instruction and load data in the same cycle, name the bus that proves it, and count the bus transfers in a short program.

The idea

A von Neumann design keeps the program and the data in one memory and reaches it over one path. The CPU cannot fetch the next instruction while it is loading a value, because both go over the same wires. A Harvard design gives instructions and data separate memories and separate paths, so the core can fetch and load at the same time. The names describe the paths, not the address map. A Cortex-M core has one address space, which both designs use. The Harvard split is about how many buses reach it.

The Cortex-M3 is a Harvard design. Arm's TRM describes it as a "Harvard processor architecture enabling simultaneous instruction fetch with data load/store" (Arm Cortex-M3 TRM DDI0337G, §1.1). It has three bus interfaces: the I-Code bus for instruction fetches from code memory (§12.3), the D-Code bus for literal and constant data in the code region (§12.4), and the System bus for SRAM and peripherals (§12.5). All three are AHB-Lite.

The Cortex-M0+ in the RP2040 is different. Arm's datasheet describes one 32-bit AMBA-3 AHB-Lite system interface that serves the whole system, and says that instructions are only fetched using the AHB-Lite interface (Arm Cortex-M0+ processor datasheet). Arm's datasheet summarises that bus as a von Neumann bus architecture. The RP2040 datasheet adds that each of its two M0+ cores has a dedicated AHB-Lite port for code fetch, loads and stores. The SIO block also has a single-cycle IOPORT bus for GPIO (RP2040 datasheet, §2.3 and Figure 6). So the chip has more than one path, but the core itself has one memory port.

Why a loop feels the difference

Take a loop that loads a value, adds it to a total and repeats. Each instruction needs one fetch, and each load needs one more transfer for the data. On a single bus those transfers queue up. On a Harvard core, the fetch of the next instruction can overlap the load of the current data, so the loop can go faster. Real speed depends on wait states, the bus matrix and caches, which later lessons cover (lesson 36 and lesson 37). The bus count is the first thing to understand.

Try it in the CPU simulator

The simulator in this lesson is a simplified teaching model. It runs a small instruction subset on one memory map and does not model separate buses, so it cannot show the overlap. What it does show is what each instruction reads and writes, which lets you count the transfers. The program stores 7 into RAM and loads it back.

  1. Before you press anything, count the transfers on one shared bus for the first four instructions. Count one fetch per instruction, and one extra transfer for each STR and each LDR.
  2. Press Instruction four times and watch the memory row and the register row change. Check that the STR writes to 0x20000010 and the LDR reads it back into R1.
  3. The fifth instruction is B ., which halts the program. Do not step past it: the simulator shows it as a branch to itself.
Hint

Each of the four instructions needs one fetch. The STR and the LDR each need one data transfer, and the two MOVs need none. Add the fetches and the data transfers together.

The simulator has one memory map, one bus and no cache. Real Cortex-M cores have several buses (Harvard on the M3, one AHB-Lite port on the M0+), and the bus fabric in the RP2040 has its own crossbar (RP2040 datasheet, §2.1). The simulator's "one bus" count is a teaching shortcut. The real chips do not count transfers the same way.

You counted the bus transfers for a short program, and you can say why a Harvard core can overlap a fetch with a load while a von Neumann core cannot.

"What is the difference between von Neumann and Harvard architecture, and which one does a Cortex-M3 use?" Answer out loud in 60 seconds, then compare.

Model answer

Von Neumann has one memory and one path shared by instructions and data, so fetches and loads take turns. Harvard has separate instruction and data paths, so the core can fetch and load at once. The Cortex-M3 is Harvard, with I-Code, D-Code and System buses. Both designs share one address map, so the split is about buses, not addresses.

Arm Cortex-M3 Technical Reference Manual, DDI0337G: read §1.1 (the Harvard statement) and §12 (the bus interfaces). The Arm Cortex-M3 Devices Generic User Guide (DUI0552) is the companion overview, which we have not checked line by line for this lesson.
