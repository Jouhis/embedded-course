Number systems

A register holds only bits. Whether 0xFF means 255 or −1 depends on the instruction that reads it, and datasheets and bug reports assume you can switch between the two readings.

By the end of this lesson you can convert an 8-bit pattern between binary, hex and decimal, and read it as a signed value in two's complement, without a calculator.

Where we are and why it matters

Lesson 18 showed you the register tables in a datasheet: a box for each register, a name for each field, and a reset value in hex. This lesson teaches you how to read the numbers in those boxes. Every later lesson in this part uses them. The bit masks in lesson 20 are written in hex, the adder in lesson 23 works on bits, and the fixed-point numbers in lesson 21 are integers with a point you imagine.

The problem shows up on real hardware all the time. A temperature sensor returns the raw value 0xFFF and your code prints 4095 degrees, or −1 degree, depending on how you read the same twelve bits. An engineer who can switch between the readings in their head finds that bug in minutes. One who cannot spends an afternoon with a serial monitor. The skill is not hard, but it has to be automatic before the rest of the course makes sense.

Bits, nibbles and bytes

A bit is the smallest unit of storage, and it holds a 0 or a 1. Inside the chip each bit is one small storage circuit, and the physical state of that circuit is a voltage: high or low on the wire (lesson 16 described logic levels). A group of bits is a register when it lives inside a peripheral, or a word when it lives in memory. The Cortex-M cores you will program have 32-bit registers, and their data bus is 32 bits wide. The Arm Cortex-M0+ datasheet describes a single 32-bit AHB-Lite interface (Arm Cortex-M0+ datasheet), so one bus transfer moves 32 bits at once, each on its own wire.

Bits are numbered from the right. Bit 0 is the least significant bit, which has the weight 1, and bit 31 is the most significant. A nibble is four bits, and a byte is eight. The nibble is the useful unit for reading, because one hex digit stands for exactly one nibble.

Positional notation: why 0x2C is 44

Every number system you have used works the same way. Each digit has a weight that is a power of the base, and the value is the sum of digit times weight. In decimal the base is 10, so 345 is 3 × 100 + 4 × 10 + 5 × 1. In binary the base is 2, and each place holds a 0 or a 1. In hexadecimal the base is 16, and each place holds one of 0 to 9 and A to F, where A is 10 and F is 15.

Hex is used for registers because the base is a power of two. Sixteen is 24, so one hex digit covers exactly four bits, and two hex digits cover one byte. There is no rounding and no carrying between groups, which is why a datasheet shows a 32-bit register as eight hex digits. The bit pattern is the same in every base; only the way you write it changes. The C prefix 0x marks hex, and the prefix 0b marks binary, which GCC accepts as an extension.

Worked example: convert 0x2C

Take the value written in the datasheet as 0x2C. Work it through one step at a time.

  1. Split the two hex digits. The high digit is 2, the low digit is C.
  2. Write each digit as four bits. 2 is 0010. C is 12, which is 1100.
  3. Join them: 0010 1100. Bit 5 is 1, bit 3 is 1, bit 2 is 1, and every other bit is 0.
  4. Add the weights of the set bits: 32 + 8 + 4 = 44. Check the high nibble on its own: 2 × 16 = 32, and the low nibble gives 12, so 32 + 12 = 44.

The same eight bits are 0x2C, 44 and 0010 1100. A register field view makes the bits visible: the widget below shows the high nibble and the low nibble as separate fields, which is how most datasheets draw them.

Click a bit above and watch the four values change together. The binary, the hex and the unsigned decimal are three names for the same eight bits. The hex digit for the high nibble changes only when a bit in bits 7 to 4 changes, so when you read a datasheet field you can read its hex digit on its own.

Two's complement: the same bits as a signed number

A register has no sign of its own. It holds bits, and the reading of the top bit is a choice made by the instruction or the programmer. To store negative numbers, almost every processor uses two's complement. In an 8-bit register bit 7 has the weight −128 instead of +128, and every other bit keeps its normal weight. A pattern with bit 7 set is negative. Harris and Harris, chapter 1 (From Zero to One) shows the same rule with the full number line. The Cortex-M instruction set has separate signed and unsigned compare conditions, so the same bits can be read either way (lesson 26).

value = −b7·128 + b6·64 + b5·32 + … + b0·1

Adding two patterns with the normal binary adder gives the same answer whether you read the bits as signed or unsigned, because the carries do not care about the reading. Only the final interpretation changes. That is why a Cortex-M core needs one adder for both kinds of arithmetic, and the instructions differ only in how they set the flags (lesson 26).

Worked example: negate 5, then negate 0xA7

To negate a value, flip every bit and add one. Take 5, which is 0000 0101. Flipping gives 1111 1010. Adding one gives 1111 1011, which is 0xFB. Read as unsigned it is 251. Read as signed it is 251 − 256 = −5, which is the answer you wanted.

Now take a harder pattern, 0xA7, and work out both readings.

  1. Unsigned: 0xA7 is 1010 0111, so 128 + 32 + 4 + 2 + 1 = 167.
  2. Signed: bit 7 is set, so subtract 256. 167 − 256 = −89.
  3. Negate the bits: flipping 1010 0111 gives 0101 1000, and adding one gives 0101 1001, which is 0x59 = 89. The negation of −89 is +89, as it should be.
  4. Check: 0xA7 + 0x59 = 0x100. The sum is 256, which carries out of the eight bits and leaves 0. Two values that add to zero modulo 256 are negatives of each other.

The last step is the reason two's complement is used. An 8-bit adder that throws away the carry out of bit 7 turns 0xA7 + 0x59 into zero, so the same circuit does subtraction by adding a negated value. The processor never needs a separate subtract circuit for signed numbers.

The signed range of an 8-bit register is −128 to +127, not −127 to +127. Zero takes one of the 256 patterns, so there is one more negative value than positive. Code that negates −128 overflows, which is a classic bug (lesson 45).
  1. Start from the datasheet value 0x2C: two hex digits, 2 and C.
  2. Each hex digit is exactly four bits. 2 is 0010 and C, which is 12, is 1100. Join them: 0010 1100.
  3. Bits are numbered from the right, and bit n has the weight 2n: 1, 2, 4 and so on up to 128 for bit 7.
  4. Add the weights of the bits that are 1: 32 + 8 + 4 = 44. The same eight bits are 0x2C, 44 and 0010 1100.
  5. Now 0xA7, read as a signed 8-bit number. In two's complement bit 7 has the weight −128, so the value is −128 + 32 + 4 + 2 + 1 = −89.
  6. To negate it, flip every bit: 1010 0111 becomes 0101 1000, which is 0x58.
  7. Then add one: 0x59, which is 89. Check: 0xA7 + 0x59 = 0x100, and an 8-bit adder drops the carry, leaving 0.

The same rule at other widths

The rule does not change with the width. A 16-bit register has bit 15 with weight −32768, so 0x8000 is −32768 and 0xFFFF is −1. A 32-bit register has bit 31 with weight −231. The pattern of a negative number always has its top bit set, and the most negative value always has the top bit set and nothing else. Widening a signed value needs care, and lesson 45 covers the promotion rules that do this for you in C. Take 0x8001 as an example. Unsigned, it is 32769. Signed, bit 15 contributes −32768 and bit 0 contributes 1, so the value is −32767.

When a signed 8-bit value such as 0xA7 (−89) is copied into a 16-bit register, the hardware extends the sign: the new upper bits take the value of the old bit 7. The 16-bit result is 0xFFA7. Check it: 0xFFA7 is 65447, and 65447 − 65536 = −89, so the value did not change. Copying an unsigned value instead fills the upper bits with zeros, which gives 0x00A7 = 167. The same bits give two different answers depending on whether the copy extends the sign, which is why the type of each variable matters.

A real case: a 12-bit ADC returns a count from 0 to 4095 (lesson 58 uses that range). The count is unsigned, so 0xFFF is 4095. If the same twelve bits were treated as a signed 12-bit value, they would be −1. The sensor did not change. Only the reading did, and that is exactly the kind of bug that a datasheet's "unsigned" or "signed" field name is there to prevent.

Common mistakes and how to spot them

Four mistakes come up again and again with this topic. Each one has a symptom you can see, and a fix.

  1. Reading hex digits as decimal. Someone writes 0x2C and reads it as "two hundred and twelve", because the digits look like decimal digits. The symptom is a value that is too large by a factor that does not look like a bug. The fix is the positional rule above: each hex digit is worth 0 to 15, and the high digit is multiplied by 16.
  2. Reading an unsigned register as signed. A raw ADC count of 255 stored in a signed 8-bit variable prints as −1. The symptom is a negative reading from a sensor that cannot go negative. The fix is to keep raw register values in unsigned types such as uint8_t or uint32_t, and to convert to a signed value only when the physical quantity really is signed.
  3. A leading zero in a constant. In C, a number that starts with a zero is octal, so int period = 010; stores 8, not 10. The symptom is a timing or count that is off by a small amount that depends on the digits. The fix is never to write a leading zero on a decimal constant, and to use 0x or 0b when the number is a bit pattern.
  4. Negating the most negative value. In 8-bit two's complement, −128 flipped is 0x7F and adding one gives 0x80 again, so −(−128) is still −128. The symptom is an absolute-value function that returns a negative number. The fix is to test for the most negative value before you negate it.

In real projects

In a professional codebase, register values are written as hex, because the datasheet is written in hex. Register headers use #define names and hex addresses. The STM32F103 device header, stm32f103xb.h, defines each block with a hex offset, for example GPIOA_BASE as APB2PERIPH_BASE + 0x00000800UL. A reviewer checks that a hex constant is written with the full width of its field, so a 4-bit field is written as one hex digit and a 16-bit value as four. Code review also looks for signed and unsigned mixes, because the compiler's warning for them is easy to ignore.

Summary

  • A bit holds a 0 or a 1. A register is a group of bits, and its meaning depends on the instruction that reads it.
  • Hex uses one digit per four bits, so two hex digits make one byte. Hex is a notation for bit patterns, not a different kind of number.
  • Positional notation gives the value: each digit times its weight, where the weights are powers of the base.
  • In an n-bit two's complement register, the top bit has weight −2n−1. The pattern 0xFF is 255 unsigned and −1 signed.
  • To negate a value, flip every bit and add one. The adder does not need a separate signed circuit.
  • The most negative value has no positive partner, so negating it overflows.
  • Keep raw register values unsigned, write each hex constant at the full width of its field, and never write a leading zero on a decimal constant.
