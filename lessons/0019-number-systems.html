Number systems

A register holds only bits. Whether 0xFF means 255 or −1 depends on the instruction that reads it, and every datasheet and every bug report assumes you can switch between the two readings.

By the end of this lesson you can convert an 8-bit pattern between binary, hex and decimal, and read it as a signed value in two's complement, without a calculator.

The idea

A bit is a 0 or a 1. A group of bits is a register or a memory word. The CPU does not store "numbers". It stores patterns, and each instruction decides how to read a pattern. An unsigned add and a signed compare read the same bits in different ways. The RP2040 datasheet describes its registers as bit patterns, with each field's meaning given separately. RP2040 datasheet, section 2 is the place to see this for yourself. A Cortex-M core has 32-bit registers (R0 to R12, SP, LR, PC, lesson 31). Bit 0 is the least significant bit, and bit 31 the most significant.

Hex is a short way to write a bit pattern. One hex digit is one nibble (four bits), so two hex digits make one byte. 0x2C is 0010 1100 in binary, which is 2 × 16 + 12 = 44 in decimal. Hex is for people: the bits are the same whichever base you write them in.

Click a bit above and watch the four values change together. The binary, the hex and the unsigned decimal are three names for the same eight bits.

Two's complement: the same bits as a signed number

To store negative numbers, a binary register uses two's complement. In an 8-bit register the top bit (bit 7) has the weight −128 instead of +128, and the other bits keep their normal weights. A pattern with bit 7 set is negative. Harris and Harris, chapter 1 (From Zero to One) shows the same rule with the full number line. Two's complement is what almost every processor uses today. The Cortex-M instruction set has separate signed and unsigned compare conditions, so the same bits can be read either way (lesson 26).

value = −b7·128 + b6·64 + b5·32 + … + b0·1

To negate a value, flip every bit and add one. Take 5 (0000 0101): flip the bits to get 1111 1010, then add one to get 1111 1011, which is 0xFB. Read as unsigned it is 251. Read as signed it is 251 − 256 = −5, and the rule gives the same answer. Negating twice gives back 5.

The signed range of an 8-bit register is −128 to +127, not −127 to +127. Zero takes one of the 256 patterns, so there is one more negative value than positive. Code that negates −128 overflows, which is a classic bug (lesson 45).

Hint for the signed questions

If bit 7 is 0, the value is the unsigned value. If bit 7 is 1, subtract 256 from the unsigned value.

You can read one bit pattern three ways (binary, hex, and signed or unsigned decimal) and you can negate a value by flipping the bits and adding one. Every later lesson assumes you can do this without thinking.

Model answer

The bits are the same, so 0xFF is 255 unsigned and −1 signed. The meaning depends on the instruction that reads it. To negate, invert every bit and add one. The top bit carries weight −2n−1, which is why the most negative value has no positive partner and negating it overflows.
