Number systems

Binary, hexadecimal and two's complement

By the end of this lesson you can convert an 8-bit pattern between binary, hex and decimal, and read it as a signed value in two's complement, without a calculator.

Numbers in registers and datasheets

Lesson 18 read the numbers in a MOSFET datasheet. A microcontroller's datasheet adds register tables, with a box for each register, a name for each field and a reset value written in hex, and this lesson teaches you to read the numbers in those boxes. Every later lesson in this part depends on it: the bit masks in lesson 20 are written in hex, the fixed-point numbers in lesson 21 are integers with an imagined point, and the adder in lesson 23 works directly on bits.

The skill matters constantly on real hardware. A temperature sensor returns the raw value 0xFFF, and your code prints either 4095 degrees or −1 degree depending on how the same twelve bits are read. An engineer who can switch between the two readings mentally finds that bug in minutes, while one who cannot may spend an afternoon with a serial monitor. The skill itself is easy, but it needs to become automatic before the rest of the course makes sense.

Bits, nibbles and bytes

A bit is the smallest unit of storage and holds a 0 or a 1. Inside the chip each bit is a small storage circuit whose state is a voltage, high or low on a wire, as lesson 16 described for logic levels. A group of bits is called a register when it lives inside a peripheral and a word when it lives in memory. The Cortex-M cores you will program have 32-bit registers and a 32-bit data bus; the Arm Cortex-M0+ datasheet describes a single 32-bit AHB-Lite interface (Arm Cortex-M0+ datasheet), so one bus transfer moves 32 bits at once, each on its own wire.

Bits are numbered from the right. Bit 0 is the least significant bit, with weight 1, and bit 31 is the most significant. A nibble is four bits and a byte eight, and the nibble is the useful unit for reading, because one hex digit stands for exactly one nibble.

Positional notation in binary and hexadecimal

Every number system you have used works the same way: each digit has a weight that is a power of the base, and the value is the sum of each digit times its weight. For a number with digits di in base b,

value = Σ di × bi(1)

where i counts the positions from 0 at the right. In decimal the base is 10, so 345 is 3 × 100 + 4 × 10 + 5 × 1. In binary the base is 2 and each place holds a 0 or a 1, and in hexadecimal the base is 16, with each place holding 0 to 9 or A to F, where A is 10 and F is 15.

Hex suits registers because its base is a power of two. Since 16 is 24, one hex digit covers exactly four bits and two cover one byte, with no rounding or carrying between groups, which is why a datasheet shows a 32-bit register as eight hex digits. The bit pattern is identical in every base and only its written form changes. In C the prefix 0x marks hex and the prefix 0b marks binary, which GCC accepts as an extension.

Worked example: converting 0x2C

Take the value written in a datasheet as 0x2C and convert it one step at a time. Before starting, estimate whether it is above or below 50.

  1. Split the two hex digits. The high digit is 2 and the low digit is C.
  2. Write each digit as four bits. 2 is 0010, and C is 12, which is 1100.
  3. Join them into 0010 1100. Bits 5, 3 and 2 are 1, and every other bit is 0.
  4. Add the weights of the set bits: 32 + 8 + 4 = 44. As a check, the high nibble alone gives 2 × 16 = 32 and the low nibble 12, so 32 + 12 = 44.

The same eight bits are therefore 0x2C, 44 and 0010 1100. A register field view makes the bits visible, and the widget below shows the high and low nibbles as separate fields, which is how most datasheets draw them.

Click a bit above and watch all four values change together, since the binary, the hex and the unsigned decimal are three names for the same eight bits. The hex digit for the high nibble changes only when one of bits 7 to 4 changes, so a datasheet field can be read from its own hex digit alone.

Two's complement signed numbers

A register has no sign of its own. It holds bits, and how the top bit is read is decided by the instruction or the programmer. To store negative numbers almost every processor uses two's complement, in which bit 7 of an 8-bit register has the weight −128 instead of +128 while every other bit keeps its normal weight, so any pattern with bit 7 set is negative. Harris and Harris, chapter 1 (From Zero to One) shows the same rule with the full number line. The Cortex-M instruction set has separate signed and unsigned compare conditions, so the same bits can be read either way (lesson 26).

For an 8-bit pattern with bits b7 to b0, the signed value is

value = −b7·128 + b6·64 + b5·32 + … + b0·1(2)

where each b is 0 or 1. Adding two patterns with an ordinary binary adder gives the same bits whether they are read as signed or unsigned, because the carries do not depend on the reading, and only the final interpretation differs. A Cortex-M core therefore needs a single adder for both kinds of arithmetic, and its instructions differ only in how they set the flags (lesson 26).

Worked example: negating 5 and reading 0xA7

To negate a value, flip every bit and add one. Take 5, which is 0000 0101: flipping gives 1111 1010, and adding one gives 1111 1011, or 0xFB. Read as unsigned it is 251, and read as signed it is 251 − 256 = −5, the expected answer.

Picture an old car odometer showing 0000. Rolled back one kilometre, it shows 9999, and two's complement reads that as −1, because the numbers just below zero are the ones at the top of the dial. A four-digit odometer has 10 000 positions and an 8-bit register 256, and two's complement splits them in half, so 0x00 to 0x7F count up from zero while 0x80 to 0xFF are the negative numbers, with 0xFF as −1. The comparison ends at the split itself, since an odometer has no rule for which readings count as negative, whereas two's complement fixes that rule in the top bit.

A harder pattern, 0xA7, shows both readings and a check.

  1. Unsigned: 0xA7 is 1010 0111, so 128 + 32 + 4 + 2 + 1 = 167.
  2. Signed: bit 7 is set, so subtract 256, giving 167 − 256 = −89.
  3. Negate the bits: flipping 1010 0111 gives 0101 1000, and adding one gives 0101 1001, which is 0x59 = 89. The negation of −89 is +89, as it should be.
  4. Check: 0xA7 + 0x59 = 0x100. The sum of 256 carries out of the eight bits and leaves 0, and two values that add to zero modulo 256 are negatives of each other.

That last step is why two's complement is used. An 8-bit adder that discards the carry out of bit 7 turns 0xA7 + 0x59 into zero, so the same circuit performs subtraction by adding a negated value, and the processor needs no separate subtraction circuit for signed numbers.

The signed range of an 8-bit register is −128 to +127, not −127 to +127. Zero takes one of the 256 patterns, leaving one more negative value than positive ones, so code that negates −128 overflows, a classic bug (lesson 45).
  1. Start from the datasheet value 0x2C: two hex digits, 2 and C.
  2. Each hex digit is exactly four bits. 2 is 0010 and C, which is 12, is 1100. Join them: 0010 1100.
  3. Bits are numbered from the right, and bit n has the weight 2n: 1, 2, 4 and so on up to 128 for bit 7.
  4. Add the weights of the bits that are 1: 32 + 8 + 4 = 44. The same eight bits are 0x2C, 44 and 0010 1100.
  5. Now 0xA7, read as a signed 8-bit number. In two's complement bit 7 has the weight −128, so the value is −128 + 32 + 4 + 2 + 1 = −89.
  6. To negate it, flip every bit: 1010 0111 becomes 0101 1000, which is 0x58.
  7. Then add one: 0x59, which is 89. Check: 0xA7 + 0x59 = 0x100, and an 8-bit adder drops the carry, leaving 0.

Two's complement at 16 and 32 bits

The rule is the same at every width. In a 16-bit register bit 15 has weight −32768, so 0x8000 is −32768 and 0xFFFF is −1, and in a 32-bit register bit 31 has weight −231. A negative number always has its top bit set, and the most negative value has the top bit set and nothing else. As an example, 0x8001 is 32769 unsigned, while signed, bit 15 contributes −32768 and bit 0 contributes 1, giving −32767.

Widening a signed value needs care, and lesson 45 covers the C promotion rules that handle it. When a signed 8-bit value such as 0xA7 (−89) is copied into a 16-bit register, the hardware extends the sign, filling the new upper bits with the old bit 7, so the result is 0xFFA7. This checks out, since 0xFFA7 is 65447 and 65447 − 65536 = −89. Copying an unsigned value instead fills the upper bits with zeros and gives 0x00A7 = 167, so the same bits yield two answers depending on whether the copy extends the sign, which is why each variable's type matters.

A real case makes this concrete. A 12-bit ADC returns a count from 0 to 4095, the range lesson 58 uses, and since the count is unsigned, 0xFFF means 4095. Treated as a signed 12-bit value, the same twelve bits would mean −1. The sensor is unchanged and only the reading differs, which is exactly the kind of bug a datasheet's "unsigned" or "signed" field description exists to prevent.

Common mistakes and how to spot them

Four mistakes come up again and again with this topic, each with a visible symptom and a fix.

Hex digits read as decimal

Someone sees 0x2C and treats its digits like decimal ones, so the value comes out too large by a factor that does not look like a bug. Apply the positional rule: each hex digit is worth 0 to 15, and the high digit is multiplied by 16.

An unsigned register read as signed

A raw ADC count of 255 stored in a signed 8-bit variable prints as −1, a negative reading from a sensor that cannot go negative. Keep raw register values in unsigned types such as uint8_t or uint32_t, and convert to a signed value only when the physical quantity really is signed.

A leading zero in a constant

In C a number starting with a zero is octal, so int period = 010; stores 8 rather than 10, and a timing or count is off by a small amount that depends on the digits. Never write a leading zero on a decimal constant, and use 0x or 0b when the number is a bit pattern.

Negating the most negative value

In 8-bit two's complement, −128 flipped is 0x7F and adding one gives 0x80 again, so −(−128) is still −128, and an absolute-value function returns a negative number. Test for the most negative value before negating it.

Hex constants in real codebases

In a professional codebase register values are written in hex, because the datasheet is written in hex. Register headers use #define names with hex addresses; the STM32F103 device header, stm32f103xb.h, defines each block with a hex offset, for example GPIOA_BASE as APB2PERIPH_BASE + 0x00000800UL. A reviewer checks that each hex constant is written at the full width of its field, one hex digit for a 4-bit field and four for a 16-bit value. Code review also looks for mixed signed and unsigned arithmetic, because the compiler's warning for it is easy to ignore.

Summary

  • A bit holds a 0 or a 1, and a register is a group of bits whose meaning depends on the instruction that reads it.
  • Hex uses one digit per four bits, so two hex digits make one byte. Hex is a notation for bit patterns rather than a different kind of number.
  • Positional notation gives the value as the sum of each digit times its weight, where the weights are powers of the base.
  • In an n-bit two's complement register the top bit has weight −2n−1, so the pattern 0xFF is 255 unsigned and −1 signed.
  • To negate a value, flip every bit and add one; the adder needs no separate signed circuit.
  • The most negative value has no positive partner, so negating it overflows.
  • Keep raw register values unsigned, write each hex constant at the full width of its field, and never put a leading zero on a decimal constant.
