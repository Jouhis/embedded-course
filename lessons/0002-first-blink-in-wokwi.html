First blink in Wokwi

You will build a Pico program, run it in a simulator, and change it the way firmware engineers do: small edits, rebuild, observe.

By the end of this lesson you can change a Pico blink to 5 Hz and wire a second LED that blinks in alternation with the on-board one, then see both work in the Wokwi simulator.

The idea

A Pico program is a C file, main.c, that the build turns into a firmware image. The Pico SDK supplies the functions it calls. The on-board LED is wired to GPIO 25, so writing 1 to that pin lights it. Wokwi's Pi Pico page confirms the GPIO 25 wiring and the GP pin names you will use. A GPIO pin is a single digital pin the CPU can drive high or low. Writing it is a bus write to a memory-mapped register, which is what lesson 38 covers.

The main loop turns the LED on, waits, turns it off and waits again. sleep_ms() is blocking: the CPU does nothing else until the time has passed. That is fine for a blink. Lesson 55 replaces it with a non-blocking loop.

The project, file by file

The generator created the project in projects/0002-first-blink. It has two folders: starter, which you edit, and solution, which you compare with after you try.

FileWhat it is for
main.cYour program. Compiled into the firmware.
diagram.jsonThe circuit: which parts exist (parts) and which pins are wired together (connections). Wokwi reads it to build the simulated board.
wokwi.tomlTells the simulator where the firmware is (elf = 'build/blink.elf') and the port the GDB server listens on (gdbServerPort = 3333). VS Code's debug configuration connects to that port.
CMakeLists.txtThe build recipe. It names the program blink and links the Pico SDK.
build/blink.elfThe build output, created when you build. The ELF file from lesson 1: firmware with symbols. Wokwi loads this file.

In diagram.json, the two connections lines wire GP0 to the serial monitor's RX and GP1 to its TX. The template's CMakeLists.txt enables UART output for printf, so that text reaches the serial monitor through those wires. Wokwi's Pi Pico page uses the same GP0 and GP1 pins for its serial example.

The loop: build, then simulate

Every change follows the same loop. Edit main.c, build, then start the simulator. The simulator loads the newest ELF file, so it always runs the code you just built. Use F5 instead of starting the simulator when you want to pause and step. Debugging is lesson 54.

In VS Code, open the starter folder (File → Open Folder), then:

  • Build with Ctrl+Shift+B. The build writes build/blink.elf.
  • Start the simulator with F1 → Wokwi: Start Simulator. The board appears with the Pico and the serial monitor.

Try it in Wokwi

The starter runs the template blink unchanged: 1 Hz, with the on-board LED on for 500 ms and off for 500 ms. Its comments mark two tasks. Look for the comments tagged (learner) in main.c.

  1. Task 1: make the blink 5 Hz. 5 Hz means 100 ms on and 100 ms off. Change the two sleep_ms delays in main.c, rebuild, and start the simulator. The LED should blink visibly faster, and the serial monitor should print LED on and LED off at the new rate.
  2. Task 2: add an external LED. Add a wokwi-led part and a wokwi-resistor part to diagram.json. Wire the LED's anode (pin A) to GP15. Wire the LED's cathode (pin C) to resistor pin 1, and resistor pin 2 to GND.1. Set the resistor's value attribute to "220", meaning 220 Ω. Then change main.c so the external LED blinks in alternation with the on-board LED. When one is on, the other is off. Declare a pin constant for GP15, and initialise and set its direction the same way as for GPIO 25.
    Hint for the wiring

    Part types and pin names are on the Wokwi LED page and the Wokwi resistor page. Each connection is a line like ["pico:GP15", "led1:A", "green", []] in the connections array. Save the file, then start the simulator again.

  3. Run and observe. You will know it works when the on-board LED and the external LED take turns, 5 times per second each, and the serial monitor shows the blink lines.
Hint for the timing

A period is the time for one complete on-and-off cycle. 100 ms on plus 100 ms off makes 200 ms, and frequency is the inverse of the period.

The reference solution is in projects/0002-first-blink/solution. Try first, compare after. Its serial output prints Blink 5 Hz lines, so you can tell at a glance that it runs.

The resistor limits the current through the LED. Lesson 9 shows how to choose its value, so do not worry about the number yet.
You changed the timing of a running firmware and added a second LED to the circuit, then saw both change in the simulator. That is the edit, build, observe loop you will use for the rest of the course.

Model answer

The build system runs the compiler on the changed source file to produce an object file, then the linker joins it with the SDK libraries into blink.elf. The simulator is configured by wokwi.toml to load that ELF, and diagram.json defines the virtual board it runs on. Starting the simulator after the build means it loads the new firmware.
