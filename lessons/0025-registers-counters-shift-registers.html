Registers, counters, shift registers

Groups of flip-flops that store, count and shift bits

By the end of this lesson you can explain how a register, a counter and a shift register are built from flip-flops, and write the two C functions that shift a byte into a 74HC595 and latch it, so that the eight LEDs show the pattern the Pico sends.

From one flip-flop to many

Lesson 24 introduced the flip-flop, a single bit of memory that copies its input D on a rising clock edge, and lesson 23 the multiplexer and the full adder. One bit is not much use to firmware, so this lesson combines flip-flops into the three structures met most often: the register, the counter and the shift register.

Each of them is already in your hardware. The CPU's general-purpose registers are registers (lesson 31), a timer's count is a counter, and a serial peripheral such as SPI sends a byte one bit at a time through an on-chip shift register, which lesson 62 uses in hardware. The shift register built in this lesson applies the same idea by hand, so that every edge is visible.

The practical problem is moving many bits with few pins. A 74HC595 needs one data pin, one shift clock and one latch clock to drive eight output pins, and three wires instead of eight is a real saving on a board, which is why many display drivers and LED matrices are built this way.

Registers and load enables

A register is n flip-flops sharing a clock, so that they copy n bits on one edge. An 8-bit register is eight D flip-flops side by side with the clock wired to all of them, and this is the storage behind every register in the CPU and every peripheral register you will write from C.

A register usually needs an enable, a control input that decides whether to load on a given edge or keep the old value. A flip-flop has no enable of its own, so the enable is built from the multiplexer of lesson 23, with a 2-to-1 mux in front of each bit's D input. When the enable is 1 the mux passes the new data bit, and when it is 0 it feeds the flip-flop's own Q back to D, so that the flip-flop reloads its own value on every edge, which amounts to holding it. The mux is what makes "do nothing" possible in a clocked circuit.

Counters

A counter is a register whose next value is its current value plus one, so each clock edge moves it to the next number. Consider a 3-bit counter with bits Q2, Q1 and Q0, from the most significant down. Bit 0 must toggle on every edge, bit 1 only when bit 0 is 1, because only then does the count carry into it, and bit 2 only when bits 0 and 1 are both 1. These three rules form the same carry chain as the adder in lesson 23, with each bit's carry given by an AND of the bits below it.

Tracing it from 000 shows the sequence. On the first edge bit 0 toggles from 0 to 1 and the counter reads 001. On the second, bit 0 toggles back to 0 and carries into bit 1, giving 010, and the count continues through 011, 100, 101, 110 and 111. The next edge would need a fourth bit to show 1000, but there is none, so the carry out of bit 2 is lost and the counter wraps to 000. An n-bit counter therefore has

states = 2n(1)

where n is the number of bits, and it wraps after that many edges, which is why a counter's width matters in every timing calculation.

The width matters in real firmware too. The Pico's TIMER block keeps a 64-bit microsecond count, and lesson 55 works through a 32-bit version that wraps about every 71 minutes. Comparing two counter values in C must allow for the wrap, or a deadline check fails after a long run.

Bit 0's D input is NOT Q0, so it toggles on every edge, and each higher bit's D input is its own Q XOR the carry from the bits below, with the carries formed by the AND gates along the top: Q1 AND Q0 for bit 2, and that result AND Q2 for bit 3. Q3 to Q0 counts 0000, 0001, 0010 and on up to 1111, then wraps to 0000 after sixteen edges, and the timing diagram shows each bit changing only on a rising edge. Bit 0 runs at half the clock frequency, bit 1 at a quarter, bit 2 at an eighth and bit 3 at a sixteenth.

Shift registers

A shift register is a chain of flip-flops in which each takes the output of the one before it, while the first takes a new bit from an input pin called serial data. On every clock edge each bit moves one place along the chain and the last one drops off the end, so eight edges fill an 8-bit shift register with eight bits, one per edge, which is serial communication on the inside. Every stage shares the same clock, so the whole chain moves in step.

A shift register resembles a bucket brigade. On each clock edge, every person hands a bucket to the next and takes a new one from the person before, so after eight edges the eight buckets that arrived one by one are spread along the line, one per person. Real people pass buckets one after another, however, whereas every stage of a shift register hands over at the same instant, which is why it needs flip-flops.

A counter and a shift register differ only in their wiring. A counter's next value depends on its own value plus one, while a shift register's next value depends on its neighbour. Both are flip-flops on a shared clock, which is why a designer can turn one into the other with a little extra logic.

Worked example: shifting 0xA5 into eight stages

We now trace a real byte. The value 0xA5 is 1010 0101 in binary, from bit 7 down to bit 0, and we send it most significant bit first, so bit 7 goes in first. The register contents are Q7 down to Q0, starting from all zeros, and each row of the table shows the state after one rising edge of the shift clock: a new bit enters at Q0 while every bit already inside moves one place up towards Q7.

After eight edges the register holds 1010 0101, or 0xA5. The first bit sent, the 1 from bit 7, has moved up to Q7, because it was shifted seven more times after entering, and this is why the rule is to send the most significant bit first: the first bit ends up in the top output. A latch edge then copies the eight bits to the output pins, and the LEDs show 0xA5.

The table also shows what happens with the opposite order. Sending the least significant bit first puts bit 0 in Q7 and bit 7 in Q0, reversing the byte on the LEDs, so 0x0F, which is 0000 1111, would light the outputs as 1111 0000, or 0xF0. Bit order is therefore a convention the code must fix. Note also that 0xA5 is a palindrome and looks right either way, so it is a test with an asymmetric pattern that catches the bug.

The 4-stage register below lets you shift a pattern yourself. Set DIN, then give one clock pulse by setting CLK to 1 and back to 0. On each rising edge every stage copies its left neighbour at the same instant while stage 0 copies DIN, so after shifting in 1, 0, 1 and 1, Q3 to Q0 shows the first bit sent in Q3. That simultaneous copy is why the stages need flip-flops rather than latches.

The 74HC595 shift register with output latch

The 74HC595 is an 8-bit shift register with a second register behind it, a storage register, which drives the output pins. The shift register takes bits on one pin and its clock on another, and the storage register copies the shift register to the outputs only when its own clock rises. The outputs therefore change all at once, and the next byte can be shifted in while the LEDs still show the old one.

The storage register acts like a theatre curtain. While the curtain is closed, the stagehands move the scenery around, which corresponds to shifting, and when it opens, the latch pulse, the audience sees the finished set at once. Without the curtain the LEDs would show every half-shifted pattern along the way. Unlike a curtain, though, the latch also leaves the old scene in place until the very moment the new one is copied.

The datasheet of the real chip, Texas Instruments' SN74HC595, uses different pin names from the Wokwi part, and the table below maps them using the Wokwi names from this course's projects. Section 8.1 of the datasheet states that both clocks are positive-edge triggered, acting on their rising edges, and its function table, Table 8-1, gives the full behaviour.

The Wokwi part's documentation describes MR as active low, to be connected to VCC if unused, and OE as active low, to be connected to GND if unused (Wokwi 74HC595 part documentation). Both statements match the datasheet's pin functions.

MR is active low, so tie it to 3.3 V to keep the register running, and OE is also active low, so tie it to GND to enable the outputs. Leaving either floating can hold the outputs off, so the LEDs stay dark even though the code is correct.

Try it in Wokwi

The project in projects/0025-shift-register-595 wires DS to GP2, SHCP to GP3 and STCP to GP4, with MR tied to 3.3 V and OE to GND so that the register runs and its outputs are on. The 74HC595 outputs drive eight LEDs through 220 Ω resistors. The C code has two layers, shift_out_msb_first() to send eight bits most significant bit first and latch_outputs() to copy them to the LEDs, and the program runs a chase from Q0 to Q7, then a fixed pattern and an all-off step.

  1. Open the starter folder, build with Ctrl+Shift+B, and start the simulator with F1 → Wokwi: Start Simulator. The serial monitor prints LEDS=0x01, LEDS=0x02 and so on, but the LEDs stay dark, because the code asks for the patterns without ever making the latch edge.
  2. In shift_out_msb_first(), loop from bit 7 down to bit 0. For each bit, put it on DS and then make a rising edge on SHCP: high, a short delay, low, a short delay. After the loop the register holds the byte, although the outputs have not yet changed.
  3. In latch_outputs(), make one rising edge on STCP: high, a short delay, low, a short delay.
  4. Rebuild and restart the simulator. It works when the LEDs chase from Q0 to Q7, then show 0xA5 with alternate LEDs on, then go all off. Only then replace the last TODO(learner) comment in main() with printf("SHIFT OK\n"); and rebuild, after which the serial monitor prints LEDS=0x01 through LEDS=0x80, then LEDS=0xA5, LEDS=0x00 and SHIFT OK.
Hint for the bit order

The first bit shifted in is pushed up to Q7 by the later shifts, so sending bit 7 first lights Q7 for a 1 in bit 7. Sending bit 0 first would put it in the wrong LED, the classic bug in shift-out code.

Hint for the edge

A shift happens on the rising edge of SHCP, and a latch on the rising edge of STCP. A pulse that stays high does not count, so set the line low again before the next edge, as the comments say.

Common mistakes and how to spot them

A missing latch edge

This is the starter's own symptom. The serial monitor shows the patterns, but the LEDs stay dark or never show the printed pattern, because the shift register fills while the outputs keep their old state. Make the rising edge on STCP after the eight shifts, not before them.

Bits sent in the wrong order

A single LED lights, but at the wrong end: 0x01 should light Q0, but with bit 0 sent first it lights Q7, and the chase runs from the wrong side. Loop from bit 7 down to bit 0, as the solution does.

A floating output-enable or clear pin

The LEDs stay dark even though the serial monitor prints the right values and the edges look correct. A floating input can take any level, so the chip may clear or disable itself at random. Check the wiring: MR must be high, tied to 3.3 V, and OE low, tied to GND, as in the project.

Both clocks on one pin

Some people wire SHCP and STCP together to save a wire, and the outputs then trail the data by one shift, so the LEDs show each pattern one step late. The TI datasheet states that when both clocks are connected together, the shift register is always one clock pulse ahead of the storage register. Keep the two clocks on separate pins and give the latch its own edge.

Shift registers in real designs

Shift registers are how a microcontroller drives many outputs from few pins. A common pattern chains several 74HC595 chips, feeding each chip's serial output into the next chip's DS pin through the datasheet's QH' output, called Q7S on the Wokwi part. The C code then shifts out two bytes instead of one, with the same single latch edge.

On real hardware the shift clock usually comes from a peripheral. Code review expects a driver not to toggle pins by hand when the MCU has an SPI peripheral, and expects any pulse width to respect the datasheet's minimum. Those minimum widths come from the datasheet's timing table, read as lesson 18 described, and a review comment such as "the 10 µs pulse is a guess, check the table" is a normal and useful one.

Summary

  • A register is a set of flip-flops sharing a clock, and an enable is a mux that feeds Q back to D to hold the value.
  • A counter is a register plus an adder. Each bit toggles on the carry from the bits below it, and a 3-bit counter wraps from 111 to 000.
  • A shift register passes each bit to the next flip-flop on every clock edge, so eight edges fill an 8-bit chain.
  • Send the most significant bit first, so that the first bit ends in Q7 and bit n of the byte lights output Qn.
  • The 74HC595 has a shift register and a storage register with separate clocks, and the storage clock copies the byte to the outputs all at once.
  • MR is an active-low clear and OE an active-low output enable, so tie MR high and OE low for normal operation.
