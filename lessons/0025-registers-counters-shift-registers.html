Registers, counters, shift registers

A CPU register is a row of flip-flops with a shared clock. A counter adds one to it on every edge, and a shift register moves its bits along one place. You will drive a 74HC595 from the Pico to light eight LEDs one bit at a time, which is the same pattern as an SPI transfer in lesson 62.

By the end of this lesson you can explain how a register, a counter and a shift register are built from flip-flops, and write the two C functions that shift a byte into a 74HC595 and latch it, so that the eight LEDs show the pattern the Pico sends.

The idea

A register is n flip-flops that share a clock and an enable, so they load n bits in one edge. This is the storage behind every register in the CPU (lesson 31) and every peripheral register. Harris and Harris, chapter 3 (Sequential Logic Design) covers registers, counters and shift registers in the same chapter as the flip-flops.

A counter is a register whose input is its own output plus one. On each clock edge it moves to the next value. A 3-bit counter goes 000, 001, 010, and so on up to 111, then wraps to 000, because there is no fourth bit to carry into.

A shift register is a chain of flip-flops where each one takes the output of the previous one. On each clock edge every bit moves one place along the chain, and a new bit enters at one end. Eight shifts move one byte in, one bit at a time. That is serial communication on the inside: the same data path an SPI master drives on MOSI.

The 74HC595: a shift register with a latch

The 74HC595 is an eight-bit shift register with a second register, a storage latch, on its outputs. The shift register takes bits on one pin and the shift clock on another. The storage register copies the shift register to the output pins only when the latch clock rises. So the outputs change all at once, and you can shift the next byte in while the LEDs still show the old one. Wokwi's 74HC595 page lists the pins as used in this course: DS (serial data), SHCP (shift clock), STCP (latch clock), MR (reset, active low), OE (output enable, active low), and Q0 to Q7 (the outputs), plus Q7S to chain several chips. The datasheet of the real chip uses other names for some of these pins. The Wokwi names are the ones in this lesson's diagram.

MR is active low, so tie it to 3.3 V to keep the register running. OE is also active low, so tie it to GND to enable the outputs. Leaving either floating can hold the outputs off, and the LEDs stay dark even though the code is right.

Try it in Wokwi

The project in projects/0025-shift-register-595 wires DS to GP2, SHCP to GP3 and STCP to GP4. The 74HC595 outputs drive eight LEDs through 220 Ω resistors. The C code is written in two layers: shift_out_msb_first() sends eight bits, most significant bit first, and latch_outputs() copies them to the LEDs. The program then runs a chase, from Q0 to Q7, and a fixed pattern.

  1. Open the starter folder, build with Ctrl+Shift+B, and start the simulator with F1 → Wokwi: Start Simulator. The serial monitor prints LEDS=0x.. lines, but the LEDs stay dark.
  2. In shift_out_msb_first(), loop from bit 7 down to bit 0. For each bit, put it on DS, then make a rising edge on SHCP: high, a short delay, low, a short delay.
  3. In latch_outputs(), make one rising edge on STCP.
  4. Rebuild and restart the simulator. You will know it works when the LEDs chase from one side to the other, and the serial monitor prints SHIFT OK after each full cycle.
Hint for the bit order

The first bit shifted in is pushed to Q7 by the later shifts. Sending bit 7 first therefore lights Q7 for a 1 in bit 7. Sending bit 0 first would put it in the wrong LED, which is the classic bug in shift-out code.

Hint for the edge

A shift happens on the rising edge of SHCP, and so does a latch on STCP. A pulse that stays high does not count. Set the line low again before the next edge, as the comments say.

The reference solution is in projects/0025-shift-register-595/solution. Try first, compare after.

Shifting out a byte on two GPIOs and a latch is the same idea as SPI, with the clock and the data each on one pin. Lesson 62 uses the Pico's SPI peripheral to do this in hardware, so the CPU does not toggle each pin by hand.
You built a shift register from flip-flops in your head, then used the 74HC595 to show a byte on eight LEDs with two separate clocks. You also know why the latch exists: the outputs change together, not bit by bit.

"How does a shift register relate to SPI, and why does the 74HC595 need a separate latch?" Answer out loud in 60 seconds, then compare.

Model answer

An SPI master shifts a byte out on MOSI, one bit per SCK edge, so the slave's shift register is filled serially. The 74HC595 does the same thing, with DS as the data and SHCP as the clock. The separate latch exists so that the outputs change all at once, after the whole byte has been shifted in, instead of showing a partly-filled value.
