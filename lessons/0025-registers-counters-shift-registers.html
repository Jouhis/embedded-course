Registers, counters, shift registers

A CPU register is a row of flip-flops with a shared clock. A counter adds one to it on every edge, and a shift register moves its bits along one place. You will drive a 74HC595 from the Pico to light eight LEDs one bit at a time, which is the same pattern as an SPI transfer in lesson 62.

By the end of this lesson you can explain how a register, a counter and a shift register are built from flip-flops, and write the two C functions that shift a byte into a 74HC595 and latch it, so that the eight LEDs show the pattern the Pico sends.

Where we are and why it matters

Lesson 24 gave you the flip-flop: one bit of memory that copies its input D on a rising clock edge. Lesson 23 gave you the multiplexer and the full adder. A single flip-flop is one bit, and nobody writes firmware with one bit, so this lesson puts flip-flops together into the three shapes you meet most: the register, the counter and the shift register.

Each shape is in your hardware already. The CPU's general-purpose registers are registers (lesson 31). A timer's count is a counter. A serial peripheral such as SPI sends a byte one bit at a time through a shift register on the chip, which lesson 62 uses in hardware. The shift register you build in this lesson is the same idea, done by hand, so that you can see every edge.

The problem this lesson solves is how to move many bits with few pins. A 74HC595 takes one data pin, one shift clock and one latch clock, and it drives eight output pins. Three wires instead of eight is a real saving on a board, and the same trick is why many display drivers and LED matrices are built this way.

Concept 1: a register is flip-flops that load together

A register is n flip-flops that share a clock, so they copy n bits on one edge. An 8-bit register is eight D flip-flops side by side, with the clock wired to all of them. This is the storage behind every register in the CPU and every peripheral register you will write from C.

A register usually needs an enable, a control input that says whether to load on this edge or keep the old value. A flip-flop has no enable of its own, so the enable is built from lesson 23's multiplexer. Each bit's D input is a 2-to-1 mux: when the enable is 1 the mux passes the new data bit, and when the enable is 0 it passes the flip-flop's own Q back to D. The flip-flop then reloads its own value on every edge, which is the same as holding it. The mux is what makes "do nothing" possible on a clocked circuit.

Concept 2: a counter is a register plus an adder

A counter is a register whose next value is its current value plus one. Each clock edge moves it to the next number. Build a 3-bit counter from three flip-flops, with the bits named Q2, Q1 and Q0 from the most significant down. Bit 0 must toggle on every edge. Bit 1 must toggle only when bit 0 is 1, because only then does the count carry into it. Bit 2 must toggle only when bits 0 and 1 are both 1. Those three rules are the same carry chain as the adder in lesson 23, with the carry for each bit given by an AND of the lower bits.

Trace it from 000. On the first edge bit 0 is 0, so it toggles to 1, and the counter reads 001. On the second edge bit 0 toggles back to 0 and carries into bit 1, which becomes 1: 010. Continue and you count 011, 100, 101, 110, 111. On the next edge the counter would need a fourth bit to show 1000, but there is none. The carry out of bit 2 is lost, and the counter wraps to 000. This wrap is not a bug in the counter. It is what a fixed number of bits does, and it is why a counter's width matters for any timing calculation.

The width matters in real firmware. The Pico's TIMER block keeps a 64-bit microsecond count, and lesson 55 works through a 32-bit version that wraps about every 71 minutes. Comparing two counter values in C must account for the wrap, or a deadline check fails after a long run.

Concept 3: a shift register moves bits one place per edge

A shift register is a chain of flip-flops in which each one takes the output of the previous one. The first flip-flop takes a new bit from an input pin called serial data. On every clock edge, each bit moves one place along the chain, and the last one falls off the end. Eight edges fill an 8-bit shift register with eight bits, one per edge, which is serial communication on the inside. The clock is the same for every stage, so the whole chain moves in step.

The difference between a counter and a shift register is only the wiring. A counter's next value depends on its own value plus one. A shift register's next value depends on its neighbour. Both are built from flip-flops and a shared clock, which is why a designer can build one from the other with a little extra logic.

Worked example: shifting 0xA5 into eight stages

Now trace a real byte. The value 0xA5 is 1010 0101 in binary, from bit 7 down to bit 0. Send it most significant bit first, which means the bit 7 goes in first. Call the register's contents Q7 down to Q0, and start from all zeros. Each row below is the state after one rising edge on the shift clock. A new bit enters at Q0, and every bit already inside moves one place up toward Q7.

After eight edges the register holds 1010 0101, which is 0xA5. The first bit sent, the 1 from bit 7, has moved up to Q7, because it was shifted seven more times after it entered. That is why the rule is "send the most significant bit first": the first bit ends up in the top output. A latch edge then copies these eight bits to the output pins, and the LEDs show 0xA5.

Check your own understanding against this table. Suppose you send the least significant bit first instead. Then bit 0 is the first bit in, so it ends in Q7, and bit 7 ends in Q0. The byte is reversed on the LEDs. A value of 0x0F, which is 0000 1111, would light the outputs as 1111 0000, or 0xF0. Bit order is a convention you must fix in the code, and the two ends of the register differ by exactly that. Note that 0xA5 is a palindrome, so it looks right either way, which is why a test with an asymmetric pattern is the one that catches the bug.

The 74HC595: a shift register with a latch

The 74HC595 is an eight-bit shift register with a second register behind it, a storage register, which drives the output pins. The shift register takes bits on one pin and its clock on another. The storage register copies the shift register to the outputs only when its own clock rises. So the outputs change all at once, and you can shift the next byte in while the LEDs still show the old one.

The datasheet of the real chip, Texas Instruments' SN74HC595, uses different pin names from the Wokwi part. The table below maps them, using the Wokwi names that this course's projects use. The datasheet's section 8.1 says that both clocks are positive-edge triggered, which means each one acts on its rising edge. The function table, Table 8-1, gives the full behaviour.

The Wokwi part's own documentation names MR as active low and says to connect it to VCC if you do not use it. It names OE as active low and says to connect it to GND if you do not use it (Wokwi 74HC595 part documentation). Both facts match the datasheet's pin functions.

MR is active low, so tie it to 3.3 V to keep the register running. OE is also active low, so tie it to GND to enable the outputs. Leaving either floating can hold the outputs off, and the LEDs stay dark even though the code is right.

Try it in Wokwi

The project in projects/0025-shift-register-595 wires DS to GP2, SHCP to GP3 and STCP to GP4. MR is tied to 3.3 V and OE to GND, so the register runs and its outputs are on. The 74HC595 outputs drive eight LEDs through 220 Ω resistors. The C code is written in two layers: shift_out_msb_first() sends eight bits, most significant bit first, and latch_outputs() copies them to the LEDs. The program then runs a chase, from Q0 to Q7, a fixed pattern and an all-off step.

  1. Open the starter folder, build with Ctrl+Shift+B, and start the simulator with F1 → Wokwi: Start Simulator. The serial monitor prints LEDS=0x01, LEDS=0x02 and so on, but the LEDs stay dark. The code asks for the patterns and never makes the latch edge.
  2. In shift_out_msb_first(), loop from bit 7 down to bit 0. For each bit, put it on DS, then make a rising edge on SHCP: high, a short delay, low, a short delay. After the loop the register holds the byte, but the outputs have not changed yet.
  3. In latch_outputs(), make one rising edge on STCP: high, a short delay, low, a short delay.
  4. Rebuild and restart the simulator. You will know it works when the LEDs chase from Q0 to Q7, then show 0xA5 (alternate LEDs on), then go all off. The serial monitor prints LEDS=0x01 through LEDS=0x80, then LEDS=0xA5, LEDS=0x00 and SHIFT OK.
Hint for the bit order

The first bit shifted in is pushed to Q7 by the later shifts. Sending bit 7 first therefore lights Q7 for a 1 in bit 7. Sending bit 0 first would put it in the wrong LED, which is the classic bug in shift-out code.

Hint for the edge

A shift happens on the rising edge of SHCP, and so does a latch on STCP. A pulse that stays high does not count. Set the line low again before the next edge, as the comments say.

Shifting out a byte on two GPIOs and a latch is the same idea as SPI, with the clock and the data each on one pin. Lesson 62 uses the Pico's SPI peripheral to do this in hardware, so the CPU does not toggle each pin by hand.

Common mistakes and how to spot them

Mistake 1: the latch edge is missing. This is the starter's symptom. The serial monitor shows the patterns, but the LEDs never change, because the shift register fills and the outputs still show the old state. Symptom: the LEDs stay dark, or they never show the pattern the monitor prints. Fix: make the rising edge on STCP after the eight shifts, not before.

Mistake 2: the bits are sent in the wrong order. Symptom: a single LED lights, but at the wrong end. The value 0x01 should light Q0, and with bit 0 sent first it lights Q7. The chase runs from the wrong side. Fix: loop from bit 7 down to bit 0, as the solution does.

Mistake 3: an output-enable or clear pin is left floating. Symptom: the LEDs are dark even though the serial monitor prints the right values and the edges look correct. Fix: check the wires. MR must be high, tied to 3.3 V, and OE must be low, tied to GND, as the project does. A floating input can take any level, so the chip can clear or disable itself at random.

Mistake 4: the two clocks are tied to one pin. Some people wire SHCP and STCP together to save a wire. Symptom: the outputs trail the data by one shift, so the LEDs show the pattern one step late. The TI datasheet states that when both clocks are connected together, the shift register is always one clock pulse ahead of the storage register. Fix: keep the two clocks on separate pins, and give the latch its own edge.

In real projects

Shift registers are how a microcontroller drives many outputs with few pins. A common pattern is to chain several 74HC595 chips by feeding each one's serial output into the next one's DS pin, and using the datasheet's QH' output for that link. In the Wokwi part this pin is Q7S. The C code then shifts out two bytes instead of one, and the latch edge is the same.

On real hardware the shift clock is a peripheral in most projects. Code review expects a driver that does not toggle pins by hand when the MCU has an SPI peripheral, and expects the pulse width to respect the datasheet's minimum. The data sheet's timing table, which lesson 18 teaches you to read, sets those minimum widths. A review comment that says "the 10 µs pulse is a guess, check the table" is a normal and useful one.

In an interview, expect the question "how does a shift register relate to SPI, and why does the 74HC595 need a separate latch?" A strong answer names the two clocks, explains that the latch makes the outputs change together, and says the same serial shifting is what an SPI master does on MOSI.

Summary

  • A register is flip-flops that share a clock. An enable is a mux that feeds Q back to D to hold the value.
  • A counter is a register plus an adder. Each bit toggles on the carry from the bits below it, and a 3-bit counter wraps from 111 to 000.
  • A shift register passes each bit to the next flip-flop on every clock edge. Eight edges fill an 8-bit chain.
  • Send the most significant bit first: the first bit ends in Q7, so bit n of the byte lights output Qn.
  • The 74HC595 has a shift register and a storage register with separate clocks. The storage clock copies the byte to the outputs all at once.
  • MR is an active-low clear and OE is an active-low output enable. Tie MR high and OE low for normal operation.
You built a shift register from flip-flops in your head, then used the 74HC595 to show a byte on eight LEDs with two separate clocks. You also know why the latch exists: the outputs change together, not bit by bit.

"How does a shift register relate to SPI, and why does the 74HC595 need a separate latch?" Answer out loud in 60 seconds, then compare.

Model answer

An SPI master shifts a byte out on MOSI, one bit per SCK edge, so the slave's shift register is filled serially. The 74HC595 does the same thing, with DS as the data and SHCP as the clock. The separate latch exists so that the outputs change all at once, after the whole byte has been shifted in, instead of showing a partly-filled value.
