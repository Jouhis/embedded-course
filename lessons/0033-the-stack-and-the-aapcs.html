The stack and the AAPCS calling convention

When one function calls another, the two have to agree on where arguments go, which registers must survive the call, and where the return address is kept. That agreement is the calling convention.

By the end of this lesson you can say where the arguments and the return value go in a call, which registers a function must preserve, and what a full-descending stack looks like after a PUSH, then check all of it in the CPU simulator.

The idea

The stack is a region of RAM that a function uses for its local data, saved registers and return addresses. On Cortex-M it grows downward, toward lower addresses. The ABI document calls this a full-descending stack: the stack pointer SP points at the last item pushed, and a push first moves SP down, then writes (Arm ABI, Procedure Call Standard for the Arm Architecture, "The Stack").

The Procedure Call Standard for the Arm Architecture (AAPCS) is the agreement between caller and callee. The rules that matter first are these.

  • Arguments: "The first four registers r0-r3 (a1-a4) are used to pass argument values into a subroutine" (AAPCS, Core registers).
  • Return value: "A word-sized Fundamental Data Type (e.g., int, float) is returned in r0" (AAPCS, Result Return).
  • Preserved: "A subroutine must preserve the contents of the registers r4-r8, r10, r11 and SP" (AAPCS, Core registers). R9 is also preserved in the variants of the standard that designate it as a callee-saved register. Check which variant your toolchain uses before you rely on R9.
  • Scratch: R12 (IP) "may be used by a linker as a scratch register between a routine and any subroutine it calls" (AAPCS, Core registers).
  • Stack alignment: at a public interface, "SP mod 8 = 0. The stack must be double-word aligned" (AAPCS, Stack constraints).

The return address is kept in LR. A BL instruction writes it there. A function that calls another function must save LR on the stack, because the inner call would overwrite it. The usual pattern is PUSH {..., LR} at the start and POP {..., PC} at the end, which pops the return address straight into the PC.

The ABI rule that R4 is preserved is a promise to the caller. A function that uses R4 must push it on entry and pop it before it returns. Forgetting this does not fail on the spot: the caller's R4 is silently wrong later, which is one of the hardest bugs to find.

Try it in the CPU simulator

The program calls add_pair with 3 and 4 in R0 and R1. Inside, it saves R4 and LR, uses R4 for a constant, and returns. Before you step through, predict the final R0. Then use the stack view to see the frame.

  1. Press Instruction three times. Predict SP and R0 after the BL. The LR value is the return address, with the low bit set, as Thumb addresses are written.
  2. Press Instruction once more, to run PUSH {R4, LR}. Predict SP, then check the stack view: the new top of the stack should hold R4 and then LR.
  3. Press Run or keep pressing Instruction until the halt. Check the final R0 and SP.
Hint

The arguments are 3 and 4, and the function adds a constant of 100. Work out the final R0 before you look. After the POP, SP should be back to its starting value.

The simulator follows the same calling pattern as the real core, with a few teaching simplifications: 2-byte instructions, a small instruction set and one stack pointer. The real Cortex-M3 pushes exception frames on the same stack, which lesson 34 covers.

"Which registers can a function clobber, and which must it preserve? Why does the stack pointer have to be 8-byte aligned at a public interface?" Answer out loud in 60 seconds, then compare.

Model answer

R0 to R3 carry arguments and R0 carries the result, so a function may change them. R12 is scratch. R4 to R8, R10, R11 and SP must be preserved, and R9 depends on the variant. The stack must be 8-byte aligned at a public interface so that a callee can rely on a known alignment, which lets the core stack an extra word to meet it. The AAPCS states the rule as SP mod 8 = 0.

Arm ABI documents, including the AAPCS: read the "Core registers" section for the preserved set and the argument registers, and the "Stack constraints at a public interface" section for the alignment rule. The release notes list the current version.
