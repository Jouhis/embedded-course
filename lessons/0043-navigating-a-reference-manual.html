Navigating a reference manual

The answer to almost every hardware question is in the reference manual. The skill is knowing which table to open, and how to cross-check it against the header file.

By the end of this lesson you can find a peripheral's base address, its register offsets, its reset values and its bit fields in the RP2040 datasheet, and cross-check each one against the STM32 device header.

The idea

A reference manual describes the chip for the programmer. It has a few kinds of content, and each one lives in a predictable place: an address map near the front, a chapter for each peripheral, a register list and a register description with a bit table for each register. The reset value of a register is the value it holds after reset, and the datasheet gives it in the register's table. Think of the manual as the specification your header file implements. The header is convenient, but the manual is authoritative, and when they disagree the manual and the errata sheet win (lesson 44).

The RP2040 datasheet is short enough to search. Its Appendix A explains the field types, such as read-write and write-only, and Appendix B lists the errata by block. RP2040 datasheet, sections 2.2, 2.3.1.7 and the appendices.

Worked example. The SIO block's registers start at 0xD0000000, as section 2.3.1.7 states. In its list of registers, GPIO_OUT_SET is at 0x014, GPIO_OUT_CLR at 0x018 and GPIO_OUT_XOR at 0x01C. The address of GPIO_OUT_CLR is therefore 0xD0000018, which is the same as base plus offset from lesson 38.

The STM32F1: RM0008 and the header

The STM32F103 reference manual is RM0008. It covers the whole STM32F101, F102, F103, F105 and F107 family, so it contains some features your Blue Pill does not have. Its memory map is in the early chapters on memory and buses. Each peripheral chapter has a register map table, which lists each register's offset and its reset value. Check this layout in your copy, since the chapter numbers vary between revisions. The ST device header, stm32f103xb.h, gives the same offsets as C structs, and the struct order is the register order in the table.

The header is the cross-check, not the source. In this course the GPIOC base is 0x40011000 and the BSRR offset is 0x10, both in stm32f103xb.h. When you read RM0008's GPIO register map, you should find the same offset for BSRR. If the two disagree, the manual is right and the header is a bug, so report it.

Do not copy a register address from a forum post or an old example. Look it up in the reference manual for the exact part you are using. The same peripheral name can have different offsets on the F1 and the F4, and a wrong offset writes to a different register without any error.

Try it in Wokwi

The project projects/0043-reference-manual is a single demo. It prints the base address of GPIOC and the addresses of four registers that the struct computes.

  1. Open projects/0043-reference-manual in VS Code, build with Ctrl+Shift+B, and start the simulator with F1 → Wokwi: Start Simulator.
  2. Before you read the output, write down the offset of each register from GPIOC base, using the header structs in stm32f103xb.h.
  3. Check the printed GPIOC->CRH address and GPIOC->BSRR address against your offsets.
  4. Open the RM0008 GPIO register map and find the offsets of CRH and BSRR. Note the reset value of CRH. Your answer should match the header.
Hint

In the struct GPIO_TypeDef, the fields are CRL, CRH, IDR, ODR, BSRR, BRR and LCKR, in that order, each 4 bytes. CRH is at offset 4, and BSRR is at offset 16, which is 0x10.

Reading a reference manual is the job, and the simulator is only a check. The demo's outputs are the addresses that the compiler computes, so they confirm your reading of the header.

Model answer

Find the peripheral's chapter in the reference manual, and its base address in the memory map. Then read the register map table for the offset and the reset value. Cross-check the offset against the vendor's header file, which should agree, and check the errata sheet for the chip's known problems with that peripheral. Write the address as base plus offset in the code, never as a number copied from elsewhere.

RP2040 datasheet: read section 2.2 (Address Map), then section 2.3.1.7 (SIO list of registers), then the Appendix A field types. This is the best practice on a short manual, and the same habits carry over to RM0008.
