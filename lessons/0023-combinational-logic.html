Combinational logic

Multiplexers, decoders and adders built from gates

By the end of this lesson you can explain how a 2-to-1 multiplexer, a 2-to-4 decoder and a full adder work, and wire a full adder from two half adders and an OR gate so that the Pico's test bench prints FULL ADDER OK.

Larger blocks from gates

Lesson 22 built single gates and checked a circuit against its truth table. This lesson applies the same method to three larger blocks, each of which appears in a real part of the processor: the multiplexer chooses where a value comes from, the decoder chooses which device an address belongs to, and the adder performs addition. Lesson 26 places an adder inside the ALU, and lesson 38 shows the memory map that a decoder reads.

Each block corresponds to something you will meet on a real board. A pin-mux setting that selects which peripheral drives a GPIO is a multiplexer, the chip-select line of a sensor on a shared bus is a decoder output, and an ADC result that is scaled and offset passes through a chain of adders. In every case the engineer must predict the output for every input and notice when a select line or a carry is wired wrongly, because such a bug shows up far from its cause.

Combinational and sequential logic

Combinational logic has outputs that depend only on its present inputs, with no memory and no clock, so the same inputs always produce the same outputs. This distinguishes it from the sequential logic of lesson 24, whose outputs also depend on what was stored earlier.

A combinational circuit is still a physical object. After an input changes, each gate takes a short time to respond, so the output settles a few gate delays later, as lesson 22 described. The truth table gives the settled value, and how long the circuit takes to reach it is a separate question.

Multiplexers

A multiplexer, or mux, has data inputs, select inputs and one output, and it copies one of the data inputs to the output as chosen by the select inputs. A 2-to-1 mux has two data inputs, I0 and I1, and one select input S: with S at 0 the output follows I0, and with S at 1 it follows I1. In gates the rule is

out = (S AND I1) OR (NOT S AND I0)(1)

where S is the select input, and it can be checked against the three-input table.

The table shows four of the eight rows, enough to see the rule when it is read with S fixed: in the two rows where S is 0 the output equals I0, and in the two where S is 1 it equals I1. The select line is a control input rather than data, and it is the first thing to check when a mux seems to swap its inputs.

Mux trees for wider selections

Muxes combine into wider ones. Three 2-to-1 muxes select one of four inputs with two select lines, the first choosing within each of two pairs and the second choosing between the pairs. A tree of 2-to-1 muxes always works this way, and for k data inputs it needs k − 1 two-input muxes, since each mux removes one candidate. An 8-to-1 mux therefore needs 4 + 2 + 1 = 7 two-input muxes and three select lines, because 23 = 8. The CPU uses wide muxes everywhere to choose where a register's value comes from, and a register file's read port is exactly such a tree.

A multiplexer resembles a set of railway points in front of a single track. Several tracks come in and one goes out, and the lever position, the select inputs, decides which incoming track connects through. Nothing is stored, so moving the lever changes the connection at once. Real points take seconds to move and a train must not be on them, whereas a mux changes in nanoseconds while data is flowing, which is where the glitches discussed in the mistakes section come from.

The mux below can be tried directly. Set I0 and I1 to different values, then flip S and watch which input reaches the output. The middle columns of the table are the two AND gates, and only one of them can pass its input at a time, because one sees S and the other NOT S.

Decoders

A decoder performs the reverse job of a mux. Where a mux takes many inputs and passes one, a decoder takes a binary address and turns it into one-hot outputs: an n-bit address drives 2n outputs, of which exactly one is 1, the one whose number matches the address. One-hot means exactly one line is active, and that property is what makes a decoder useful for choosing a device.

A 2-to-4 decoder takes two address bits, A as the high bit and B as the low bit, and drives four outputs. Each output is an AND of the two address bits, with a bit inverted wherever its value must be 0, so Y0 = NOT A AND NOT B, Y1 = NOT A AND B, Y2 = A AND NOT B and Y3 = A AND B. Every output is a two-input AND gate, so the whole decoder consists of four ANDs and two NOT gates.

ABY0Y1Y2Y3
001000
010100
100010
110001

Worked example: address 10 on a 2-to-4 decoder

We apply the address 2 to the decoder and evaluate all four outputs to see which one is selected.

  1. Write the address in binary. Decimal 2 is 10, so A = 1 and B = 0.
  2. Evaluate each output: Y0 = NOT 1 AND NOT 0 = 0 AND 1 = 0, Y1 = NOT 1 AND 0 = 0, Y2 = 1 AND NOT 0 = 1 AND 1 = 1, and Y3 = 1 AND 0 = 0.
  3. Only Y2 is 1, so output 2 is selected, matching the address 2.

Peripheral address decoding works in this way: a bus address is compared with each peripheral's range, and the decoder output becomes that peripheral's chip-select line. The RP2040 datasheet describes its register access in the same terms, with each register reached through one of four access methods "selected by address decode" (RP2040 datasheet, section 2.1.2). Lesson 38 shows the memory map the decoder reads.

Half adders

Adding two bits produces a sum and a carry, a two-digit binary number. The half adder computes it with

SUM = A XOR B,   CARRY = A AND B(2)

where A and B are the input bits. The sum digit is 1 when exactly one input is 1, and the carry digit only when both are. The cases confirm it: 0 + 0 is 00, 0 + 1 and 1 + 0 are 01 with a sum of 1, and 1 + 1 is binary 10, so the sum is 0 and the carry is 1. A half adder cannot accept a carry from a lower position, however, which is why a multi-bit adder needs the full adder.

Full adders

A full adder adds three bits, A, B and the carry in from the lower position, CIN, and two half adders do the job. The first adds A and B, giving a sum S1 and a carry C1, and the second adds S1 and CIN, giving the final sum and a carry C2. The carry out is C1 OR C2, and an OR is correct because the two carries can never both be 1: C1 is 1 only when A and B are both 1, in which case S1 is 0 and the second half adder produces no carry. The circuit therefore needs five gates, two XORs for the sum, two ANDs for the carries and one OR for the carry out.

A + B + CINBinary totalSUMCOUT
0 + 0 + 00000
1 + 0 + 00110
1 + 1 + 01001
1 + 1 + 11111

For every row the result satisfies

A + B + CIN = 2 × COUT + SUM(3)

where COUT has weight 2 and SUM weight 1, which makes a useful check on any adder you build.

Worked example: 1 + 1 + 1 in a full adder

We trace the hardest row, with all three inputs at 1, through both half adders.

  1. The first half adder takes A = 1 and B = 1. Its sum is 1 XOR 1 = 0 and its carry 1 AND 1 = 1.
  2. The second half adder takes the sum 0 and CIN = 1. Its sum is 0 XOR 1 = 1 and its carry 0 AND 1 = 0.
  3. The final sum is 1, and the carry out is C1 OR C2 = 1 OR 0 = 1.
  4. Equation 3 confirms it: 2 × 1 + 1 = 3, which equals 1 + 1 + 1, so the circuit is correct for this row.

The circuit below is the full adder built from two half adders: the first XOR and AND add A and B, the second pair adds CIN, and the OR combines the two carries. Set A, B and CIN to 1 and follow the signals, then try every row and check that 2 × COUT + SUM always equals the number of inputs that are 1.

Ripple-carry adders

A full adder handles one bit position, so adding two 8-bit numbers takes eight full adders in a row, with each stage's carry out feeding the next stage's carry in. The lowest stage has CIN tied to 0, and the highest stage's carry out becomes the carry flag of the whole addition. This structure is called a ripple-carry adder, because the carry ripples from the lowest bit to the highest, and it forms the core of the ALU in lesson 26.

The ripple is also the adder's weakness. The carry out of bit 0 must be known before bit 1 can finish, and so on up the word, so an 8-bit adder takes about eight carry delays and a 32-bit adder about 32. Faster adders use a carry-lookahead network that computes the carries in parallel at the cost of more gates, and lesson 26 returns to the ALU and its adder.

A ripple-carry adder behaves like a row of dominoes. Bit 7 cannot settle until bit 6 has passed on its carry, bit 6 waits for bit 5, and so on down to bit 0, so the worst case is a carry that travels the whole row, as in 0xFF + 0x01. That is why faster adders compute the carries ahead instead of waiting for the dominoes to fall. Unlike dominoes, though, an adder resets itself, and a new pair of inputs simply ripples through again.

Worked example: 6 + 7 in a 4-bit adder

We add 0110 (6) and 0111 (7) with CIN = 0, working from bit 0 upwards and passing each carry to the next stage. Predict the carry out of bit 3 before starting.

  1. Bit 0: A = 0, B = 1, CIN = 0. The sum is 1 and the carry 0, so the result so far is ...1.
  2. Bit 1: A = 1, B = 1, CIN = 0. The sum is 0 and the carry 1, giving ...01.
  3. Bit 2: A = 1, B = 1, CIN = 1. The sum is 1 and the carry 1, giving ...101.
  4. Bit 3: A = 0, B = 0, CIN = 1. The sum is 1 and the carry 0, giving 1101, which is 13.

As a check, 6 + 7 = 13, and 1101 is 8 + 4 + 1 = 13. The carry out of bit 3 is 0, so the sum fits in four bits. Tracing the carries is worth doing whenever you check an adder, because a wrong carry is the most common cause of a wrong sum.

  1. Bit 0: A = 0, B = 1 and the carry in is 0. The sum bit is 1 and the carry out is 0.
  2. Bit 1: A = 1, B = 1, carry in 0. 1 + 1 = 10 in binary: the sum bit is 0, and a carry of 1 moves left.
  3. Bit 2: A = 1, B = 1, carry in 1. 1 + 1 + 1 = 11: the sum bit is 1, and the carry is 1 again.
  4. Bit 3: A = 0, B = 0, carry in 1. The sum bit is 1 and the carry out is 0. Each stage had to wait for the carry from the one before: that is the ripple.
  5. The result is 1101, which is 13. The carry out of bit 3 is 0, so the sum fits in four bits.

The adder test bench in C

The test bench for the project computes the expected answer with ordinary integer addition, the easiest reference a programmer has. 

static bool expected_sum(int a, int b, int cin) {
    return (a + b + cin) & 1;       // the low bit of the total is the sum
}

static bool expected_cout(int a, int b, int cin) {
    return (a + b + cin) >> 1;      // the high bit of the total is the carry out
}

The total of three bits is 0, 1, 2 or 3, which is two bits wide. & 1 keeps the low bit, which is the sum because the sum has weight 1, and >> 1 moves the high bit down to bit 0, which is the carry because the carry has weight 2. Each function returns bool, so a result of 1 or 0 is compared directly with the pin's level. The rest of check_row drives the three inputs, waits, reads the two outputs and compares each with its expected value, exactly as in lesson 22.

The starter diagram is missing one wire of the full adder, so the starter fails. Your task is to find the missing wire from what the test bench reports, without comparing the diagram with the solution, since tracing a failing test back to one broken connection is the skill that matters on a real board.

  1. Open the starter folder in VS Code, build with Ctrl+Shift+B, and start the simulator with F1 → Wokwi: Start Simulator.
  2. Read the serial monitor. Expect eight rows, at least one ending in WRONG, followed by FULL ADDER FAILED. Each row shows the inputs and both outputs, and because an unconnected input stays at a fixed level that cannot be right on every row, some row must fail.
  3. Write down the failing rows and which output is wrong on them, SUM or COUT. List what those rows have in common: which inputs are 1, and what the first sum, A XOR B, is on each.
  4. Open diagram.json and read the connections list. Match each gate input to the full adder in this lesson, two XOR gates, two AND gates and one OR gate, then find the gate input that nothing drives and decide from your list of failing rows which signal belongs there.
  5. Add the missing connection in the same form as the others, ["source:PIN", "destination:PIN", "colour", []], using the part ids and pin names from the diagram, and save the file. Restart the simulator and expect eight rows ending in ok, followed by FULL ADDER OK.
Hint for the failing rows

Only COUT is wrong, so the fault lies on the carry side rather than in the two XOR gates. The carry out is the OR of two AND terms, the second of which is the first sum AND CIN. Compare the failing rows with the rows where the first sum and CIN are both 1, then ask which AND gate input should carry the first sum and check whether the starter connects it.

Common mistakes and how to spot them

Five mistakes account for most combinational bugs, each with a visible symptom, and the test bench for this lesson catches the first three.

A mux with reversed select polarity

If the select line feeds the wrong gate, S = 1 passes I0 instead of I1, so two sources swap and the wrong bus is read on every access. Write the rule as (S AND I1) OR (NOT S AND I0) and check the S = 1 row first, because that is the one people get backwards.

An adder with its carries cut

Half adders, or full adders with their carry in tied to 0, add each bit without the carry from below. For 1111 + 0001 with the chain cut, the bits add to 1110, or 14, instead of 0000 with a carry out, so the sum is wrong by exactly the dropped carries. Connect each carry out to the next carry in.

A half adder where a full adder is needed

A half adder cannot add 1 + 1 + 1 because it has no carry in, so it gives a sum of 1 with the carry missing where the answer should be 1 with a carry of 1. Use the full adder.

Overlapping decoder ranges

If two peripherals' address ranges overlap, both decoder outputs are 1 for the same address, and two devices answer the same transaction, which corrupts the bus. Check the address map from lesson 38 and decode the bits that tell the ranges apart.

A decoder read while its address changes

Address bits do not all change at the same instant, so a decoder output can pulse to 1 for a few nanoseconds, briefly selecting a device during a transaction meant for another. Sample the output only after the address has settled, or register the decoder output with a clock, as lesson 24 explains.

Combinational blocks in real designs

Blocks like these are written in hardware description languages such as Verilog and VHDL, or drawn as schematics. Either way a reviewer checks the same things: that each select line has the polarity its comment claims, that every adder carry is connected and that the decoder ranges agree with the address map. A review also asks for a test covering every row, since a combinational block has a finite truth table that a test can cover completely, and the bench in this lesson is that kind of test applied to a real circuit.

Firmware meets these blocks through the address map. The bus hardware performs the decoding and driver code never sees the decoder, but a driver that writes to two peripherals at overlapping addresses reaches both. A senior engineer therefore checks the address ranges of new peripherals against the map before a board is designed, which is the same question as the overlap mistake above. Adders matter to firmware in every fixed-point multiply and every accumulated sum, and an adder's wrap-around is the same silent overflow that lesson 21 met in fixed-point sums.

Summary

  • Combinational logic has outputs that depend only on its present inputs, and they settle a few gate delays after the inputs change.
  • A multiplexer copies one of its data inputs to the output as chosen by its select lines, and a tree of 2-to-1 muxes needs one mux fewer than it has inputs.
  • A decoder turns an n-bit address into 2n outputs, exactly one of which is 1.
  • A half adder forms the sum with XOR and the carry with AND, and a full adder combines two half adders and an OR gate, five gates in all.
  • A ripple-carry adder chains full adders, so its delay grows with its width.
  • Check an adder against integer addition, since the total is 2 × COUT + SUM for every row.
  • A reversed select swaps two sources, and a cut carry gives a sum short by exactly the lost carries.
