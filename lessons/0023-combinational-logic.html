Combinational logic

A multiplexer picks a bus, a decoder picks a peripheral, and an adder adds. Each is a gate circuit with no memory, and the adder is the first piece of the CPU's ALU that you will build.

By the end of this lesson you can explain how a 2-to-1 multiplexer, a 2-to-4 decoder and a full adder work, and wire a full adder from two half adders and an OR gate so that the Pico's test bench prints FULL ADDER OK.

The idea

Combinational logic has outputs that depend only on the current inputs. There is no memory and no clock. Lesson 24 adds memory. Every gate circuit in this lesson is combinational, and every output settles a few gate delays after its inputs change. Harris and Harris, chapter 2 (Combinational Logic Design) covers the same blocks with their full truth tables.

Multiplexer: choose one input

A multiplexer (mux) has data inputs, select inputs and one output. A 2-to-1 mux with inputs I0 and I1 and select S gives I0 when S = 0, and I1 when S = 1. In gates: out = (S AND I1) OR (NOT S AND I0). The CPU uses wide muxes everywhere to choose where a register's value comes from.

Muxes compose. Eight 2-to-1 muxes in a tree make one 8-to-1 mux, and a tree of k inputs always needs k − 1 two-input muxes. For eight inputs that is 7.

Decoder: pick one output

A decoder does the reverse of a mux. An n-bit address drives 2n outputs, and exactly one output is 1, the one whose number matches the address. A 2-to-4 decoder drives four outputs from two address bits. Peripheral address decoding works this way: the bus address selects one peripheral's chip-select line, and lesson 38 shows the memory map this comes from.

Half adder and full adder

Adding two bits gives a sum and a carry. The half adder adds two bits: sum = A XOR B and carry = A AND B. Check the cases: 1 + 1 is binary 10, so the sum is 0 and the carry is 1.

A full adder adds three bits: A, B and the carry in from the lower position, CIN. Two half adders do it. The first adds A and B. The second adds that sum to CIN. The carry out is the OR of the two carries, because at most one of them can be 1. Five gates in all. A row of full adders, with each carry out feeding the next carry in, makes a ripple-carry adder for a whole word. That is the core of the ALU in lesson 26.

0 + 0 + 00000
1 + 0 + 00110
1 + 1 + 01001
1 + 1 + 11111

The total is always 2·COUT + SUM, which is a useful check on any adder you build.

Gates take a short but real time to settle, and combinational outputs can glitch while the inputs change. A circuit that is correct in its truth table can still show a wrong value for a few nanoseconds. Lesson 24 explains how a clock tells the rest of the system when the output is valid.

Try it in Wokwi

The project in projects/0023-full-adder has three inputs on GP2 (A), GP3 (B) and GP4 (CIN), and two outputs read on GP10 (SUM) and GP11 (COUT). The Pico tests all eight rows, and checks each one against integer addition.

  1. Open the starter folder in VS Code, build with Ctrl+Shift+B, and start the simulator with F1 → Wokwi: Start Simulator.
  2. Read the serial monitor. Some rows print WRONG. Each row shows the inputs and both outputs, so you can see which output fails.
  3. Find the missing wire in the circuit. The first XOR gate's output must feed the input A of the second AND gate, as well as the input A of the second XOR gate. Add this line to the connections list of diagram.json, then save:
    ["x1:OUT", "a2:A", "orange", []]
  4. Restart the simulator and watch the table. You will know it works when the serial monitor shows FULL ADDER OK.

Model answer

Two half adders and an OR gate. The first half adder adds A and B, the second adds that sum to CIN, and the OR combines the two carries. An 8-bit adder chains eight full adders, with each carry out feeding the next carry in. The carry must ripple through every stage, so the delay grows with the width. Faster adders use carry-lookahead to shorten that path.
