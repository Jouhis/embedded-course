Combinational logic

A multiplexer picks a bus, a decoder picks a peripheral, and an adder adds. Each is a gate circuit with no memory, and the adder is the first piece of the CPU's ALU that you will build.

By the end of this lesson you can explain how a 2-to-1 multiplexer, a 2-to-4 decoder and a full adder work, and wire a full adder from two half adders and an OR gate so that the Pico's test bench prints FULL ADDER OK.

Where we are and why it matters

Lesson 22 built single gates and showed how to check a circuit against its truth table. This lesson uses the same method on three larger blocks, and each of them appears in a real part of the processor. The multiplexer chooses where a value comes from, the decoder chooses which device an address belongs to, and the adder performs addition. Lesson 26 puts an adder inside the ALU, and lesson 38 shows the memory map that a decoder reads.

Each of these blocks is a job you will meet on a real board. A pin-mux setting that selects which peripheral drives a GPIO is a multiplexer. A chip-select line for a sensor on a shared bus is the output of a decoder. An ADC result that is scaled and offset is an adder chain. In each case the engineer must predict the output for every input, and must notice when a select or a carry is wired wrongly, because the bug shows up far from its cause.

Combinational logic: no memory, only inputs

Combinational logic has outputs that depend only on its current inputs. There is no memory and no clock. If you write down the inputs, the outputs are fixed, and writing them down a second time gives the same answer. That is the difference from the sequential logic of lesson 24, where an output also depends on what was stored earlier.

A combinational circuit is still a physical thing. After an input changes, each gate takes a short time to respond, so the output settles a few gate delays later. Lesson 22 introduced this delay, and the circuits in this lesson have the same property. The truth table describes the settled value, and the time it takes to get there is a separate question.

Multiplexer: choose one input

A multiplexer (mux) has data inputs, select inputs and one output. Its job is to copy one of the data inputs to the output, and the select inputs say which one. A 2-to-1 mux has two data inputs, I0 and I1, and one select input, S. When S is 0 the output follows I0. When S is 1 the output follows I1. In gates the rule is written as out = (S AND I1) OR (NOT S AND I0), and you can check it against the three-input table.

The table shows four of the eight rows, enough to see the rule. Read it with S fixed. In the two rows where S is 0, the output is I0. In the two rows where S is 1, the output is I1. The select line is a control input, not data, and that is the first thing to check when a mux seems to swap its inputs.

Muxes compose into wider muxes

Muxes can be combined. Three 2-to-1 muxes pick one of four inputs, with two select lines: the first select line chooses within each of two pairs, and the second chooses between the two pairs. A tree of 2-to-1 muxes always works this way. For k data inputs the tree needs k − 1 two-input muxes, because each mux reduces the number of candidates by one. An 8-to-1 mux therefore needs 4 + 2 + 1 = 7 two-input muxes, and it takes 3 select lines, because 23 = 8. The CPU uses wide muxes everywhere to choose where a register's value comes from, and a register file read port is exactly such a tree.

Decoder: pick one output

A decoder does the reverse of a mux. A mux takes many inputs and passes one of them. A decoder takes a binary address and turns it into one-hot outputs: an n-bit address drives 2n outputs, and exactly one output is 1, the one whose number matches the address. The word "one-hot" means exactly one line is hot, which is the property that makes a decoder useful for choosing a device.

A 2-to-4 decoder takes two address bits, A (the high bit) and B (the low bit), and drives four outputs. Each output is an AND of the two address bits, with each bit inverted where its value must be 0. Y0 = NOT A AND NOT B, Y1 = NOT A AND B, Y2 = A AND NOT B, and Y3 = A AND B. Every output is an AND gate with two inputs, so the whole decoder is four ANDs and two NOT gates.

ABY0Y1Y2Y3
001000
010100
100010
110001

Worked example: address 10 selects output 2

  1. Write the address in binary. Decimal 2 is 10, so A = 1 and B = 0.
  2. Evaluate each output. Y0 = NOT 1 AND NOT 0 = 0 AND 1 = 0. Y1 = NOT 1 AND 0 = 0. Y2 = 1 AND NOT 0 = 1 AND 1 = 1. Y3 = 1 AND 0 = 0.
  3. Only Y2 is 1. Output 2 is the chosen one, which matches the address 2.

Peripheral address decoding works this way. A bus address is compared with each peripheral's range, and the decoder output is the chip-select line for that peripheral. The RP2040 datasheet describes its register access in the same terms: each register is reached through one of four access methods, "selected by address decode" (RP2040 datasheet, section 2.1.2). Lesson 38 shows the memory map that the decoder reads.

Half adder: add two bits

Adding two bits gives a sum and a carry, and that is a binary number with two digits. The half adder adds two bits. Its sum is A XOR B, because the sum digit is 1 when exactly one input is 1. Its carry is A AND B, because the carry digit is 1 only when both inputs are 1. Check the cases: 0 + 0 is 00, 0 + 1 and 1 + 0 are 01 with sum 1, and 1 + 1 is binary 10, so the sum is 0 and the carry is 1.

The half adder does not handle a carry coming in from a lower position. That is why a multi-bit adder needs the full adder.

Full adder: add three bits

A full adder adds three bits: A, B and the carry in from the lower position, CIN. Two half adders do the job. The first adds A and B, giving a sum S1 and a carry C1. The second adds S1 and CIN, giving the final sum and a carry C2. The carry out is C1 OR C2. The OR is correct because the two carries can never both be 1. C1 is 1 only when A and B are both 1, and then S1 is 0, so the second half adder produces no carry. Five gates in all: two XOR gates for the sum, two AND gates for the carries, and one OR gate for the carry out.

A + B + CINBinary totalSUMCOUT
0 + 0 + 00000
1 + 0 + 00110
1 + 1 + 01001
1 + 1 + 11111

The total is always 2·COUT + SUM, which is a useful check on any adder you build.

Worked example: 1 + 1 + 1

  1. The first half adder takes A = 1 and B = 1. Its sum is 1 XOR 1 = 0, and its carry is 1 AND 1 = 1.
  2. The second half adder takes the sum 0 and CIN = 1. Its sum is 0 XOR 1 = 1, and its carry is 0 AND 1 = 0.
  3. The final sum is 1, and the carry out is C1 OR C2 = 1 OR 0 = 1.
  4. Check with the formula: 2 × 1 + 1 = 3, which is 1 + 1 + 1. The circuit is right for this row.

Ripple-carry adder: a full adder for each bit

A full adder adds one bit position. To add two 8-bit numbers you connect eight full adders in a row, with the carry out of each stage feeding the carry in of the next. The lowest stage has CIN tied to 0, and the highest stage's carry out is the carry flag of the whole addition. This structure is a ripple-carry adder, because the carry ripples from the lowest bit to the highest. It is the core of the ALU in lesson 26.

The ripple is also the adder's weakness. The carry out of bit 0 must be known before bit 1 can finish, and so on up the word. An 8-bit adder therefore takes about eight carry delays, and a 32-bit adder takes about 32. Faster adders use a carry-lookahead network that computes the carries in parallel, at the cost of more gates. Lesson 26 returns to the ALU and its adder.

Worked example: 6 + 7 in four bits

Add 0110 (6) and 0111 (7) with CIN = 0. Work from bit 0 upwards and carry each result to the next stage.

  1. Bit 0: A = 0, B = 1, CIN = 0. Sum is 1, carry is 0. The result so far is ...1.
  2. Bit 1: A = 1, B = 1, CIN = 0. Sum is 0, carry is 1. The result is ...01.
  3. Bit 2: A = 1, B = 1, CIN = 1. Sum is 1, carry is 1. The result is ...101.
  4. Bit 3: A = 0, B = 0, CIN = 1. Sum is 1, carry is 0. The result is 1101, which is 13.

Check: 6 + 7 = 13, and 1101 is 8 + 4 + 1 = 13. The carry out of bit 3 is 0, so the sum fits in four bits. Trace the carries in your head whenever you check an adder: a wrong carry is the most common source of a wrong sum.

Common mistakes and how to spot them

Five mistakes account for most combinational bugs. Each has a symptom you can see, and the test bench for this lesson catches the first three.

  1. A mux with its select polarity reversed. If the select line feeds the wrong gate, S = 1 passes I0 instead of I1. The symptom is two sources that swap, so the wrong bus is read on every access. The fix is to write the rule as (S AND I1) OR (NOT S AND I0), and to check the S = 1 row first, because it is the one people get backwards.
  2. An adder with its carries cut. Using half adders, or full adders with their carry in tied to 0, adds each bit without the carry from below. For 1111 + 0001 with the chain cut, the bits add to 1110, which is 14, when the answer should be 0000 with a carry out. The symptom is a sum that is wrong by exactly the carries that were dropped. The fix is to connect each carry out to the next carry in.
  3. Using a half adder where a full adder is needed. A half adder cannot add 1 + 1 + 1, because it has no carry in. The symptom is a sum of 1 with the carry missing, where the answer should be 1 with a carry of 1. The fix is the full adder.
  4. Overlapping decoder ranges. If two peripherals' address ranges overlap, their decoder outputs are both 1 for the same address. The symptom is two devices answering the same transaction, which corrupts the bus. The fix is to check the address map (lesson 38) and to decode the bits that tell the ranges apart.
  5. Reading a decoder while its address changes. When the address bits change, they do not change at the same instant, so a decoder output can pulse 1 for a few nanoseconds. The symptom is a device that is selected briefly during a transaction to another device. The fix is to sample the output only after the address has settled, or to register the decoder output with a clock, which lesson 24 explains.

In real projects

Blocks like these are written in hardware description languages such as Verilog and VHDL, or they are drawn as schematics. In both cases a reviewer checks the same things: that each select line has the polarity the comment says, that every adder carry is connected, and that the decoder ranges agree with the address map. A review also asks for a test that covers every row, because a combinational block has a finite truth table and the test can cover all of it. The bench in this lesson is that kind of test, applied to the real circuit.

Firmware meets these blocks in the address map. The bus hardware performs the decode, and the driver code never sees the decoder, but a driver that writes to two peripherals at overlapping addresses will reach both of them. A senior engineer checks the address ranges of new peripherals against the map before a board is designed, and that check is the same question as the overlap mistake above. Adders matter to firmware in every fixed-point multiply and every accumulated sum, and the wrap-around of an adder comes back in lesson 21, where a fixed-point sum overflows silently.

Summary

  • Combinational logic has outputs that depend only on its current inputs. Its outputs settle a few gate delays after the inputs change.
  • A multiplexer copies one of its data inputs to the output. The select lines choose which one, and a tree of 2-to-1 muxes needs one fewer mux than it has inputs.
  • A decoder turns an n-bit address into 2n outputs, exactly one of which is 1.
  • A half adder makes the sum with XOR and the carry with AND. A full adder adds two half adders and an OR gate, five gates in all.
  • A ripple-carry adder chains full adders, so its delay grows with its width.
  • Check an adder against integer addition: the total is 2 × COUT + SUM for every row.
  • A reversed select swaps two sources, and a cut carry gives a sum that is short by exactly the lost carries.

Try it in Wokwi

The project in projects/0023-full-adder has three inputs on GP2 (A), GP3 (B) and GP4 (CIN), and two outputs read on GP10 (SUM) and GP11 (COUT). The Pico tests all eight rows, and checks each one against integer addition. Its circuit is built from two XOR gates, two AND gates and one OR gate, which is the full adder you just read about.

The project's starter diagram already has every wire of the full adder, so the starter should pass without any change. Check that for yourself. Then you will break the circuit on purpose and see what the test bench reports, which is the skill that matters on a real board.

Reading the test bench

static bool expected_sum(int a, int b, int cin) {
    return (a + b + cin) & 1;       // the low bit of the total is the sum
}

static bool expected_cout(int a, int b, int cin) {
    return (a + b + cin) >> 1;      // the high bit of the total is the carry out
}

The test bench computes the expected answer with ordinary integer addition, which is the easiest reference a programmer has. The total of three bits is 0, 1, 2 or 3, which is two bits wide. & 1 keeps the low bit, and that is the sum, because the sum is the digit with weight 1. >> 1 moves the high bit down to bit 0, and that is the carry, because the carry has weight 2. The function returns bool, so a result of 1 or 0 is compared directly with the pin's level. The rest of check_row drives the three inputs, waits, reads the two outputs and compares each with its expected value, exactly as in lesson 22.

  1. Open the starter folder in VS Code, build with Ctrl+Shift+B, and start the simulator with F1 → Wokwi: Start Simulator.
  2. Read the serial monitor. Expect eight rows, each ending in ok, then FULL ADDER OK. Each row shows the inputs and both outputs.
  3. Open diagram.json and find the connection ["x1:OUT", "a2:A", "orange", []]. This wire carries the first sum into the carry gate. Delete that one line from the connections list, then save.
  4. Restart the simulator. Expect at least one row to print WRONG. A missing input stays at a fixed level, and that level cannot match the right value on every row, so some row must fail. Look at which output is wrong, SUM or COUT, on the failing rows.
  5. Put the line back, save, restart, and expect FULL ADDER OK again.
Hint for the failing rows

The carry out is the OR of two AND terms, and the second term is the first sum AND CIN. With the wire removed, that term sees a fixed level. Find the rows where the first sum and CIN are both 1, and ask what the missing input would need to be to get COUT right on those rows and on the others.

Model answer

Two half adders and an OR gate. The first half adder adds A and B, the second adds that sum to CIN, and the OR combines the two carries. An 8-bit adder chains eight full adders, with each carry out feeding the next carry in. The carry must ripple through every stage, so the delay grows with the width.
