Core registers

A Cortex-M core has sixteen register names and one status register. Knowing what each one holds is the difference between reading a debugger and guessing.

By the end of this lesson you can name the core registers R0 to R12, SP, LR, PC and xPSR, say which xPSR bits hold the NZCV flags, and predict the flags after a CMP.

The idea

The core has 13 general-purpose registers, R0 to R12. Arm's TRM lists them with the link register (LR, R14), the program counter (PC, R15) and one program status register, xPSR (Arm Cortex-M3 TRM DDI0337G, §2.3). The stack pointer (SP, R13) is different: it is a banked register with two physical copies, and only one is visible at a time.

The two stack pointers are SP_main (the main stack pointer, MSP) and SP_process (the process stack pointer, PSP). Lesson 35 explains when each one is active. Reset uses the main stack, and the TRM says that all exceptions use it (§2.2.1). The simulator has only one SP. It does not model MSP and PSP, so the register table shows one stack pointer and does not switch it.

RegisterNameWhat it holds
R0 to R12General-purposeOperands, results and, by convention, function arguments and return values (lesson 33).
R13SP (MSP or PSP)The top of the current stack, which grows down. Banked: SP_main or SP_process.
R14LRThe return address after a BL call, or a special value on exception entry.
R15PCThe address of the instruction the core is working on. Writing it branches.
xPSRProgram statusThe flags and the status fields, read as APSR, IPSR and EPSR (below).

xPSR: three views of one register

xPSR is one 32-bit register, but Arm's TRM describes it as three overlapping views. The APSR holds the condition flags. The IPSR holds the number of the exception being handled. The EPSR holds the Thumb state bit and the bits for interruptible instructions (DDI0337G, Tables 2-1 to 2-3).

  • APSR, bits 31 to 28: N (negative), Z (zero), C (carry) and V (overflow). The TRM's figure labels them in that order from bit 31 down.
  • IPSR, bits 8 to 0: the active exception number. Zero means thread mode, which is the normal program.
  • EPSR: the T bit (Thumb state) and the interruptible-instruction and If-Then state.

Try it in the CPU simulator

The simulator has R0 to R12, SP, LR and PC, plus the four flags N, Z, C and V. It does not have PRIMASK in this lesson's program, and it has no separate IPSR or EPSR. Predict each value before you press the button.

  1. Press Reset, then Instruction twice. Predict R2 after SUB R2, R0, R1, and predict the Z flag. Both are in the register and flag panels.
  2. Press Instruction twice more. The CMP R0, #11 compares 10 with 11 without changing R0. Predict which flag is set. The flag panel will light the one that is set.
Hint

For CMP, compute 10 − 11, which is −1. A negative result sets N. It is not zero, so Z stays clear. Work out C and V from the subtraction too: a borrow clears C.

You named every core register, wrote down which xPSR bits hold the flags, and predicted the flags from a compare. That is the vocabulary you need for the rest of Part 2.

"Which registers does a Cortex-M have, and what is special about the stack pointer?" Answer out loud in 60 seconds, then compare.

Model answer

R0 to R12 are general-purpose. R13 is the stack pointer, which is banked: there is an MSP for handlers and reset, and a PSP that a thread can use. R14 is the link register, R15 is the PC, and xPSR holds the flags in its top bits and the active exception number in its low bits. The stack pointer is special because the hardware switches it on exception entry and return.
