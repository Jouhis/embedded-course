Bare-metal blink with CMSIS only

Lesson 47 used a register struct you wrote yourself. Now you use the vendor's CMSIS names, and you add the two things the STM32 needs before a pin does anything: a clock on the port, and a mode in CRL or CRH.

By the end of this lesson you can enable a GPIO port's clock, set a pin's mode in CRL or CRH, drive two LEDs at different rates from the SysTick counter without a blocking delay, and explain why BSRR is safer than ODR for a shared pin.

The idea

Three things happen before a pin can drive an LED on the STM32F1. The clock of its port must run. The pin's mode must be set, which for the F1 means a 4-bit field in a configuration register. Then you drive the level with a write to a data register. Lesson 47 covered the last step. This lesson adds the first two, and the timing.

Step 1: the clock is off until you enable it

The STM32F1 gates the clock to each peripheral. A peripheral whose bit in an RCC enable register is 0 ignores your reads and writes. The GPIO ports are on APB2, so their enables are in RCC->APB2ENR. The header gives each bit a name: 

/* from stm32f103xb.h: the bit positions */
RCC_APB2ENR_AFIOEN    /* bit 0 */
RCC_APB2ENR_IOPAEN    /* bit 2 */
RCC_APB2ENR_IOPBEN    /* bit 3 */
RCC_APB2ENR_IOPCEN    /* bit 4 */
RCC_APB2ENR_USART1EN  /* bit 14 */

RCC->APB2ENR |= RCC_APB2ENR_IOPCEN;   /* now GPIOC accepts writes */
A missing clock enable does not fault. The write is ignored, the pin stays where reset left it, and the LED never lights. When a register write seems to do nothing, check the clock before anything else.

On the Pico, the SDK's gpio_init() does this step for you. On the STM32 you write it, and the code that sets a pin always starts with the clock. The enable bits are the clock gating from the RCC section of the reference manual. Lesson 40 introduced the clock tree, which is the source of the clock that these gated peripherals receive.

Step 2: CRL and CRH, the F1's odd pin configuration

On the RP2040, a pin's function is one field, and its direction and drive are separate registers. The F1 is different. Each pin owns a 4-bit field, and the fields are split between two registers by pin number. Pins 0 to 7 are in CRL, and pins 8 to 15 are in CRH. Pin n starts at bit (n mod 8) × 4. Inside a field, two bits set the mode and two bits set the configuration.

The field for a push-pull output at 2 MHz is 0x2: configuration 00 (push-pull), mode 10 (2 MHz). The change is a mask and a set, so the other pins in the register keep their settings: 

GPIOC->CRH = (GPIOC->CRH & ~(0xFU << 20)) | (0x2U << 20);   /* PC13: push-pull, 2 MHz */

The header gives the same bit names for every field, for example GPIO_CRH_MODE13 and GPIO_CRH_CNF13. The positions are in the header, and the encodings are in the reference manual's GPIO register section. The cheat sheet at the end of this course lists the values in one table. Step 3: ODR or BSRR

Lesson 47 introduced both. ODR holds the output level of all 16 pins. Setting one pin with ODR |= bit is a read-modify-write: load, change, store. BSRR does the change in one store: bit n sets pin n, and bit n + 16 resets it. A 0 changes nothing.

Use BSRR for any pin that an interrupt or another task might touch, and for every pin you change in the loop. The risk is real even on one core, because an interrupt can run between the load and the store, and then its change is lost. Lesson 70 puts an interrupt on a button pin, which is exactly this situation.

Timing with SysTick, without blocking

The template's delay_ms() blocks: while it waits, nothing else runs. Two LEDs at different rates cannot share one blocking delay. Instead, let SysTick count milliseconds, and keep a deadline for each LED. SysTick is the 24-bit countdown built into every Cortex-M core. It reloads from LOAD and sets COUNTFLAG when it reaches zero. Reading CTRL clears the flag. Arm Cortex-M3 Devices Generic User Guide, and the SysTick section of PM0056 (ST's programming manual for the STM32F10xxx). 

SysTick->LOAD = (SystemCoreClock / 1000U) - 1U;   /* 8000 - 1 at 8 MHz: one millisecond */
SysTick->VAL  = 0;
SysTick->CTRL = SysTick_CTRL_CLKSOURCE_Msk | SysTick_CTRL_ENABLE_Msk;

/* in the loop: one call per millisecond that has passed */
if (SysTick->CTRL & SysTick_CTRL_COUNTFLAG_Msk) { now_ms++; }

The loop then checks each LED's deadline. A deadline is a millisecond value that the LED changes at. When now_ms reaches it, the code toggles the LED and moves the deadline forward by one half period. A slow LED never holds up a fast one. The loop must poll at least once per millisecond, or it misses a COUNTFLAG. Printing a long line over the serial port can take longer than that, which is why the solution prints only at startup. Hint for step 2

PB0 is pin 0, so it is in GPIOB->CRL, and its field starts at bit 0. The same mask-and-set line as PC13, with the shift changed to zero, does the job.

Hint for step 4

PB0 is active high, so setting bit 0 of BSRR turns it on, and bit 16 turns it off. Use next_external_ms, external_on and LED_EXTERNAL_HALF_MS, the names the PC13 block already uses with its own variables.

"What is the difference between ODR and BSRR, and why does it matter for a pin an interrupt also uses?" Answer out loud in 60 seconds, then compare.

Model answer

ODR holds the output level of all 16 pins, and changing one pin in it means a read, a change and a write. BSRR takes a set bit and a reset bit for each pin and needs only one store, and a 0 changes nothing. If an interrupt changes another pin on the same port between the read and the write, the read-modify-write can undo that change. BSRR cannot lose one, so use it for any pin that more than one piece of code touches.
