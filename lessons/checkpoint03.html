Checkpoint 3: Embedded C

Lessons 45 to 50 are the C you need to read a register map and a driver without help. This checkpoint mixes them, so you have to pick the right rule for each question.

By the end of this checkpoint you can predict integer results on fixed-width types, explain why a shared flag needs volatile, write a register access that is atomic, parse a big-endian buffer, use a callback table safely, and choose between a macro and a function.

Answer the questions below without notes first. The explanations tell you which lesson to revisit when you miss one. Then answer the three explain-out-loud prompts at the end, as if to a colleague. The integer rules come from the cppreference page on conversions.

Explain out loud

Say each answer in 60 to 90 seconds, as if to a junior engineer. Then open the model answer.

1. "Explain to a junior why their ISR flag never changes, as seen from main."

Model answer

Check three things. First, the flag must be declared volatile, or the compiler may keep it in a register and never reload it, which is the -O2 hang from lesson 46. Second, the ISR must really run: the interrupt must be enabled, the source must fire, and the handler must be the one the vector table points at. Third, the flag must be the same variable in both places, so check that the static or extern declarations match. Only after those, look at the timing.

2. "Explain why a checksum written with uint8_t arithmetic can be wrong, and how you would check it."

Model answer

Each byte is promoted to int before the addition. The intermediate sum is an int, so it does not wrap at 255, and only the final store into a uint8_t wraps modulo 256. A test with bytes that sum past 255 shows whether the code wraps at the right point. The fix is to compute the sum in a wide type on purpose and reduce modulo 256 at the end, and to test the boundary values explicitly. Lesson 45 has the rule.

3. "Explain why a single BSRR write is safer than a read-modify-write, and when a read-modify-write is still fine."

Model answer

A read-modify-write loads the register, changes a bit and stores the result. An interrupt between the load and the store can change another pin, and the store then writes back the old value and loses that change. BSRR is one store that names only the pins to set or reset, so the hardware never reads the old state. A read-modify-write is still fine for setup code, where no interrupt touches the port, such as configuring CRH once at startup. Lesson 47 covers both.
