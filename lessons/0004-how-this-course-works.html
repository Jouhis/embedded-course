How this course works

The method behind every lesson: try before you look, answer from memory, come back later, and mix the topics.

By the end of this lesson you can plan a study session that tries a task before reading its solution, retrieves from memory, and returns to earlier lessons.

The idea

The course is built on retrieval practice: you bring an answer out of your memory, rather than rereading the page. Retrieval is the source of the quizzes you have already met. The research summary on retrievalpractice.org puts it plainly: "Easy learning leads to easy forgetting." Rereading feels productive because the material is familiar. Familiar is not the same as remembered.

Three other habits sit alongside it. Spaced review returns to earlier material after a gap, so the memory is rebuilt each time. Interleaving mixes topics in one session, so you must choose the right method for each problem. And desirable difficulty is the idea that a little struggle now makes the learning last longer. Make It Stick (Brown, Roediger and McDaniel, 2014) gives the full case for all of these.

Fluency and storage

Two things can be mistaken for learning. Fluency is how easily you perform or recall something right now. Storage strength is how well it is learned, and it lasts. Practice that is easy builds fluency fast, and fluency can rise without much storage behind it. The Bjorks' "new theory of disuse" describes this split. Their 2020 paper, Desirable difficulties in theory and practice, is the primary reference; read it if you want the theory in the authors' words.

The practical rule: an answer you struggle to reach, and then check, builds more storage than one you read straight off the page. That is why the course asks you to try a task before you open its hint or solution.

Try before you peek

Each lesson's task has a hint in a details box, and a solution in projects/<id>/solution. Both are there so you can get unstuck. Open them after you have made a real attempt. An attempt can be wrong and still do its job, because the struggle is what makes the correction stick. The course gives a project in two folders: starter is yours to change, and solution is the reference. Edit only the starter.

Using the agent as a tutor

The AI agent in this workspace is your tutor. It can quiz you, explain a point again, or set an extra exercise, and it can see your learning records. Some prompts to start with:

  • "Quiz me on lessons 5 to 8, mixing the topics."
  • "Explain this register again, using the bus and memory, not a formula."
  • "Give me an extra exercise on the resistor from lesson 2."

A study routine

  1. Read the goal. Know what you are trying to be able to do before you start.
  2. Try the task first. Make a real attempt before opening a hint or the solution.
  3. Answer the quiz from memory. Do it before you reread the explainer, so the answers you give are yours.
  4. Write three things from memory at the end of the lesson, then check them against the page.
  5. Come back in a few days. Do the spaced-review quiz in a later lesson, or ask the tutor to quiz you on this one.

Communities

When the tutor and the course do not answer a question, these communities do. Pick the one that matches the question:

  • r/embedded for career questions and "how is this done in industry".
  • Electronics Stack Exchange for a specific circuit or firmware question.
  • EEVblog forum for hardware and measurement questions.
  • The Interrupt community for professional practice, debugging and tooling.
  • The Zephyr Project community for Zephyr questions.
  • The Raspberry Pi forums, Pico section for RP2040 and Pico SDK specifics.
  • The ST Community for STM32 peripheral and HAL quirks.
  • Embedded.fm, interviews with working embedded engineers.

Model answer

I would start with a small project on real hardware or a simulator, and try each peripheral before reading its example. I would answer from memory, not from the manual, and keep a short list of what I could not recall. I would come back to each peripheral after a few days and mix them, so each session makes me choose the right register and API. Being able to produce the code cold, without the datasheet open, is the test.
