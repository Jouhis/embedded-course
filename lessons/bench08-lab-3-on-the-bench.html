Bench lab 8: Lab 3 on the bench

The Lab 3 environment monitor on real hardware

By the end of this lab you can replace a driver behind an existing interface without touching the code above it, and bring a multi-part project up on hardware one subsystem at a time.

The sensor interface of Lab 3

This lab runs your Lab 3 environment monitor on a real Pico 2 with a real OLED, real buttons and a real temperature sensor. The simulated MYS-1 does not exist as a part, so a thermistor takes its place behind the same interface, and nothing above that interface changes. The lab is optional, needing a Pico 2, the SSD1306 OLED, two pushbuttons, a 10 kΩ NTC thermistor, a 10 kΩ resistor and two 4.7 kΩ resistors, and it does not count towards your progress. It is split into three parts of under an hour each, so you can stop after any part.

Lab 3 read the MYS-1, the course's own I2C sensor from lesson 63, a custom Wokwi chip that exists only in the simulator and cannot be bought. Lab 3's main.c, however, never talks to the MYS-1 directly, because it calls two functions from sensor.h. 

bool sensor_init(void);
sensor_status_t sensor_poll(float *celsius);   /* SENSOR_IDLE, SENSOR_NEW_SAMPLE or SENSOR_ERROR */

Any sensor that can fill in those two functions can therefore replace it. The bench version uses a 10 kΩ NTC thermistor in a divider on ADC0 (GP26), wired the way Wokwi's NTC part is, with 10 kΩ from 3V3 to GP26 and the NTC from GP26 to GND, a divider whose reading lesson 58 converted to a temperature with the Beta equation. The new file is sensor_ntc.c, while main.c, ui.c, display.c, ssd1306.c and font.c are Lab 3's, copied unchanged into projects/bench08-lab3-on-the-bench.

The contract has details worth keeping. sensor_poll() must return at once and never wait, and it returns SENSOR_NEW_SAMPLE once per new reading, so the NTC version reports a new sample every 500 ms and SENSOR_IDLE in between. A broken sensor must show as SENSOR_ERROR rather than as a plausible wrong temperature, so that the UI's error path still works.

Part 1: the board without the sensor (about 40 minutes)

  1. Open the starter in Wokwi, build and run it. Its sensor_ntc.c returns SENSOR_ERROR, so the OLED, the menu and both buttons work while the screen reports a sensor error, the expected state of everything except the sensor.
  2. On the bench, wire the OLED as in bench lab 6 (GP4 SDA, GP5 SCL, 4.7 kΩ pull-ups) and the buttons from GP14 and GP15 to GND, then flash the starter and open the serial port.
  3. Check each subsystem against what Wokwi did. The log prints LAB3 OK and T=none, the screen shows the error, button A changes screens and button B changes the setpoint.
  4. Press each button 20 times and watch for double steps. Lab 3's debounce is a 30 ms lockout, so check it against the bounce you measured in bench lab 4.

A screen that stays black is bench lab 6's fault, because Lab 3's display_init() cannot report a missing panel, so scan the bus with bench lab 6's program before you change anything here.

Part 2: the NTC driver (about 50 minutes)

  1. Fill in sensor_init(), keeping the I2C set-up, which the OLED needs, and adding adc_init() and adc_gpio_init(26).
  2. Fill in sensor_poll() so that it returns SENSOR_IDLE if 500 ms have not passed since the last sample, and otherwise reads ADC0 16 times, averages (bench lab 5) and converts with lesson 58's Beta equation.
  3. Treat a raw average within 16 codes of 0 or 4095 as SENSOR_ERROR, because near 0 the NTC is shorted and near full scale it is missing.
  4. Build and run in Wokwi. The NTC part's default is 24 °C, so the screen should show about that, and moving its slider makes the reading follow.
  5. Wire the real divider, 10 kΩ from 3V3 (pin 36) to GP26 and the NTC from GP26 to AGND (pin 33), then flash and compare the reading with a room thermometer. Holding the NTC between two fingers should make it climb towards 30 °C within half a minute.
  6. Unplug the NTC, after which the screen must show the sensor error within a second rather than a temperature.
float inv_t = logf(1.0f / ((float)FULL_SCALE / (float)raw - 1.0f)) / BETA + 1.0f / T0_KELVIN;
*celsius = 1.0f / inv_t - 273.15f;

Part 3: what the bench changed (about 30 minutes)

With everything working, compare your bench readings with the simulator's and explain each difference, the typical findings being these.

  • An offset of a degree or two. Your thermistor's Beta may not be 3950 (3380 is also common), and the 10 kΩ resistor and the NTC each have a tolerance. Find the Beta on your part's listing or datasheet and change BETA. A two-point check, room air and a glass of ice water stirred for a minute (0 °C), shows how far off you are.
  • A last digit that flickers. This is ADC noise from bench lab 5. Without the 16-fold averaging it is worse, and the alarm can chatter when the temperature sits at the setpoint. Lab 3's alarm has no hysteresis; consider adding 0.5 °C.
  • The ADC's offset. The Pico 2's ADC carries an offset of about 30 mV, from its own current through the 200 Ω supply filter resistor (Pico 2 datasheet, section 5.3), which bench lab 5 measured. At room temperature that is a fraction of a degree, small but part of the offset.
Your Lab 3 runs on real parts, and you changed exactly one file to get there, which is what the interface was for.

Common mistakes and how to spot them

main.c or ui.c edited to make the NTC fit

The change spreads beyond the driver file, because the interface did not fit the new sensor, whereas the point of the interface is that nothing above it changes. Keep the edit in sensor_ntc.c, and if you cannot, note that the interface was wrong rather than hiding it.

Blocking in sensor_poll()

The buttons and the screen freeze for half a second each time, because a sleep_ms(500) replaced the deadline check. Return SENSOR_IDLE until the deadline has passed.

A temperature reported for an open sensor

The screen shows a very cold reading with the NTC unplugged, because a missing NTC reads near 4095, which the equation turns into a temperature. Range-check the raw value first.

The NTC on GND instead of AGND

The reading works but is noisier than it should be, because the NTC shares the digital ground's noise, whereas AGND is the ADC's reference ground on the Pico 2. Return the divider to AGND.

Summary

  • A small interface (sensor_init, sensor_poll) let a different sensor replace a simulator-only one, with the rest of Lab 3 unchanged.
  • A board is brought up one subsystem at a time, each checked against what the simulator showed.
  • The interface's contract holds: non-blocking, one sample reported once, faults as errors rather than values.
  • Real temperature readings carry Beta, tolerance, noise and offset errors, which a two-point check measures.
Your thermistor's own datasheet or listing: find its resistance at 25 °C and its Beta value (often written B25/50 or B25/85). Compare it with the 3950 the code assumes.
Ask your teacher (the AI agent in this workspace) about anything unclear. Try: "My NTC's datasheet gives B25/85 = 3435. How do I calibrate the code with my two measurements instead of trusting the datasheet value?" Related: Lab 3: Environment monitor, Lesson 58: ADC.
