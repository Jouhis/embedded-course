Timers: PWM, input capture, encoder mode

A timer is a counter that the hardware advances for you. The CPU sets a few registers once, and then the counter times pulses, measures edges and counts rotation while your code does other work.

By the end of this lesson you can compute a timer's prescaler and reload value for a target frequency, configure PWM output and input capture on the Blue Pill's TIM2 to TIM4 through CMSIS registers, and read a rotary encoder in encoder mode.

The idea

A general-purpose timer has a counter, CNT, that counts up on a clock. The clock is first divided by the prescaler PSC, so the counter ticks at f_clk ÷ (PSC + 1). When the counter reaches the auto-reload value ARR, it wraps to zero and raises an update event. The update rate is therefore f = f_clk ÷ ((PSC + 1)(ARR + 1)). The counter runs in hardware, next to the bus. A load of TIM2->CNT reads a register, and the CPU is not involved in the counting itself. That is why a timer can time a pulse more precisely than a delay loop.

The Blue Pill runs from the 8 MHz HSI oscillator in these projects (lesson 40). With PSC = 7 the counter ticks at 1 MHz, so one count is one microsecond. Every number in this lesson is a count of microseconds, and the arithmetic stays easy to check.

PWM: an output that the timer draws for you

Output compare mode drives a pin from the comparison between CNT and a compare register CCRx. In PWM mode 1 the pin is active while CNT < CCR. The duty cycle is CCR ÷ (ARR + 1). For the LED in this lesson, ARR = 999 and CCR = 250 give a 1 kHz signal at 25 % duty. RM0008, chapter "General-purpose timers (TIM2 to TIM5)", PWM mode description

A hobby servo expects a 50 Hz frame (a 20 ms period) with a pulse of about 1 to 2 ms, and the centre position is near 1.5 ms. This is the usual convention for hobby servos, not a figure from this course's sources: check your servo's datasheet before you rely on the end points. Here PSC = 7 and ARR = 19999 give 50 Hz, and CCR = 1500 gives the centre.

Setting the preload bit (OC1PE) and the auto-reload preload bit (ARPE) makes a new ARR or CCR take effect at the next update event. Without them, a write during a period can give one short or long cycle. Always set the preload bits before you start the counter.

Input capture: time the edges

An input channel records the value of CNT when an edge arrives on its pin. Two captures give the pulse width, and the subtraction does the timing. The subtraction must use the counter's width: with a 16-bit counter, (uint16_t)(fall - rise) is correct even if the counter wrapped between the two edges. Input capture is interrupt-free timing. The hardware latches the count at the edge, and the CPU reads it later. This is the reason a pulse-width measurement can be accurate even when the main loop is busy.

Channels 3 and 4 of a timer can both capture the same input, one at the rising edge and one at the falling edge. The solution uses this on TIM3 (CH3 at PB0, CH4 for the falling edge), because the same timer's CH1 is already the servo output. Using CH1 for the input would conflict with the output.

Encoder mode: count rotation

A quadrature encoder has two outputs, A and B, that are 90 degrees out of phase. The order of the edges shows the direction. Encoder mode (SMS = 011 in SMCR) makes the counter count up or down by itself from these two signals, so the CPU reads only CNT. Mode 3 counts edges on both channels, which gives about four counts per detent on a typical mechanical encoder. Check the count with your own encoder before you rely on the figure.

The Wokwi wokwi-ky-040 part has pins CLK (A), DT (B), SW (push button) and the supply pins VCC and GND. Its docs say each detent sends a low pulse on both CLK and DT, and the direction is set by which pin falls first. It has 20 steps per revolution. Wokwi part: KY-040 rotary encoder

Which pins, which timer

Each timer channel has a fixed pin on the default mapping, and this lesson uses only that mapping. TIM2 CH1 is on PA0, TIM3 CH1 is on PA6, TIM3 CH3 is on PB0, and TIM4 CH1 and CH2 are on PB6 and PB7. These are checked against the pinout table of the datasheet. Remapping with AFIO would move them, and the course does not remap. STM32F103x8/xB datasheet, "Pinouts and pin description" table, alternate-function column

The Wokwi docs list TIM1 to TIM4 as simulated on the Blue Pill. They do not say whether encoder mode is simulated, so the encoder line in the solution is not checked by the simulator in this course. Treat it as the reference for the register setup, and test the encoder on hardware when you can.

Hint for the LED timer

With PSC = 7, set ARR so that 1 MHz ÷ (ARR + 1) = 1000 Hz. Then choose PWM mode 1 in OC1M, which is 110 in binary, and set the preload bit.

Hint for the capture

Channel 3 captures the rising edge, and channel 4 captures the falling edge on the same input. The register CCMR2 chooses the input for each channel, and CCER chooses the edge. Channel 4 uses the falling-edge polarity bit CC4P.

You turned one counter into a 1 kHz PWM output, a 50 Hz servo signal, a microsecond pulse measurement and a rotary encoder, and you computed every frequency from the prescaler and the reload value.

"You need a 1 kHz PWM with at least 1 % duty resolution, from an 8 MHz clock. How do you set the prescaler and the reload?" Answer out loud in 60 seconds, then compare.

Model answer

Work out the resolution first. A 1 % duty step needs at least 100 counts in one period. With PSC = 0 the 8 MHz clock gives 8000 counts per millisecond, so ARR = 7999 gives exactly 1 kHz, and the duty step is 8000 ÷ 100 counts. A smaller prescaler gives more steps per period, and the only limit is that ARR must fit in the 16-bit register. Here PSC = 0 already does that, so it is the right choice. The check is ARR = f_clk ÷ ((PSC + 1) × f) − 1. For 1 % steps, CCR = 80 gives 1 % of (ARR + 1). The tempting mistake is a large prescaler that leaves fewer than 100 steps per period, for example PSC = 999, which gives only 8 counts per period.
