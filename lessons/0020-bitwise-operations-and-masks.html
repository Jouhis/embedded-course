Bitwise operations and masks

Almost every line of peripheral code is one of five bit patterns: set, clear, toggle, test, and read-modify-write. Learn them until you stop translating them in your head.

By the end of this lesson you can set, clear, toggle and test one bit, and read or write a multi-bit field, using |, &, ^, ~, << and >>, and you can predict the result of each line before you run it.

The idea

The C bitwise operators act on every bit position at once, with no carry between positions. & keeps a bit only where both inputs have it. | sets a bit where either input has it. ^ flips a bit where the inputs differ. ~ flips every bit. << and >> move bits left and right, and fill with zeros. The operators work on integer types only. Do not use & on a float, and do not use the logical && where you mean the bitwise &. Lesson 45 covers the integer promotion rules that surprise people.

A mask is a pattern with ones in the bits you care about. The masks for one bit are simple: 1u << n has only bit n set. The C you will write on the Pico for an LED on GPIO 25 looks like this: 

// Set bit n: the bit becomes 1, the others stay as they were.
reg |= (1u << n);

// Clear bit n: AND with the inverse mask.
reg &= ~(1u << n);

// Toggle bit n: XOR flips it.
reg ^= (1u << n);

// Test bit n: non-zero if set.
if (reg & (1u << n)) { /* set */ }

Each line is read-modify-write: read the register, change some bits, write it back. The other bits keep their values. Writing the whole register with a constant would wipe them, so the mask is what protects them.

Fields: several bits at once

A field is a group of adjacent bits that hold one value, such as a 3-bit mode. To read it, shift it down to bit 0 and mask off the rest. To write it, clear the field, then OR in the new value shifted to the right place: 

// Field at bits hi..lo. Width = hi - lo + 1.
#define FIELD_MASK(lo, width)  (((1u << (width)) - 1u) << (lo))

// Read: shift down, then mask.
uint32_t mode = (reg >> lo) & ((1u << width) - 1u);

// Write: clear the field, then insert the new value.
reg = (reg & ~FIELD_MASK(lo, width)) | ((value << lo) & FIELD_MASK(lo, width));
Always mask the value before you shift it in. If value is 9 and the field is 3 bits wide, value << lo sets a bit in a neighbouring field, and the bug appears somewhere else entirely.

Why the hardware cares

A peripheral register often has several fields, and some bits are read-only or change on their own. Software that does read-modify-write races with an interrupt that changes the same register between the read and the write. The RP2040 solves this in hardware: each peripheral register block has aliases at offsets +0x2000 (atomic set) and +0x3000 (atomic clear), so one bus write sets or clears bits without a read. RP2040 datasheet, section 2.1.2 (Atomic Register Access) gives the four aliases. Lesson 47 uses the register addresses, and lesson 57 explains why interrupts make this matter.

Hint for field questions

Field questions give you the shift and the mask. First shift right by the low bit, then AND with the mask. The shift moves the field down, and the mask removes the bits above it.

You can predict the result of set, clear, toggle, test and field operations, and you know why each one is a read-modify-write. That is the whole vocabulary for register code: lessons 38, 47 and 62 use exactly these forms.

"Write a C function that sets bits 5 to 3 of a register to a 3-bit value, without disturbing the other bits. Then say what can go wrong if an interrupt runs in the middle." Answer out loud in 60 seconds, then compare.

Model answer

Clear the field with reg &= ~FIELD_MASK, then OR in (value & 7u) << 3. Mask the value first so it cannot spill into bit 6. If an interrupt changes the register between the read and the write, its change is lost. Fix it with a critical section, or with the atomic set and clear aliases where the peripheral has them.
