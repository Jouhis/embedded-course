Bitwise operations and masks

Almost every line of peripheral code is one of five bit patterns: set, clear, toggle, test, and read-modify-write. Learn them until you stop translating them in your head.

By the end of this lesson you can set, clear, toggle and test one bit, and read or write a multi-bit field, using |, &, ^, ~, << and >>, and you can predict the result of each line before you run it.

Where we are and why it matters

Lesson 19 taught you to read a register as bits, in binary, hex and decimal. This lesson teaches you to change those bits without disturbing the rest. A peripheral register such as a GPIO output register has one bit per pin, and every bit belongs to a different wire. When you turn on the LED on GP25, you must not turn off the pin next to it. The operators in this lesson are how C lets you change one bit and leave the others alone.

The skill appears in every driver you will write. The Pico SDK, the STM32 HAL and the Zephyr drivers all use the same few patterns, and a code review of a driver is mostly a check that each mask is right. A bug in one mask can break a peripheral that has nothing to do with the line you were editing, so people in this job read masks slowly and carefully.

The bitwise operators, one bit at a time

The C bitwise operators act on every bit position at once, with no carry between positions. Take one position at a time. & (AND) gives 1 only where both inputs are 1. | (OR) gives 1 where either input is 1. ^ (XOR) gives 1 where the inputs differ. ~ (NOT) flips every bit. << moves bits towards the most significant end, and >> moves them towards bit 0. Both shifts fill the vacated positions with zeros, for unsigned values. The operators work on integer types only. Do not use & on a float, and do not use the logical && where you mean the bitwise &. Each operator is the logic gate of lesson 22 applied to a whole word at once. A 32-bit AND is 32 AND gates side by side, each taking one bit from each operand. That is why a bitwise operation takes one instruction on the core, while a loop over the bits would take many.

Worked example: one byte through four operators

Let x = 0xC5 (1100 0101) and y = 0x0F (0000 1111). Work each result bit by bit, then convert to hex.

  1. x & y: keep a bit only where both are 1. The high nibble of y is zero, so the high nibble is zero. The low nibble of x is 0101 and of y is 1111, so the result is 0101. Answer: 0000 0101, which is 0x05.
  2. x | y: set a bit where either is 1. The high nibble comes from x (1100), and the low nibble is all 1s. Answer: 1100 1111, which is 0xCF.
  3. x ^ y: flip where they differ. The high nibble of x is 1100 and of y is 0000, so the high nibble stays 1100. The low nibble of x is 0101 and of y is 1111, so the bits that differ are the ones that are 0 in x. Answer: 1100 1010, which is 0xCA.
  4. ~x: flip every bit of 1100 0101. Answer: 0011 1010, which is 0x3A.

The pattern to notice is that AND with a mask keeps only the bits the mask selects, and OR with a mask forces them to 1. The next section uses exactly that.

Masks: one pattern that selects the bits you care about

A mask is a bit pattern with ones in the bits you want to keep, change or test. A single-bit mask for bit n is 1u << n, which has only bit n set. For bit 5 it is 0x20, and for bit 25 it is 0x02000000. The suffix u makes the constant unsigned. That matters: a plain 1 << 31 shifts a signed int into its sign bit, which C does not define. Lesson 45 explains the rule.

With a mask, every bit operation is the same shape. You combine the register with a mask using one operator, and the mask decides which bits move. The table below is the whole vocabulary for one bit.

OperationCWhy it works
Set bit nreg |= (1u << n);OR with 1 forces the bit to 1; OR with 0 leaves a bit as it was.
Clear bit nreg &= ~(1u << n);AND with 0 forces the bit to 0; the inverted mask has 1s everywhere else.

The C you will write on the Pico for an LED on GPIO 25 looks like this:

// Set bit n: the bit becomes 1, the others stay as they were.
reg |= (1u << n);

// Clear bit n: AND with the inverse mask.
reg &= ~(1u << n);

// Toggle bit n: XOR flips it.
reg ^= (1u << n);

// Test bit n: non-zero if set.
if (reg & (1u << n)) { /* set */ }

Worked example: set, clear and toggle on 0x2C

Start from reg = 0x2C, which is 0010 1100. Apply three operations in turn.

  1. reg |= (1u << 0);. The mask is 0x01. OR sets bit 0, which was 0, so 0010 1101, which is 0x2D.
  2. reg &= ~(1u << 5);. The mask is 0x20, and its inverse is 0xDF (1101 1111). AND clears bit 5, which was 1, and keeps the others. 0000 1101, which is 0x0D. Check: 0x2D − 0x20 = 0x0D.
  3. reg ^= (1u << 7);. The mask is 0x80. XOR flips bit 7, which was 0, so 1000 1101, which is 0x8D.

Each line reads the register, changes some bits and writes it back. That is a read-modify-write. The other bits keep their values because the mask does not select them, and the writing back puts them in the same place they came from.

Why a read-modify-write is three steps on the bus

The C line reg |= mask looks like one operation, but on a Cortex-M core it becomes three. The core loads the register value from its address into a register, which is one bus read. It ORs the mask into that value inside the core, which costs no bus traffic. It stores the result back to the same address, which is one bus write. The core's load and store instructions move data across the bus to the peripheral. Lesson 38 explains how a peripheral register is reached through an address in the memory map.

Those three steps are the danger. If an interrupt runs between the load and the store, and it changes the same register, the store writes back the old value of the bits the interrupt changed. The interrupt's change is lost. Lesson 57 covers interrupts in practice, and this lost update is one of the classic reasons driver code disables interrupts around a read-modify-write.

Fields: several bits that hold one value

A field is a group of adjacent bits that together hold one number, such as a 3-bit mode or a 4-bit prescaler. A datasheet names the field and its bit range, for example bits 6 to 4. To read a field, shift it down so its lowest bit is bit 0, then mask off everything above it. To write a field, clear it with the inverse of its mask, then OR in the new value after shifting it to the right place. 

// Field at bits hi..lo. Width = hi - lo + 1.
#define FIELD_MASK(lo, width)  (((1u << (width)) - 1u) << (lo))

// Read: shift down, then mask.
uint32_t mode = (reg >> lo) & ((1u << width) - 1u);

// Write: clear the field, then insert the new value.
reg = (reg & ~FIELD_MASK(lo, width)) | ((value << lo) & FIELD_MASK(lo, width));

Worked example: write a 3-bit field at bits 6 to 4

Let reg = 0x56, which is 0101 0110. Bits 6 to 4 hold 101, which is 5. Write the value 3, which is 011, into that field.

  1. Build the mask. Bits 6 to 4 are 0111 0000, which is 0x70. FIELD_MASK(4, 3) gives ((1u << 3) - 1u) << 4, which is (0b111) << 4, and that is 0x70.
  2. Clear the field. The inverse of 0x70 is 0x8F (1000 1111). 0x56 & 0x8F is 0x06, because only bits 3 to 0 survive.
  3. Shift the new value into place and mask it. 3 << 4 is 0x30, and 0x30 & 0x70 is still 0x30.
  4. Combine. 0x06 | 0x30 is 0x36, which is 0011 0110. Bits 6 to 4 now hold 011, and bits 3 to 0 are unchanged.

Read the same field back with (reg >> 4) & 7u. The shift gives 0x03, the mask keeps three bits, and the answer is 3.

Always mask the value before you shift it in. If value is 9 and the field is 3 bits wide, value << lo sets a bit in a neighbouring field, and the bug appears somewhere else entirely.

Writing the Pico LED without a read

The RP2040 can avoid the read in the middle. Each peripheral register block is allocated 4 kB of address space, and each register can be reached through four addresses. The normal address does a plain read or write. The address plus 0x1000 does an atomic XOR on write, the address plus 0x2000 does an atomic bitmask set on write, and the address plus 0x3000 does an atomic bitmask clear on write. The datasheet says this lets software change a field without a read-modify-write sequence (RP2040 datasheet, section 2.1.2, Atomic Register Access).

The SIO block is the exception. It is the single-cycle IO block that the cores use for GPIO, and it does not support atomic aliases at the bus level. Its GPIO registers have their own set, clear and XOR registers instead. The Pico SDK header lists them: SIO_GPIO_OUT_OFFSET is 0x10, SIO_GPIO_OUT_SET_OFFSET is 0x14, SIO_GPIO_OUT_CLR_OFFSET is 0x18 and SIO_GPIO_OUT_XOR_OFFSET is 0x1C, all added to SIO_BASE, which is 0xD0000000.

The LED on the Pico is GPIO 25 (the SDK defines PICO_DEFAULT_LED_PIN as 25 in its board header). Its mask is 1u << 25, which is 0x02000000. To turn the LED on with one write, store that mask to the SET register at 0xD0000014. To toggle it, store the mask to the XOR register at 0xD000001C. Neither write reads the register, so nothing else on the GPIO bank can be lost between a read and a write. Writing to SET only changes the bits you name, so the other outputs keep their values.

The SIO GPIO registers accept bits 0 to 29 only, as the SDK's SIO_GPIO_OUT_SET_BITS mask shows. Bits 30 and 31 are not GPIOs on the RP2040, so a mask for them does nothing useful.

Common mistakes and how to spot them

Five mistakes account for most bit bugs in firmware. Each one has a symptom you can see.

  1. Using = where you meant |=. Writing GPIO_OUT = 1u << 25; replaces the whole register, so every other output goes low. The symptom is an LED that turns off when a second output is driven. The fix is to use the SET alias, or the |= form on a register you have read.
  2. Forgetting the inversion when clearing. The line reg &= (1u << 5); keeps only bit 5 and clears everything else. On 0x2C it gives 0x20, not 0x0C. The symptom is a peripheral that loses its configuration when you change one bit. The fix is ~ on the mask.
  3. Precedence in a test. In C, == binds more tightly than &. So reg & 1u << 3 == 1 means reg & ((1u << 3) == 1), which is reg & 0, and the test is never true. Compiling with -Wall gives the warning suggest parentheses around comparison in operand of '&', which is the symptom. The fix is (reg & (1u << 3)) != 0. Put parentheses around every bitwise expression.
  4. An unmasked value shifted into a field. If value is 9 and the field is 3 bits, the shift pushes bit 3 into the next field. The symptom is a change in a field you did not touch. The fix is to mask the value to the field width before the shift.
  5. A signed mask. The expression 1 << 31 shifts a signed int into its sign bit, and C says that is undefined. The symptom can be a wrong mask that only breaks on one compiler. The fix is 1u << 31.

In real projects

Professional drivers rarely write raw masks in every function. They name each mask, or they use the device header's _Pos and _Msk macros. The STM32F103 header defines them for every field, so RCC_CR_HSION_Msk is 0x1UL shifted by RCC_CR_HSION_Pos, which is 0. A reviewer then reads the name, not the number. The rule in most teams is that a bare hex constant in driver code is a finding. This rule keeps the mask next to its meaning.

The atomic aliases are how the Pico SDK avoids the race in the bus sequence. The SDK's addressmap.h defines REG_ALIAS_XOR_BITS as 0x1 << 12, REG_ALIAS_SET_BITS as 0x2 << 12 and REG_ALIAS_CLR_BITS as 0x3 << 12. The header address_mapped.h provides hw_set_bits() and hw_clear_bits() as functions on a register pointer, for peripherals that have the aliases. For a register that does not have them, the same rule applies as in the table above: disable interrupts around the read-modify-write, or make sure no interrupt touches that register.

In interviews, the question is usually a small function. A typical prompt is "write a function that sets bits 5 to 3 of a register to a 3-bit value without disturbing the others, then say what can go wrong if an interrupt runs in the middle". A good answer uses a mask, masks the value, and names the lost update.

Summary

  • The bitwise operators work on every bit position at once, with no carry between positions.
  • A mask selects bits. Use 1u << n for one bit, so the constant is unsigned.
  • Set with |=, clear with &= ~mask, toggle with ^=, and test with & mask.
  • Every change to a register is a read, a change and a write. The bus performs two transfers, and an interrupt can run between them.
  • A field is read by shifting down and masking, and written by clearing it and then OR-ing in the shifted value.
  • The RP2040 gives most peripherals SET, CLR and XOR aliases at +0x2000, +0x3000 and +0x1000. The SIO GPIO registers have their own set and clear registers at 0x14 and 0x18.
  • Put parentheses around every bitwise expression, because == binds more tightly than &.

Hint for field questions

Field questions give you the shift and the mask. First shift right by the low bit, then AND with the mask. The shift moves the field down, and the mask removes the bits above it.

You can predict the result of set, clear, toggle, test and field operations, and you know why each one is a read-modify-write. That is the whole vocabulary for register code: lessons 38, 47 and 62 use exactly these forms.
