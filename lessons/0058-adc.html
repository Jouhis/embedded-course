ADC: thermistors and oversampling

A printer's heater temperature is a voltage on one pin. The ADC turns that voltage into a 12-bit number, a divider and a formula turn the number into degrees, and averaging several samples takes the jitter out of the answer.

By the end of this lesson you can read a 12-bit ADC channel with the Pico SDK, convert a thermistor divider reading to degrees with Wokwi's beta formula, and explain why averaging 16 conversions reduces noise.

Where we are and why it matters

So far every input in this course has been a digital one: a pin is high or low, and lessons 16 and 52 taught you how to read that reliably. Lesson 8 introduced the voltage divider, which turns one voltage into a smaller one in a fixed ratio. A sensor that changes its resistance with temperature, light or pressure needs both ideas: a divider converts the resistance change into a voltage, and something must measure that voltage. The measuring part is the analogue-to-digital converter (ADC).

In products this is everywhere. A 3D printer reads its heater and bed temperatures through thermistors and turns the voltages into degrees for the control loop. A battery pack reports its voltage through a divider into an ADC, and a pressure sensor for a vacuum pump does the same. The firmware job is to choose the channel, take a few readings, reject the impossible ones, convert the number to a physical unit, and check that the result makes sense. This lesson covers each step for a thermistor on the Pico.

The concepts, one at a time

Four ideas come together here: what an ADC does to a voltage, what a thermistor does to a divider, why a reading carries noise, and why averaging reduces that noise. Take them in that order.

What an ADC produces

An analogue-to-digital converter (ADC) compares the voltage on an input pin with a reference and produces an integer, called a code, that is proportional to the voltage. The RP2040 ADC produces 12 bits, so its codes run from 0 to 4095, which is 212 − 1. It is a successive-approximation converter: it decides one bit at a time, from the most significant bit down, by comparing the input with a trial level RP2040 datasheet, section 4.9.2.

The ADC has one converter shared by four pins. Pins GP26 to GP29 are ADC inputs 0 to 3, and input 4 is the internal temperature sensor. A small multiplexer selects which input the next conversion reads. You set it by writing the input number to the AINSEL field, and the datasheet says no settling time is needed after you switch RP2040 datasheet, section 4.9.2.1. A single conversion takes 96 cycles of the 48 MHz ADC clock, which is 2 µs, so the converter can make 500,000 samples per second RP2040 datasheet, section 4.9.2. The internal temperature sensor on the RP2040 reads 0 in the Wokwi simulator, so this lesson uses an external NTC thermistor instead.

The step size, called one LSB (least significant bit), is the reference voltage divided by the number of codes. The RP2040 ADC's supply, ADC_AVDD, is nominally 3.3 V RP2040 datasheet, section 2.9.5. One code is therefore 3.3 V ÷ 4096 = 0.806 mV. The SDK's own example uses the same factor, 3.3f / (1 << 12) pico-examples, adc_console.

A thermistor is a divider

A thermistor is a resistor whose value changes strongly with temperature. An NTC (negative temperature coefficient) thermistor's resistance falls as it warms. A resistance cannot be read by the ADC directly, because the ADC measures voltage. So the thermistor is put in a divider with a fixed resistor, and the midpoint voltage tracks the temperature. This is the divider from lesson 8, with one arm changing.

The NTC sits on the ground side, and the fixed resistor sits on the supply side. When the NTC is warm, its resistance is small, so the midpoint is pulled toward ground and the ADC code is small. When it is cold, the code is large. The Wokwi NTC part already contains this arrangement, as a 10 kΩ NTC in series with a 10 kΩ fixed resistor, so in the simulator you connect only VCC, OUT and GND Wokwi, NTC temperature sensor. Noise, and why one reading is not enough

Every reading carries noise: small random changes from the power supply, the converter itself and the pickup on the wire. A 12-bit ADC does not give 12 clean bits. The RP2040 datasheet measures an effective number of bits (ENOB) of 8.7 for its typical device, with a 997 Hz test input and a sample rate of 250 ksps RP2040 datasheet, section 4.9.3, Tables 565 and 566. The ENOB is the number of bits that are useful once the noise is counted. The lowest bits of a single reading are partly noise.

Averaging is the standard fix. If you add N independent readings and divide by N, the random part of the error shrinks by about the square root of N. Sixteen readings cut the noise by a factor of four. Averaging helps only while the noise is larger than one code step. If the signal is perfectly steady, extra samples give the same number every time.

Worked example: from a temperature to a code and back

Take the thermistor at 24 °C, the Wokwi default, and follow the chain from the temperature to the number the Pico reads. This is the calculation the simulator does, so the result is what you should see.

  1. The thermistor's resistance. The beta equation gives the NTC's resistance at a temperature T from its value at 25 °C (R0 = 10 kΩ), its beta constant B = 3950 K, and the absolute temperatures T and T0 = 298.15 K. T = 24 °C is 297.15 K. So R = 10,000 × e3950 × (1/297.15 − 1/298.15) = 10,000 × e0.0447 = 10,456 Ω, about 10.46 kΩ Wokwi, NTC temperature sensor.
  2. The divider ratio. The NTC is the lower arm, and the fixed resistor is 10 kΩ. The pin sees RNTC ÷ (Rfixed + RNTC) = 10,456 ÷ 20,456 = 0.5111 of the supply.
  3. The pin voltage. The supply is 3.3 V, so the pin is at 0.5111 × 3.3 V = 1.686 V.
  4. The code. The ADC has 4096 codes across 3.3 V, so the code is 0.5111 × 4095 = 2093. The 4095 is the top code, not 4096, because the codes run from 0 to 4095. That is the raw value the program should read.
  5. Back to degrees. The formula in the next section takes 2093 and returns 24.0 °C. The round trip closes, so the code, the divider and the formula agree.

If your simulator's reading is near 2093, the divider and the constants are right. If it is far from that, the formula constant is the first place to look, as the mistakes section explains.

The formula, and the line that must change

Solve the divider for the NTC's resistance. Because the pin sees a/4095 of the supply, RNTC ÷ (Rfixed + RNTC) = a/4095. Cross-multiplying gives a × Rfixed = RNTC × (4095 − a), so RNTC = Rfixed ÷ (4095/a − 1). For the 2093 example that is 10,000 ÷ 0.9566 = 10,455 Ω. The beta equation then turns that resistance into a temperature. Wokwi's documentation gives both steps in one line, with the beta coefficient of 3950 by default Wokwi, NTC temperature sensor. 

/* Wokwi's formula, with the full-scale constant changed from 1023 (10-bit) to 4095 (12-bit) */
float celsius = 1 / (log(1 / (4095 / a - 1)) / BETA + 1 / 298.15) - 273.15;

Read the expression from the inside out. 4095 / a is the full-scale code divided by the reading, which equals (Rfixed + RNTC) ÷ RNTC. Subtracting 1 leaves Rfixed ÷ RNTC, and its reciprocal, which is what the 1 / inside the log takes, is RNTC ÷ Rfixed. The log of that ratio is what the beta equation needs. Dividing by BETA and adding 1/298.15 gives 1/T, the reciprocal of the temperature in kelvin. The outer 1/ turns it back into kelvin, and - 273.15 converts to Celsius.

Two parts of the line are easy to get wrong. The first is the constant 4095. Wokwi's documented formula uses 1023, which is the top code of a 10-bit analogRead(). The Pico gives 12 bits, so the constant must be 4095. The second is the temperature 298.15 K, which is 25 °C in kelvin and is the reference point where the thermistor's value R0 is 10 kΩ. Using 273 instead gives about −1 °C for the 2093 reading, which is 25 °C too low, so the constant matters a great deal.

The formula divides by a − 1 and takes a log, so a raw reading of 0 or 4095 is not valid and the code must reject it. At 4095 the term is zero, and at 0 the division has no meaning. The solution's ntc_celsius() returns NaN for both.

Oversampling in code

The averaging idea becomes a small function. The reading is taken with adc_read(), which starts a conversion and waits until it is ready. Each call takes about 2 µs, so 16 calls take about 32 µs. 

static uint16_t read_averaged(uint input) {
    adc_select_input(input);     /* AINSEL: the input number, 0 for GP26 */
    uint32_t sum = 0;                  /* 16 results of 12 bits fit easily in 32 bits */
    for (int i = 0; i < 16; i++) {
        sum += adc_read();       /* blocks for one conversion, about 2 us */
    }
    return (uint16_t)(sum / 16);
}
  1. adc_select_input(input) writes the input number into the AINSEL field. The argument is the input number, not the GPIO number, so GP26 is input 0. The solution calls this once per function call, before the loop.
  2. uint32_t sum = 0; holds the total. Each reading is 12 bits, so 16 of them need at most 16 bits more, and 32 bits leaves room with no risk of overflow.
  3. sum += adc_read(); adds one conversion. The SDK's adc_read() sets the start bit, polls the ready bit, and returns the 16-bit result register. It blocks, which is acceptable here because each conversion is short. Lesson 55 explains when a blocking wait is not acceptable.
  4. return (uint16_t)(sum / 16); divides once, at the end, with integer division. The cast returns a value that fits in the 12-bit range.
The ADC pin and the GPIO function are separate settings. Call adc_gpio_init() on the pin before you read it. The SDK sets the pin's function to none, disables its pulls, and turns off its digital input, so the pin does not fight the analogue level Pico SDK, hardware/adc.h.

Hint for the wrong temperature

In the starter, the temperature prints as nan, not as a number far from 24 °C. The starter's ntc_celsius() returns NaN for any raw reading at or above 1023, and a reading near 2093 is above that. At 24 °C the raw value should be near 2093 on the 12-bit scale. Once ADC_FULL_SCALE is 4095, the reading is accepted and the temperature is about 24 °C.

Hint for the average

Add up the conversions in a uint32_t and divide once at the end. Divide each reading first and the rounding error adds up.

The reference solution is in projects/0058-adc/solution. Try first, compare after. The serial monitor prints ADC OK once, then a line every half second.

You turned a divider into a temperature with a formula, you made the formula match the 12-bit ADC, and you averaged the readings to steady them. The same three steps work for any analogue sensor on the Pico.

Common mistakes and how to spot them

Mistake 1: the 10-bit constant. Symptom: the temperature is wrong, or prints as nan. With ADC_FULL_SCALE set to 1023, the formula's 1023 / a − 1 is negative for any reading above 1023, and the log of a negative number is undefined. The starter does this on purpose. Fix: use 4095 for the 12-bit ADC, and check the result against the 24 °C worked example.

Mistake 2: reading the wrong channel. Symptom: the NTC and the pot print the same value, or the pot's value looks like a temperature. The call to adc_select_input() was left out, so the conversion reads whichever input was selected last. Fix: select the input before each block of conversions, and check that the two channels print different values when you turn the pot.

Mistake 3: dividing each reading before the sum. Symptom: the averaged temperature sits a little below the single readings, and the gap grows as the number of samples grows. Each integer division drops a fraction. At raw 2093, dividing each of 16 readings by 16 first gives a sum of 2080 instead of 2093, so the average is 13 codes low, about 10 mV. Fix: add all the readings first, then divide once.

Mistake 4: the pin not set up. Symptom: the reading is less steady than the noise budget suggests, and it changes when you touch nearby wires. The pin still has its digital input on, so it reads the logic level as well as the analogue one. Fix: call adc_gpio_init() on every ADC pin before the first read.

Mistake 5: reading the internal temperature sensor in the simulator. Symptom: the RP2040 die temperature reads 0 in Wokwi, and any code that converts it to degrees prints a fixed, wrong value. The simulator does not model that sensor. Fix: use the external NTC on GP26, as this lesson does, and use the datasheet's formula only on real hardware, where it applies RP2040 datasheet, section 4.9.5.

In real projects

Production firmware rarely calls a blocking read in a loop. The usual pattern is free-running sampling: the ADC converts on its own at a fixed rate, and each result goes into a FIFO that the DMA moves to a buffer, so the CPU is not involved in each sample. The datasheet describes this mode, with the pacing timer set by the DIV register and the sample FIFO enabled by FCS, in sections 4.9.2.2 and 4.9.2.5 RP2040 datasheet, sections 4.9.2.2 and 4.9.2.5. Blocking reads like the ones in this lesson are the right first step, because they are easy to check.

A reviewer looks for three things in a sensor driver. The reference voltage and the full-scale code must agree, as in mistake 1. The raw value must be checked before it enters a formula that has a domain, which is the reject-at-the-limit rule. And the driver must say what resolution it claims. Sensor datasheets give an accuracy in degrees, and the ADC's noise and the divider's tolerance decide whether the claim is possible.

In interviews, the question "what is the resolution of a 12-bit ADC at 3.3 V" tests whether you know that the ideal step is about 0.8 mV and that the effective number of bits is lower. The model answer below gives the number the RP2040 datasheet measures, which is the kind of citation a good answer includes.

Summary

  • The RP2040 ADC returns a 12-bit code from 0 to 4095 for a voltage between 0 and the 3.3 V reference. One code is about 0.806 mV.
  • GP26 to GP29 are inputs 0 to 3, and input 4 is the internal temperature sensor. adc_select_input() takes the input number, not the GPIO number.
  • One conversion takes 96 cycles of the 48 MHz clock, which is 2 µs, and adc_read() blocks until it is ready.
  • A thermistor is a resistor in a divider. The NTC is the lower arm, so a warmer NTC gives a smaller code.
  • The beta formula turns a code into degrees. Use 4095 for the 12-bit full scale, and reject raw values of 0 and 4095.
  • Averaging N readings cuts random noise by about the square root of N. Add first, then divide once.
  • Call adc_gpio_init() on each analogue pin, so its digital input does not fight the analogue level.

Model answer

One code is 3.3 V ÷ 4096, about 0.8 mV, so the ideal resolution is 12 bits. The useful number is lower because noise, reference error and the converter's own nonlinearity take bits away. The RP2040 datasheet measures 8.7 effective bits at a typical test input. Averaging reduces random noise, but cannot remove a systematic error such as a wrong reference or a wrong divider ratio.

RP2040 datasheet, section 4.9 (ADC and temperature sensor): read 4.9.2 for the 96-cycle conversion and the input pins, 4.9.2.1 for AINSEL, and 4.9.3 with Tables 565 and 566 for the effective number of bits. Then read the Pico SDK ADC reference for adc_read.
