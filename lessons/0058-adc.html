ADC: thermistors and oversampling

A printer's heater temperature is a voltage on one pin. The ADC turns that voltage into a 12-bit number, a divider and a formula turn the number into degrees, and averaging several samples takes the jitter out of the answer.

By the end of this lesson you can read a 12-bit ADC channel with the Pico SDK, convert a thermistor divider reading to degrees with Wokwi's beta formula, and explain why averaging 16 conversions reduces noise.

The idea

The RP2040 has one successive-approximation ADC shared by four pins. It converts one channel at a time and returns a 12-bit result from 0 to 4095 RP2040 datasheet, section 4.9. Pins GP26 to GP29 are ADC inputs 0 to 3, and input 4 is the internal temperature sensor. A single conversion takes 96 ADC clock cycles, which is 2 µs at 48 MHz, so the ADC can make 500,000 samples per second RP2040 datasheet, section 4.9.2. The internal temperature sensor in the RP2040 reads 0 in the Wokwi simulator, so this lesson uses an external NTC thermistor instead.

One code step is the reference voltage divided by 4096. With the 3.3 V supply the ADC uses, one step is 3.3 V ÷ 4096 = 0.806 mV. The SDK's own example uses the same factor, 3.3f / (1 << 12) pico-examples, adc_console.

A thermistor is a divider

An NTC thermistor's resistance falls as it warms. Put it in series with a fixed 10 kΩ resistor, and the midpoint voltage tracks temperature. This is the divider from lesson 8. The NTC sits on the ground side, and the fixed resistor sits on the supply side.

The ADC pin sees the fraction a/4095 = RNTC / (Rfixed + RNTC). Solving for the NTC resistance gives RNTC = Rfixed × (4095/a − 1). Wokwi's documentation gives the conversion from the reading to degrees directly, with a beta coefficient of 3950 by default Wokwi, NTC temperature sensor. 

/* Wokwi's formula, with the full-scale constant changed from 1023 (10-bit) to 4095 (12-bit) */
float celsius = 1 / (log(1 / (4095 / a - 1)) / BETA + 1 / 298.15) - 273.15;

The formula is written for a 10-bit reading in Wokwi's own Arduino example. The Pico gives 12 bits, so the constant changes from 1023 to 4095. The formula divides by a − 1 and takes a log, so a raw reading of 0 or 4095 is not valid and the code must reject it. The expected raw value is computed, not yet simulated. With the NTC at 24 °C (about 10.46 kΩ) and a 10 kΩ fixed resistor, the ratio is 0.511, so the raw value is about 2093. Check your simulator's reading against this.

Noise and oversampling

Every reading carries noise, and a 12-bit ADC does not give 12 clean bits. The RP2040 datasheet measures an effective number of bits of 8.7 at a typical 997 Hz test input RP2040 datasheet, section 4.9.3, Table 566. The lowest bits of a single reading are partly noise.

Averaging N readings reduces random noise by about the square root of N. Sixteen readings cut the noise by a factor of four. Averaging helps only while the noise is larger than one code step. If the signal is perfectly steady, extra samples give the same number every time. 

static uint16_t read_averaged(uint input) {
    adc_select_input(input);     /* AINSEL: the input number, 0 for GP26 */
    uint32_t sum = 0;                  /* 16 results of 12 bits fit easily in 32 bits */
    for (int i = 0; i < 16; i++) {
        sum += adc_read();       /* blocks for one conversion, about 2 us */
    }
    return (uint16_t)(sum / 16);
}
The ADC pin and the GPIO function are separate settings. Call adc_gpio_init() on the pin before you read it. It disables the digital input, so the pin does not fight the analogue level.

Try it in Wokwi

The project projects/0058-adc wires an NTC thermistor to GP26 and a potentiometer to GP27. It reads both channels every half second, averages 16 conversions each, and prints the temperature and the pot voltage.

  1. Open projects/0058-adc/starter in VS Code (File → Open Folder).
  2. Build: Ctrl+Shift+B. Start the simulator: F1 → Wokwi: Start Simulator.
  3. Your task: make read_averaged() average OVERSAMPLE conversions, set OVERSAMPLE to 16, and change ADC_FULL_SCALE from 1023 to 4095. The starter uses the 10-bit value, so its temperature is wrong. Then print ADC OK once, after a valid reading.
Hint for the wrong temperature

At 24 °C the raw value should be near the middle of the range, about 2093 on the 12-bit scale. If your temperature is far off, compare the constant in the formula with the number of codes the ADC returns.

Hint for the average

Add up the conversions in a uint32_t and divide once at the end. Divide each reading first and the rounding error adds up.

The reference solution is in projects/0058-adc/solution. Try first, compare after. The serial monitor prints ADC OK once, then a line every half second.

You turned a divider into a temperature with a formula, you made the formula match the 12-bit ADC, and you averaged the readings to steady them. The same three steps work for any analogue sensor on the Pico.

"What is the resolution of a 12-bit ADC at 3.3 V, and what limits the number of useful bits?" Answer out loud in 60 seconds, then compare.

Model answer

One code is 3.3 V ÷ 4096, about 0.8 mV, so the ideal resolution is 12 bits. The useful number is lower because noise, reference error and the converter's own nonlinearity take bits away. The RP2040 datasheet measures 8.7 effective bits at a typical test input. Averaging reduces random noise, but cannot remove a systematic error such as a wrong reference or a wrong divider ratio.

RP2040 datasheet, section 4.9 (ADC and temperature sensor): read 4.9.2 for the 96-cycle conversion and the input pins, and 4.9.3 with Table 566 for the effective number of bits. Then read the Pico SDK ADC reference for adc_read.
