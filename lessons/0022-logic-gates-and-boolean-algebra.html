Logic gates and Boolean algebra

Circuits that compute functions of bits

By the end of this lesson you can write the truth table of a gate circuit, rewrite an expression with De Morgan's laws, and wire a gate circuit in Wokwi so that the Pico's test bench prints TRUTH TABLE OK.

Bitwise operations in hardware

Lesson 16 established that a digital pin carries a voltage read as high or low, lesson 17 showed how to read a schematic and its symbols, and lessons 19 to 21 covered bit patterns and C's bitwise operators. A logic gate is the hardware that performs one of those bitwise operations on a single bit. The & operator from lesson 20 is, inside the chip, a row of AND gates, one per bit position.

Many everyday decisions inside a microcontroller are gate circuits. An address leaves the core as 32 bits, and each peripheral must decide whether the address is its own, a timer must check whether an overflow and an enable are both set, and a safety circuit must check whether any of four sensors has tripped. An engineer who writes or reviews such logic must be able to predict its output for every input, and that prediction is the truth table, so this lesson is about building one and checking a circuit against it.

Logic gates and truth tables

A logic gate takes one or two input bits and produces one output bit. Its output depends only on the present inputs, with no memory of earlier ones, a property called combinational logic; memory first appears in lesson 24.

A truth table lists the output for every combination of inputs. One input gives two rows and two inputs give four, and in general n inputs give

rows = 2n(1)

where n is the number of inputs, so a three-input gate has 8 rows rather than 6, since each input doubles the count. A truth table is a complete specification: two circuits with the same table compute the same function, however different their wiring looks.

ABANDORXORNAND
000001
010111
100111
111100

The table is read column by column. AND is 1 only in its last row, where both inputs are 1, while OR is 1 in three rows and 0 only when both inputs are 0. XOR, the exclusive OR, is 1 when the inputs differ, and NAND, NOT AND, is the AND column with every output flipped. NOT has a single input and turns 0 into 1 and 1 into 0, NOR is NOT OR, and XNOR is NOT XOR. The bubble on a gate symbol means that the output is inverted, which is why a NAND symbol is an AND symbol with a small circle at its output. Lesson 17 showed that a schematic symbol specifies the function. The bubble is the only difference between an AND symbol and a NAND symbol, so read it carefully.

Worked example: a table row as a logic statement

Take the XOR row where A is 1 and B is 0 and say it as a sentence: the output is 1 when A is 1 and B is 0, because the inputs differ. For AND the same row reads: the output is 0, because the inputs are not both 1. Each row is one true statement about the gate, so if you can say the four rows of a table in plain words, you have understood the gate and can check any circuit by testing each sentence against the wiring.

A car's interior light comes on when any door is open. Each door has a switch, and the switches are wired in parallel, so any one closed switch lights the lamp, which is an OR gate built from wire. A seat-belt warning is an AND, since it sounds when the driver's seat is occupied and the belt is unbuckled. Each such rule is a Boolean function before anyone decides whether to build it from switches, gates or code.

Boolean algebra

Boolean algebra is the notation for gate circuits. AND is written as a dot or by juxtaposition, so A AND B is A·B or AB, OR is written as a plus, so A OR B is A + B, and NOT is an overbar, so NOT A is Ā. The algebra works on the values 0 and 1 only, and each of its rules can be checked with a truth table. Among the most useful identities are A · 1 = A, A + 0 = A, A · 0 = 0, A + 1 = 1, A · Ā = 0 and A + Ā = 1.

In practice the commutative, associative and distributive laws matter most, and they are the same as in ordinary algebra. A·(B + C) = A·B + A·C holds for Boolean values, which you can confirm by testing the eight rows of its three variables. Such a check is always possible because there are only finitely many rows, and this is what makes Boolean algebra safe for hardware: every identity can be verified exhaustively.

Worked example: proving De Morgan's laws

The most useful identities for gate design are De Morgan's laws,

NOT (A AND B) = (NOT A) OR (NOT B)(2)

NOT (A OR B) = (NOT A) AND (NOT B)(3)

where A and B are single bits. We prove Equation 2 by evaluating both sides for every row and comparing them.

  1. Row A = 0, B = 0: NOT (A AND B) = NOT 0 = 1, and (NOT A) OR (NOT B) = 1 OR 1 = 1. The two sides agree.
  2. Row A = 0, B = 1: NOT (0 AND 1) = NOT 0 = 1, and (NOT 0) OR (NOT 1) = 1 OR 0 = 1. They agree.
  3. Row A = 1, B = 0: NOT (1 AND 0) = 1, and (NOT 1) OR (NOT 0) = 0 OR 1 = 1. They agree.
  4. Row A = 1, B = 1: NOT (1 AND 1) = NOT 1 = 0, and (NOT 1) OR (NOT 1) = 0 OR 0 = 0. They agree.

All four rows agree, so the two expressions are the same function, and Equation 3 is proved in the same way. In practice this means that a NOT in front of an AND can be moved inside, turning the AND into an OR, so a chip designer can rewrite a function into whichever form is cheapest to build from the gates the process offers.

Universal gates

A universal gate is one from which every other logic function can be built on its own. NAND and NOR are both universal, but AND is not, because no combination of AND gates can turn a 1 into a 0 and so none can make a NOT. This is why a chip's basic gate is almost always NAND or NOR.

NAND builds the other gates as follows, and each construction can be checked against its table in the same way as the worked example.

  • NOT A is NAND(A, A). With A at 0 the NAND gives 1, and with A at 1 it gives NOT 1 = 0, so tying the two inputs together turns a NAND into a NOT.
  • A AND B is the NOT of a NAND. Feeding NAND(A, B) into a second NAND with its inputs tied gives NOT (NOT (A AND B)) = A AND B, using two NAND gates.
  • A OR B is NAND(NOT A, NOT B), since by Equation 2, NOT (NOT A AND NOT B) = A OR B. This takes three NAND gates, one for each NOT and one for the final NAND.

The same reasoning works for NOR, which is why many chips are built from NAND or NOR gates and why the nand2tetris course starts from them. nand2tetris builds a full computer upwards from NAND gates, and Ben Eater's video "Making logic gates from transistors" shows the transistor version of the same gates. XOR is not universal on its own, so it is always built from other gates. Lesson 23 builds it again as the core of an adder.

Logic chips and propagation delay

The gates in a Wokwi circuit are ideal, whereas those in a real chip are not. A real gate consists of a few transistors, which lesson 12 introduced as MOSFET switches, and its output changes a short time after its inputs do, a time called the propagation delay. The 74HC00 is a common quad NAND chip with four independent 2-input NAND gates, and its datasheet describes each gate as Y = A·B in positive logic, with a function table matching the NAND column above (TI SN74HC00 datasheet, section 8.1 and Table 8-1). Its switching characteristics table in section 6.7 gives the propagation delay in nanoseconds, which grows as the supply voltage falls.

This matters for the test bench you will write. A circuit can be correct in its truth table and still show a wrong value for a few nanoseconds after an input changes, so the test bench waits before reading the output, and real hardware needs the same wait. Lesson 23 explains the glitch that can appear during that interval.

  1. Three NOT gates in a chain. A is 0, so X is 1, Y is 0 and Z is 1. Everything has settled.
  2. A rises to 1. The first gate does not answer at once: a real gate is a few transistors, and its output moves only after its propagation delay, tpd.
  3. One tpd later X falls to 0. Only now does the second gate see a change at its input.
  4. Another tpd later Y rises.
  5. And after a third tpd Z falls. Delays add along a path, so the longest path sets how soon the output is valid.
  6. A test bench, or a CPU reading a pin, that samples too early sees the old value of Z. It must wait for the longest path to settle. The datasheet's switching table gives tpd, and it grows as the supply voltage falls.

Worked example: XOR from AND, OR and NOT

The exclusive OR is 1 when the inputs differ. It is not among the basic gates normally used, so we build it from three that are, starting from an expression that is true in the right rows. XOR is 1 when at least one input is 1 and the inputs are not both 1, which in Boolean algebra is

A XOR B = (A OR B) AND NOT (A AND B)(4)

where each term corresponds to one gate. Filling in the table column by column makes every intermediate signal visible.

ABA OR BA AND BNOT (A AND B)(A OR B) AND NOT (A AND B)
000010
011011
101011
111100

The last column, 0, 1, 1, 0, is the answer, and it matches the XOR column of the first table. Each middle column is one gate in the circuit: an OR gate, an AND gate, a NOT gate on the AND output, and a final AND gate combining the OR with the NOT. The test bench in C

The test bench is the program that checks the circuit. It does the same job as a truth table, except that it runs the circuit instead of computing it on paper, and the part of main.c that drives one row is short. 

static bool check_row(bool a, bool b) {
    gpio_put(PIN_A, a);              // drive input A of the circuit (GP2)
    gpio_put(PIN_B, b);              // drive input B of the circuit (GP3)
    sleep_us(SETTLE_US);             // wait until the gates have settled
    bool out = gpio_get(PIN_OUT); // read the circuit's output (GP10)
    bool ok = (out == expected_out(a, b));
    printf("A=%d B=%d -> OUT=%d %s\n", a, b, out, ok ? "ok" : "WRONG");
    return ok;
}

gpio_put is the Pico SDK call that sets an output pin high or low, declared in the SDK header as static inline void gpio_put(uint gpio, bool value). Its second argument is a bool, so passing a sends 1 for true and 0 for false, and the next line does the same for B. The call sleep_us(SETTLE_US) is the wait: a real gate settles in nanoseconds, and the code must give the circuit time to finish before reading. The constant is 100 µs, far longer than any gate needs, so the wait is generous, as the comment in the project notes.

gpio_get returns a pin's level as a bool, here the level the circuit drives onto GP10. The next line compares it with expected_out(a, b), the function the circuit must implement, and a comparison of two bool values with == is true only when they agree. The printf prints the row, with the conditional operator choosing ok or WRONG for the last field.

Try it in Wokwi

Wokwi is a digital simulator, which makes it the right tool here, since every signal is a 0 or a 1 and the gates are ideal. The starter circuit in projects/0022-logic-gates/starter has two inputs driven by the Pico, GP2 for A and GP3 for B, an output read on GP10, and four gates. The Pico drives every combination of A and B, prints each result, compares it with exclusive OR, and prints TRUTH TABLE OK only if all four rows match.

  1. Open the starter folder in VS Code (File → Open Folder).
  2. Build with Ctrl+Shift+B, then start the simulator with F1 → Wokwi: Start Simulator.
  3. Read the serial monitor. Some rows print WRONG and the table fails. Looking at the gates, one input of the second AND gate is not connected, so its output is unreliable.
  4. Add the missing wire. The output of the NOT gate should feed input B of the second AND gate, so add this line to the connections list in diagram.json and save:
    ["not1:OUT", "and2:B", "orange", []]
  5. Still in the starter folder, open main.c, find the TODO(learner) in expected_out(), and write the exclusive OR of a and b.
  6. Rebuild, restart the simulator and watch the table. It works when the serial monitor shows TRUTH TABLE OK, after four lines that each end in ok.
Hint for the wiring

Each gate has inputs and an output. In this circuit the NOT gate's input is the first AND gate's output, and the NOT gate's output must go to the second AND gate. A floating input reads as an unknown level, so a row can be wrong even though the logic is right.

Common mistakes and how to spot them

Five mistakes come up again and again when people first build gate circuits or write the logic in C, each with a visible symptom.

An unconnected gate input

A wire missing from diagram.json leaves an input floating, so the output is wrong in some rows only, and the test bench prints WRONG on a row where the logic is right. Count the connections for every gate input in the diagram, and check each gate against its symbol in the schematic.

Bitwise NOT used on a bool

In C, bool b = true; bool n = ~b; does not make n false. The ~ operator flips the bits of an integer, the true value is promoted to the integer 1, and ~1 is −2, which converts back to bool as true. GCC warns '~' on a boolean expression, which is the symptom to look for, and the fix is !b. On a byte the two also differ: for x = 0x02, !x is 0 while ~x is 0xFD.

XOR confused with OR

The sum of 1 and 1 should be 0 with a carry, which XOR gives and OR does not, so the bug appears as a sum one too large in every row where both inputs are 1. Check the row with both inputs at 1 first, since it is the one that separates the two gates.

A missing inversion in a NAND-only circuit

A single NAND gives the inverted AND, so a circuit that needs AND but uses one NAND outputs the complement, 1 exactly when it should be 0. Count the inversions on the path from input to output.

The output read too early

The test bench in this project waits 100 µs. A bench that reads at once can see the previous row's value, so a row's OUT matches the row before even though the inputs have changed. Keep the settle delay, which the code implements with sleep_us.

Gate-level logic in real projects

Gate-level design is still used where timing and area matter most, in clock dividers, address decoders and the glue logic between a microcontroller and its peripherals. Most firmware never writes gates by hand, but every C expression is compiled into gates in the core's datapath, and the bitwise operators of lesson 20 map straight onto them. Hardware description languages such as Verilog and VHDL describe the same circuits in text, which a synthesis tool turns into gates, and reviewers of those files check the same things as in C: that every output is driven, every input is used, and the function matches its specification.

Summary

  • A logic gate computes one Boolean function of one or two input bits, and its truth table lists the output for every combination of inputs, so it is a complete specification.
  • A table of n inputs has 2n rows, and each row can be checked by testing one sentence against the wiring.
  • Boolean algebra rewrites an expression without changing its table, and De Morgan's laws turn a NOT over an AND into an OR of the negations, and the reverse.
  • NAND and NOR are universal: NOT is a NAND with its inputs tied, and AND and OR follow from two or three NAND gates.
  • XOR is 1 when the inputs differ, and (A OR B) AND NOT (A AND B) is one way to build it.
  • Real gates have a propagation delay, so a test bench must wait before reading the output.
  • In C, use ! for a logical NOT of a bool, because the bitwise ~ gives the wrong answer on a bool.
