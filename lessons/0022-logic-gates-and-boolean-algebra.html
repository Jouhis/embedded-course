Logic gates and Boolean algebra

Every adder, comparator and address decoder in your MCU is built from a few gates. You will build an exclusive-OR from AND, OR and NOT, and check it against its truth table, with the Pico as the test bench.

By the end of this lesson you can write the truth table of a gate circuit, rewrite an expression with De Morgan's laws, and wire a gate circuit in Wokwi so that the Pico's test bench prints TRUTH TABLE OK.

Where we are and why it matters

Lesson 16 taught you that a digital pin is a voltage that reads as high or low, and lesson 17 taught you to read a schematic, including the symbols that stand for parts. Lessons 19 to 21 gave you the bit patterns and the bitwise operators of C. A logic gate is the hardware that does one of those bitwise operations on one bit. The C operator & you used in lesson 20 is, inside the chip, a row of AND gates, one for each bit position.

A bus address comes out of the core as 32 bits, and a peripheral must know whether the address is its own. A timer must know whether an overflow and an enable are both set. A safety circuit must know whether any of four sensors is tripped. Each of these answers is a gate circuit, and an engineer who writes or reviews the logic must be able to predict its output for every input. That prediction is the truth table, and the skill of this lesson is to build one and check it.

A gate is a function of its inputs

A logic gate takes one or two input bits and gives one output bit. The output depends only on the current inputs, with no memory of what came before. That property is called combinational logic, and lesson 24 is the first place in this course where memory appears.

A truth table lists the output for every combination of inputs. With one input there are two rows, with two inputs there are four, and with n inputs there are 2n rows. A three-input gate therefore has 8 rows, not 6, because each input doubles the count. A truth table is a complete specification: if two circuits have the same table, they compute the same function, however different their wiring looks.

ABANDORXORNAND
000001
010111
100111
111100

Read the table by columns. AND is 1 only in its last row, where both inputs are 1. OR is 1 in three rows, and is 0 only when both inputs are 0. XOR, the exclusive OR, is 1 when the inputs differ. NAND is NOT AND, so it is the AND column with every output flipped. NOT has one input: it turns 0 into 1 and 1 into 0. NOR is NOT OR, and XNOR is NOT XOR. The bubble on a gate symbol means "invert the output", which is why a NAND symbol is an AND symbol with a small circle at its output. Lesson 17 showed that a schematic symbol specifies the function. The bubble is the only difference between an AND symbol and a NAND symbol, so read it carefully.

Worked example: read a row of the table as a logic statement

Take the XOR row where A is 1 and B is 0. Write it as a sentence: "the output is 1 when A is 1 and B is 0, because the inputs differ". Now do the same for AND: "the output is 0, because not both inputs are 1". Each row is one true statement about the gate. If you can say the four rows of a table in plain English, you have understood the gate, and you can check any circuit by testing each sentence against the wiring.

Boolean algebra: the same function written two ways

Boolean algebra is the notation for gate circuits. Write AND as a dot or as juxtaposition, so A AND B is A·B or AB. Write OR as a plus, so A OR B is A + B. Write NOT as an overbar, so NOT A is Ā. The algebra works on the values 0 and 1 only, and it has rules you can check by truth table. Some of the most useful are these identities: A · 1 = A, A + 0 = A, A · 0 = 0, A + 1 = 1, A · Ā = 0, and A + Ā = 1.

The rules that matter most in practice are the commutative, associative and distributive laws, which are the same as in ordinary algebra. A·(B + C) = A·B + A·C holds for Boolean values, and you can check it by testing the eight rows of its three variables. Checking by truth table is always possible, because there are only finitely many rows. That is why Boolean algebra is safe to use for hardware: every identity can be verified exhaustively.

Worked example: De Morgan's laws, row by row

The most useful identities for gate design are De Morgan's laws:

NOT (A AND B) = (NOT A) OR (NOT B)
NOT (A OR B) = (NOT A) AND (NOT B)

To prove the first law, build a table with a column for each side and compare the last two columns.

  1. Row A = 0, B = 0: NOT (A AND B) = NOT 0 = 1. (NOT A) OR (NOT B) = 1 OR 1 = 1. The two sides agree.
  2. Row A = 0, B = 1: NOT (0 AND 1) = NOT 0 = 1. (NOT 0) OR (NOT 1) = 1 OR 0 = 1. They agree.
  3. Row A = 1, B = 0: NOT (1 AND 0) = 1. (NOT 1) OR (NOT 0) = 0 OR 1 = 1. They agree.
  4. Row A = 1, B = 1: NOT (1 AND 1) = NOT 1 = 0. (NOT 1) OR (NOT 1) = 0 OR 0 = 0. They agree.

All four rows agree, so the two expressions are the same function. The second law is proved the same way. The practical use is that a NOT placed in front of an AND can be moved inside, and the AND becomes an OR. A chip designer who has a function in one form can rewrite it in the form that is cheapest to build from the gates the process offers.

NAND alone can build everything

A universal gate is a gate from which every other logic function can be built alone. NAND is universal, and so is NOR. AND is not, because you cannot make a NOT from ANDs alone: no combination of AND gates can turn a 1 into a 0. That is why the basic gate of a chip is almost always NAND or NOR.

Here is how NAND builds the other gates. Each construction is checked by the table in the same way as the worked example above.

  • NOT A is NAND(A, A). When A is 0 the NAND gives 1, and when A is 1 it gives NOT 1 = 0. Tying the two inputs together turns NAND into NOT.
  • A AND B is NOT of NAND. Feed NAND(A, B) into another NAND with both inputs tied together, so the output is NOT (NOT (A AND B)) = A AND B. That is two NAND gates.
  • A OR B is NAND(NOT A, NOT B). By De Morgan's law, NOT (NOT A AND NOT B) = A OR B. That is three NAND gates in all: one for each NOT, and one for the final NAND.

The same reasoning works for NOR. This is why many chips are built from NAND or NOR gates, and why the nand2tetris course starts there. nand2tetris builds a full computer from NAND gates upwards, and Ben Eater's video "Making logic gates from transistors" shows the transistor version of the same gates. XOR is not universal on its own, so it is always built from other gates. Lesson 23 builds it again, as the core of an adder.

Real gates are chips, and they take time

The gates in your Wokwi circuit are ideal, and the gates in a real chip are not. A real gate is a few transistors (lesson 12 introduced MOSFETs as switches), and its output changes a short time after its inputs do. That time is the propagation delay. The 74HC00 is a common quad NAND chip, with four independent 2-input NAND gates, and its datasheet describes each gate as Y = A·B in positive logic. Its function table gives the same results as the NAND column above (TI SN74HC00 datasheet, section 8.1 and Table 8-1). The switching characteristics table in section 6.7 gives the propagation delay in nanoseconds, and it grows as the supply voltage falls.

This matters for the test bench you will write. A circuit can be right in its truth table and still show a wrong value for a few nanoseconds after an input changes. The test bench waits before it reads the output, and the same wait is needed on real hardware. Lesson 23 explains the glitch that can appear during that time.

Worked example: build XOR from AND, OR and NOT

The exclusive OR is 1 when the inputs differ. It is not in the basic set of gates you would normally use, so build it from three that are. Start from the expression that is true in the right rows: XOR is 1 when at least one input is 1 and not both are 1. In Boolean algebra that is A XOR B = (A OR B) AND NOT (A AND B). Now fill the table column by column, so that each intermediate signal is visible.

ABA OR BA AND BNOT (A AND B)(A OR B) AND NOT (A AND B)
000010
011011
101011
111100

The last column is the answer. It is 0, 1, 1, 0, which is the XOR column of the table in the first section. Each gate in the circuit is one of the middle columns: an OR gate, an AND gate, a NOT gate on the AND output, and a final AND gate that takes the OR and the NOT. Try it in Wokwi

Wokwi is a digital simulator, so it is the right tool here: every signal is a 0 or a 1, and the gates are ideal. The starter circuit in projects/0022-logic-gates/starter has two inputs driven by the Pico (GP2 for A, GP3 for B), an output read on GP10, and four gates. The Pico drives every combination of A and B, and prints each result. It compares the result with exclusive OR, and prints TRUTH TABLE OK only if all four rows match.

Reading the test bench

The test bench is the program that checks the circuit. Its job is the same as a truth table, but it runs the circuit instead of computing it on paper. The part of main.c that drives one row is short. 

static bool check_row(bool a, bool b) {
    gpio_put(PIN_A, a);              // drive input A of the circuit (GP2)
    gpio_put(PIN_B, b);              // drive input B of the circuit (GP3)
    sleep_us(SETTLE_US);             // wait until the gates have settled
    bool out = gpio_get(PIN_OUT); // read the circuit's output (GP10)
    bool ok = (out == expected_out(a, b));
    printf("A=%d B=%d -> OUT=%d %s\n", a, b, out, ok ? "ok" : "WRONG");
    return ok;
}

gpio_put is the Pico SDK call that sets an output pin high or low. Its second argument is a bool, so passing a sends 1 for true and 0 for false. The SDK header declares it as static inline void gpio_put(uint gpio, bool value). The next line does the same for B. The call sleep_us(SETTLE_US) is the wait. A real gate takes nanoseconds to settle, and the code must give the circuit time to finish before it reads. The constant is 100 µs, far longer than any gate needs, so the wait is generous, and the comment in the project says so.

gpio_get returns the level of a pin as a bool, which is the level the circuit drives onto GP10. The next line compares it with expected_out(a, b), the function the circuit must implement. The comparison of two bool values with == is true only when they agree. The printf prints the row, and the conditional operator chooses ok or WRONG for the last field.

Common mistakes and how to spot them

Five mistakes come up again and again when people first build gate circuits or write the logic in C. Each one has a symptom you can see.

  1. An unconnected gate input. A wire missing from diagram.json leaves an input floating, and the output is wrong for some rows only. The symptom is the test bench printing WRONG on a row where the logic is right. The fix is to count the connections for every gate input in the diagram, and to check each gate against its symbol in the schematic.
  2. Using ~ for a logical NOT on a bool. In C, bool b = true; bool n = ~b; does not make n false. The ~ operator flips the bits of an integer, the true value is promoted to the integer 1, and ~1 is −2. Converting −2 to bool gives true. GCC warns '~' on a boolean expression, which is the symptom to look for. The fix is !b. On a byte, !x and ~x also differ: for x = 0x02, !x is 0 and ~x is 0xFD.
  3. XOR confused with OR. The sum of 1 and 1 should be 0 with a carry, and XOR gives that. OR gives 1, and the bug shows up as a sum that is one too large in every row where both inputs are 1. The fix is to check the row where both inputs are 1 first, because it is the one that separates the two gates.
  4. Forgetting the inversion in a NAND-only circuit. A single NAND gives the inverted AND. If the circuit needs AND and you use one NAND, the output is the complement, and the symptom is an output that is 1 exactly when it should be 0. The fix is to count the inversions on the path from input to output.
  5. Reading the output too early. The test bench in this project waits 100 µs. A bench that reads the output at once can see the old value of the last row, and the symptom is a row whose OUT matches the previous row's OUT, even though the inputs have changed. The fix is the settle delay, which the code shows as sleep_us.

In real projects

Gate-level design is still used in the places where timing and area matter most, such as clock dividers, address decoders and the glue logic between a microcontroller and its peripherals. Most firmware never writes gates by hand, but every C expression you write is compiled to gates in the core's datapath, and the bitwise operators of lesson 20 map straight onto them. Hardware description languages such as Verilog and VHDL describe the same circuits in text, and a synthesis tool turns the text into gates. Reviewers of those files check the same things as in C: that every output is driven, that every input is used, and that the function matches its specification.

Summary

  • A logic gate computes one Boolean function of one or two input bits. Its truth table lists the output for every combination of inputs, so it is a complete specification.
  • A table of n inputs has 2n rows. Each row can be checked by testing one sentence against the wiring.
  • Boolean algebra rewrites an expression without changing its table. De Morgan's laws turn NOT over AND into OR of the negations, and the reverse.
  • NAND and NOR are universal. NOT is NAND with its inputs tied, and AND and OR follow from two or three NAND gates.
  • XOR is 1 when the inputs differ, and (A OR B) AND NOT (A AND B) is one way to build it.
  • Real gates have a propagation delay, so a test bench must wait before it reads the output.
  • In C, use ! for a logical NOT of a bool. The ~ operator is bitwise, and on a bool it gives the wrong answer.
