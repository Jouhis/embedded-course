Fetch, decode, execute

Every instruction goes through the same three phases. If you can predict the program counter and the registers after each phase, you can follow any Cortex-M program in a debugger.

By the end of this lesson you can predict the program counter and a destination register after each phase of a simple instruction, then check your prediction in the CPU simulator.

The idea

The CPU runs one instruction at a time, in a loop. In the fetch phase it reads the instruction at the address in the program counter (PC) into the instruction register. In the decode phase it works out what the bits mean: the operation, the source registers and the destination register. In the execute phase it does the operation, writes the result, updates the flags and moves the PC on, or changes it for a branch. These are the logical phases. A real pipeline runs them overlapped, so while one instruction executes the next is already being decoded. Lesson 30 covers that.

Arm's TRM names the same three stages for the Cortex-M3: "the Fetch stage, the Decode stage, the Execute stage" (Arm Cortex-M3 TRM DDI0337G, §1.3). The same manual has a separate section on the prefetch unit (§1.4), which is where the real core's fetch behaviour is described.

What the simulator does

The simulator in this lesson is a teaching model, not a Cortex-M. It has four differences you need to know. First, it updates the PC during the execute phase, so the PC stays on the current instruction while it is fetched and decoded. Second, every instruction is 2 bytes, which is the Thumb size, but the instruction set is a small subset. Third, the memory map is a toy: code at 0x0, 64 words of RAM at 0x20000000 and a GPIO register at 0x40000000. Fourth, MOV accepts any 32-bit constant, which a real 16-bit MOVS cannot encode (lesson 29 shows its 8-bit immediate).

The Step button runs one phase. The Instruction button runs all three phases of one instruction. The EXECUTE phase is where a register changes.

Try it in the CPU simulator

The program sets R0 to 2, adds 3, and writes the result to the LEDs. Press Reset, then predict before each press. The phase row shows which of the three phases is running.

  1. From reset, press Step once. Predict the PC. Then press Step twice more and predict R0 after the third press.
  2. Press Instruction to reach the ADD. Predict R0 after the ADD finishes.
  3. Press Instruction twice more. Count the LEDs that are lit after the STR.
Hint

The PC only changes in the execute phase, so it reads 0 after the first Step. A register only changes in the execute phase too: the value appears on the third press of a Step cycle, not the first.

Then compare the simulator with a real Cortex-M. Its PC bookkeeping differs from the simulator's, because the real core fetches ahead. Read the TRM's prefetch section (§1.4) before you trust a PC value from a debugger on the hardware. Lesson 32 shows real PC values in a disassembly.

"Walk me through what the CPU does for one instruction, and where a register actually changes." Answer out loud in 60 seconds, then compare.

Model answer

The CPU fetches the instruction at the PC, decodes its fields, then executes it. The register is written during execute, along with the flags, and the PC moves to the next instruction or to a branch target. On a real pipelined core the three phases overlap, so the register write of one instruction happens while the next one is being decoded.

Arm Cortex-M3 TRM DDI0337G: §1.3 (the three pipeline stages) and §1.4 (the prefetch unit). Read them to see where the simulator simplifies the real core.
