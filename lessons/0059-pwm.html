PWM: dimming, servos, tones

A pin cannot output 1.6 V, but it can switch fast enough that the average looks like 1.6 V. PWM does that with a counter, a wrap value and a compare. The same three numbers give you a dimmed LED, a 50 Hz servo signal and a buzzer tone.

By the end of this lesson you can compute the PWM frequency and duty cycle of an RP2040 slice from the system clock, the clock divider and the wrap value, and set up a dimmed LED, a 50 Hz servo signal and a 440 Hz tone with the Pico SDK.

The idea

A PWM slice is a 16-bit counter that counts from 0 up to a wrap value TOP and then starts again. An output goes high while the counter is below a compare value and low after that. The fraction of each period spent high is the duty cycle RP2040 datasheet, section 4.5.2.1. The duty cycle is the fraction of time high, and the average voltage of a filtered PWM signal is that fraction times the supply. That is why a dimmed LED looks dim, and why a motor speed control works.

The RP2040 has eight slices. Each slice has two outputs, A and B, so there are 16 PWM channels. They map to GPIO pins in order: GP0 is slice 0 A, GP1 is slice 0 B, and the mapping repeats from GP16 RP2040 datasheet, Table 515. Two outputs in the same slice share one counter, so they share one period. Two outputs on different slices can have different periods.

The three numbers

The clock divider DIV slows the counter. It is an 8-bit integer with a 4-bit fraction, so it can divide by 1.0 to 255.9375 RP2040 datasheet, section 4.5.2.4. With TOP and DIV, the period in clock cycles is (TOP + 1) × DIV, and the frequency follows from the system clock RP2040 datasheet, section 4.5.2.6. The Pico SDK's header states the same rule: the counter runs at clk_sys ÷ DIV pico-sdk, hardware/pwm.h. 

/* frequency = clk_sys / (DIV * (TOP + 1)) */
/* duty cycle = compare / (TOP + 1)        */
/* example: 125 MHz, DIV 125, TOP 19999 gives 125e6 / (125 * 20000) = 50 Hz */
Read the system clock with clock_get_hz(clk_sys) instead of assuming 125 MHz. The code in this lesson does that.

Dimming, a servo, and a tone

Dimming. Choose a frequency high enough that the eye does not see flicker, such as 1 kHz. Then set the compare to a fraction of TOP + 1 with the potentiometer.

Servo. A hobby servo expects a 20 ms frame, that is 50 Hz, and reads the pulse width. A 1 ms pulse is the 0-degree end, and 2 ms is the 180-degree end Wokwi, servo part. With a 1 MHz tick, one count is 1 µs, so the compare is the pulse width in microseconds, and TOP is 19,999 for a 20,000-tick frame.

Tone. A buzzer makes a tone at the PWM frequency, and a 50 % duty cycle gives a clean square wave. Wokwi's buzzer part is driven by the pin's signal Wokwi, buzzer part. For 440 Hz, a DIV of 8 keeps TOP inside 16 bits: 125 MHz ÷ (8 × 440) − 1 = 35,510.

Try it in Wokwi

The project projects/0059-pwm has a potentiometer on GP26, an LED on GP18 (slice 1, A), a servo on GP16 (slice 0, A) and a buzzer on GP22 (slice 3, A). The three outputs use three slices, because each slice has only one period. The solution sets the LED to 1 kHz, the servo to 50 Hz and the buzzer to 440 Hz.

  1. Open projects/0059-pwm/starter in VS Code (File → Open Folder).
  2. Build with Ctrl+Shift+B, then start the simulator with F1 → Wokwi: Start Simulator.
  3. Your task: check the LED's TOP and explain it in a comment. Fix the servo's TOP (the starter has a planted 2 ms period, which gives 500 Hz). Compute the buzzer's TOP from sys_hz and set its level to half of TOP + 1. Set the LED and servo levels from the potentiometer reading. You will know it works when the servo arm moves with the pot, the LED dims, and the serial monitor prints PWM OK.
Hint for the servo

The servo wants 20,000 ticks per frame at 1 µs each. Count the ticks in one frame, and the TOP is that count minus one.

Hint for the levels

The level is a count of ticks, not a percentage. For the servo that is microseconds, from 1000 to 2000. For the LED it is a fraction of TOP + 1.

"You have a 16-bit PWM counter and a 125 MHz clock. How do you make a 50 Hz signal, and what limits the duty cycle resolution?" Answer out loud in 60 seconds, then compare.

Model answer

Pick a divider so the counter ticks at a convenient rate, for example 1 MHz with DIV 125. Then set TOP to 19,999, which gives 20,000 ticks, or 50 Hz. The duty resolution is the number of levels between 0 and TOP + 1, so at TOP 19,999 you have 20,000 steps, and a wider TOP gives finer control at a lower frequency. A higher frequency needs a smaller TOP, which means fewer steps.

RP2040 datasheet, section 4.5 (PWM): read 4.5.2.1 for the duty cycle, 4.5.2.4 for the clock divider, 4.5.2.6 for the period, and Table 515 for the pin map. The period equation in 4.5.2.6 is an image in the PDF, so check it against the SDK's pwm.h.
