Bus architecture: AHB, APB, and the bus matrix

Every register write you make travels over a bus. Knowing which bus, and what it costs, explains why two accesses can finish in the same cycle or one can wait.

By the end of this lesson you can trace one register write from the core to a peripheral on an RP2040 or an STM32F103, name the bus it crosses, and say which accesses can run in parallel.

The idea

A bus is a set of wires and a protocol that carries an address, data and a control signal from one device to another. The device that starts a transfer is the master: the core, or a DMA controller. The device that answers is the slave: memory, or a peripheral register block. Your architecture course will know the shared-bus problem: one bus means one transfer at a time. A bus matrix (also called a crossbar) removes most of that limit. Each master has a path to each slave, so transfers to different slaves can run at the same time. Two masters that want the same slave still have to take turns.

RP2040: a crossbar with ten ports

The RP2040 bus fabric connects four bus masters (core 0, core 1, and the read and write ports of the DMA) to ten downstream ports: ROM, XIP flash, SRAM 0 to 5, a shared port for the fast AHB-Lite peripherals, and a bridge to all the APB peripherals. The four masters can reach four different ports in the same cycle, and the fabric adds no wait states to an AHB-Lite access. At a 125 MHz system clock the datasheet gives a sustained bandwidth of 2.0 GBps. RP2040 datasheet, section 2.1 (Bus Fabric) and 2.1.1 (AHB-Lite Crossbar).

The SRAM is split so that parallel accesses rarely collide. The first 256 kB is word-striped across four 64 kB banks, and two 4 kB banks sit above it. That is six banks in all, not four. RP2040 datasheet, section 2.6.2 (SRAM) and Table 153.

The fabric also gives every peripheral register block three more addresses, for atomic updates. The address offset +0x1000 XORs the bits you write, +0x2000 sets them, and +0x3000 clears them. A set or clear is then a single bus write that the hardware applies, so an interrupt cannot land between a read and a write-back. RP2040 datasheet, section 2.1.2 (Atomic Register Access).

The APB bridge costs cycles

The fast AHB-Lite side has zero wait states. The slow peripherals sit behind the APB bridge, which registers the request and the response. The datasheet gives the cost: an APB access takes at least two cycles, a read adds one more, and a write adds two more. RP2040 datasheet, section 2.1.3 (APB Bridge). This is the cost of a shared, lower-speed peripheral bus: the bridge is simpler and smaller than a full crossbar port, and the peripherals need far less bandwidth than memory.

STM32F103: AHB, APB1, and APB2

The STM32F1 uses the same idea with different names. The ST device header defines three peripheral bus regions from the peripheral base 0x40000000: APB1 at 0x40000000, APB2 at 0x40010000, and AHB at 0x40020000. The header then places the blocks you will use: GPIOC_BASE is APB2PERIPH_BASE + 0x1000, which is 0x40011000, and RCC_BASE is AHBPERIPH_BASE + 0x1000, which is 0x40021000. So GPIOC is on APB2 and the clock controller RCC is on AHB. third_party/cmsis-device-f1/Include/stm32f103xb.h.

Before a peripheral can be used, its clock must be enabled in RCC. The template does this as its first step: RCC->APB2ENR |= RCC_APB2ENR_IOPCEN; sets bit 4, which enables GPIOC. The RCC block is on the AHB side, so the clock enable is a write to one bus and the GPIO register write is a write to another.

The bus matrix and bridge details for the STM32F1 are in the bus architecture chapter of RM0008, with the bus figure. This course has not yet checked the exact figure against the vendor text, so use the header addresses above, and read RM0008 for the matrix itself.
You can name the bus behind any address in the RP2040 or STM32 memory map, and you can explain why a write through the APB bridge is slower than a write to SRAM.

Hint

The bus region is the address with the offset removed. GPIOC base is 0x40011000, which is in the APB2 region that starts at 0x40010000. Bit 4 is value 0x10.

"Why do peripherals usually sit on a slower bus than SRAM, and what does the bridge cost you?" Answer out loud in 60 seconds, then compare.

Model answer

Memory needs bandwidth, so it gets wide, zero-wait paths on a crossbar with its own ports. Peripherals need little bandwidth and their register blocks are simple, so a shared, lower-speed bus with a bridge is much cheaper in silicon and power. The bridge costs cycles: on the RP2040 an APB write takes at least two cycles more than an AHB write, and a register poll or a write-heavy loop feels that cost.
