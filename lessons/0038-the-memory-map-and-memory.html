The memory map and memory-mapped registers

A peripheral register is just an address. Once you can compute that address from a base and an offset, the struct syntax in the vendor header stops being magic.

By the end of this lesson you can compute the address of a peripheral register from its base address and offset, write it through a pointer, and check that the raw write and the struct access land on the same address.

The idea

The core sees one flat 32-bit address space. Each region of that space is assigned to something: flash, SRAM, or a peripheral. The assignment is the memory map. The core reaches a peripheral with an ordinary load or store to an address inside its region. A register inside a peripheral that is reached this way is a memory-mapped register. This is why the architecture course's "load and store" model covers peripherals too. A write to GPIO is a store instruction, and the bus delivers it to the GPIO block instead of to RAM.

A peripheral has a base address, the start of its block, and each register sits at a fixed offset from that base. So the register's address is base + offset. The header files and the reference manual both give you the base and the offset, and the struct in the header is only a convenient way to write the same arithmetic.

The RP2040 map, in brief

RegionAddressWhat is there
ROM0x0000000016 kB bootrom

That table is the datasheet's summary: RP2040 datasheet, Table 15 in section 2.2.1, with the detail in 2.2.2. Within the APB region the blocks are 16 kB apart. For example, the clocks block base is 0x40008000 (section 2.15.7), the GPIO bank IO base is 0x40014000 (section 2.19.6.1), and the GPIO pad control base is 0x4001C000 (section 2.19.6.3).

The SIO block is special. It is the single-cycle IO block attached to the cores' IO ports, not an APB peripheral. Its registers start at 0xD0000000. Its GPIO registers are at fixed offsets: GPIO_OUT at 0x010, GPIO_OUT_SET at 0x014, GPIO_OUT_CLR at 0x018 and GPIO_OUT_XOR at 0x01C. RP2040 datasheet, section 2.3.1.7 (SIO list of registers).

The STM32F103 map, from the header

The ST device header defines the regions. The flash starts at FLASH_BASE = 0x08000000, SRAM at SRAM_BASE = 0x20000000, and the peripheral region at PERIPH_BASE = 0x40000000. APB2 is PERIPH_BASE + 0x10000, GPIOC is APB2PERIPH_BASE + 0x1000 and the RCC is AHBPERIPH_BASE + 0x1000. All of these come from third_party/cmsis-device-f1/Include/stm32f103xb.h.

Writing the address yourself

The C form of a register is a pointer to volatile. volatile tells the compiler that each access must really happen, because the hardware can change the value at any time, and that the access must not be merged or removed. Lesson 46 covers why this matters. 

/* GPIOC base 0x40011000 + BSRR offset 0x10 */
#define GPIOC_BSRR_ADDR  (0x40011000UL + 0x10UL)

/* A write through this pointer is a store to 0x40011010. */
volatile uint32_t *bsrr = (volatile uint32_t *)GPIOC_BSRR_ADDR;
*bsrr = GPIO_BSRR_BR13;     /* bit 29: reset PC13, the LED on the Blue Pill */
A write to BSRR sets or resets only the bits you name, and bits written as 0 leave their pins alone. That is why it is safer than reading the output register, changing one bit and writing it back, which can race an interrupt. The template uses BSRR for this reason. The bit meanings are in the GPIO section of RM0008.

"What is a memory-mapped register, and what does the compiler emit when you write a value to a GPIO's BSRR field?" Answer out loud in 60 seconds, then compare.

Model answer

A memory-mapped register is a peripheral control register that sits at a fixed address in the memory map, so the core reaches it with ordinary loads and stores. The compiler computes base plus offset, loads that address into a register, and emits a single store, such as str, to it. The bus delivers the store to the GPIO block, which decodes the offset and acts on it. The pointer must be volatile, so the store is not optimised away.

RP2040 datasheet: read section 2.2 (Address Map) and its Table 15, then the register list at section 2.3.1.7 for the SIO offsets. The base and offset arithmetic is the same on the STM32, where the header plays the role of the list.
