FreeRTOS setup, tasks and scheduling

A FreeRTOS program is a set of tasks, each with a priority, and a kernel that runs the most urgent ready task. On the Blue Pill that means one tick interrupt, one scheduler and a few lines of configuration.

By the end of this lesson you can create two or more tasks with xTaskCreate(), choose their priorities, write a periodic task with vTaskDelayUntil(), and explain the difference from vTaskDelay(), the idle task and the tick.

The idea

A task is an infinite loop with its own stack. The kernel keeps a ready list of tasks that could run now, and at every decision point it picks the ready task with the highest priority. That selection is the scheduler. FreeRTOS keeps the code for it in tasks.c. The macro that picks the task, taskSELECT_HIGHEST_PRIORITY_TASK(), is at tasks.c line 235 in the kernel version this course uses, V11.2.0 (set in include/task.h line 56).

Three things drive the scheduler. A task that waits (for a delay, a queue or a semaphore) moves out of the ready list. The tick is a periodic interrupt, here 1 kHz from SysTick, that checks whether a waiting task's time has come. And a task that becomes ready with a higher priority than the running task causes a switch at once: this is preemption, and the switch itself is lesson 88. Preemption is set by configUSE_PREEMPTION. With it at 1, a higher-priority task interrupts a lower one. With it at 0, tasks switch only when they block or yield.

Creating tasks

xTaskCreate() takes a function, a name, a stack depth in words, an argument, a priority and an optional handle. It allocates the stack and the task control block from the FreeRTOS heap, and makes the task ready. The kernel book describes the parameters; the function is defined at tasks.c line 1740. 

static void blink_task(void *arg) {
    (void)arg;
    TickType_t last_wake = xTaskGetTickCount();
    for (;;) {
        GPIOC->ODR ^= GPIO_ODR_ODR13;
        vTaskDelayUntil(&last_wake, pdMS_TO_TICKS(500));   /* a fixed 500 ms period */
    }
}

/* in main(), before vTaskStartScheduler(): */
xTaskCreate(blink_task, "blink", 128, NULL, 2, NULL);   /* 128 words, priority 2 */

The stack depth is in words because the stack is a StackType_t array, and on a Cortex-M3 that type is 32 bits. A depth of 128 is 512 bytes. Lesson 91 shows how to size it.

Priority numbers grow upward: 0 is the lowest (the idle task), and configMAX_PRIORITIES − 1 is the highest. Many bugs come from reading "priority 1" as the most urgent, which is the opposite of the NVIC rule in lesson 72, where a lower number is more urgent.

Two delays: relative and absolute

vTaskDelay(n) blocks the task for n ticks from the moment it is called. If the work before it takes time, the period grows by that time, and it drifts. vTaskDelayUntil(&last, n) keeps an absolute schedule: the next wake-up is last + n, so the period holds even when the work takes time. The FreeRTOS API reference documents vTaskDelay() on its own page (freertos.org, vTaskDelay).

CallWake-up timeUse it for
vTaskDelay(n)now + n ticksWaiting a while, where a drift is acceptable
vTaskDelayUntil(&last, n)last + n ticks; last is updatedA periodic job, such as a sensor every 200 ms

The idle task and the tick

When no task is ready, the kernel runs the idle task. The kernel creates it inside vTaskStartScheduler(), at priority 0 (tasks.c near line 3654), so the CPU always has something to run. The idle task frees memory from deleted tasks, and it is the place to put a low-power WFI if you want one. You never write it.

The tick is the heartbeat. SysTick fires 1000 times a second (configTICK_RATE_HZ 1000 in the template's FreeRTOSConfig.h), and the handler calls xTaskIncrementTick() (tasks.c line 4725). That function moves tasks whose delay has ended back to the ready list. If one of them has a higher priority, the handler asks for a switch through PendSV (lesson 88). Tick resolution therefore limits delays: a 1 ms tick cannot give a 0.5 ms delay.

With configUSE_TIME_SLICING set to 1 (the default), tasks of equal priority take turns at each tick. Tasks of different priority never share the CPU this way: the higher one always wins.

"What is the difference between vTaskDelay and vTaskDelayUntil, and when would you use each?" Answer out loud in 60 seconds, then compare.

Model answer

vTaskDelay blocks for a number of ticks counted from the call, so the period drifts by the time the work takes. vTaskDelayUntil keeps the wake-up times on an absolute schedule by adding the period to the last wake-up time. Use vTaskDelayUntil for a periodic job that must keep its rate, such as a sensor read every 200 ms. Use vTaskDelay to wait for a while where the drift does not matter, such as a debounce or a status line once a second. Mention that both block the task and put it on the blocked list, so the CPU is free for lower-priority work.
