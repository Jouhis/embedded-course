Sequential logic

Gates alone cannot remember anything. A latch adds memory, a flip-flop adds a clock so that all the memory changes at the same moment, and every register in your MCU is a row of flip-flops.

By the end of this lesson you can explain why a clock exists, tell a latch from a flip-flop by when each one copies its input, and explain setup and hold time, then wire a D flip-flop so that the Pico's test bench prints D FLIP-FLOP OK.

The idea

A sequential circuit has state: its outputs depend on its inputs and on what it stored before. Lesson 23's circuits had no state. The simplest state is one bit, held by feedback. Two NAND gates with their outputs cross-connected form an SR latch. Its output holds when both inputs are inactive, and changes when one input is pulsed. Ben Eater's video "SR latch" builds this on breadboard, and Harris and Harris, chapter 3 (Sequential Logic Design) gives the timing rules.

Latch and flip-flop: when does the copy happen?

A D latch has a data input D and an enable input. While enable is high, Q follows D. When enable goes low, Q holds the last value. Because Q follows D for the whole time the enable is high, the latch is level-sensitive: a glitch on D during that window reaches Q.

A D flip-flop copies D to Q only at one instant, the rising edge of the clock. Between edges it holds, whatever D does. Inside, it is two latches in series, one transparent while the clock is low and the other while it is high. That arrangement makes the copy happen on one edge only. Ben Eater's video "D flip-flop" builds the same structure from logic chips.

Why a clock exists

A circuit with many paths of different lengths settles at different times, so its outputs can show wrong intermediate values for a while. If every state element copies its input at the same, known instant, the designer only has to check that everything settles between two clock edges. That is a synchronous design, and nearly every digital system you will meet uses one. The clock is a periodic signal. Its period is the time between two rising edges. The frequency is the inverse of the period: a 1 MHz clock has a period of 1 µs.

Setup and hold: the timing rules

A flip-flop needs its input to be stable for a short time around the clock edge. Setup time is the time D must be stable before the edge. Hold time is the time D must stay stable after the edge. If D changes inside that window, the flip-flop can settle to the wrong value, or enter a metastable state for a while before it settles. Datasheets give these times for every flip-flop, and the timing diagrams in lesson 18 show them. Setup and hold are a concept in this lesson. The Pico test bench is slow enough (hundreds of microseconds per edge) that you will never violate them, so the test cannot show a violation. Real firmware reads the datasheet, and lesson 18 teaches that.

A flip-flop with a setup or hold violation does not necessarily fail loudly. It may take the right value most of the time, and the wrong one once in a million edges. That is why a clock-domain crossing is a real design problem, and why a simulator that is too fast can hide it.

Try it in Wokwi

The project in projects/0024-d-flip-flop drives D from GP2 and CLK from GP3, and reads Q on GP10. The test first clocks a 0 into the flip-flop, so its starting state does not matter. Then, for five values of D, it changes D while the clock is low and checks that Q does not change, then makes one rising edge and checks that Q now equals D.

  1. Open the starter folder, build with Ctrl+Shift+B, and start the simulator with F1 → Wokwi: Start Simulator.
  2. Read the serial monitor. The first line, the load step, already fails. Q never changes, because the clock never reaches the flip-flop.
  3. Find the missing wire. The clock input of the flip-flop, CLK, must connect to GP3. Add this line to the connections list in diagram.json, then save:
    ["pico:GP3", "ff1:CLK", "blue", []]
  4. In main.c, write the body of pulse_clock(). It must make a rising edge: drive CLK low, then high (this is the edge), then low again, with sleep_us() between the steps. The comments say which is which.
  5. Restart the simulator. You will know it works when the serial monitor prints D FLIP-FLOP OK.
Hint for the edge

The copy happens when CLK goes from 0 to 1. Setting CLK to 1 and then leaving it at 1 is not enough: the next pulse needs a 0 first, so the flip-flop sees a new rising edge. The starter's pulse_clock() ends with CLK at 0 for that reason.

The reference solution is in projects/0024-d-flip-flop/solution. Try first, compare after. The test prints one line per step, so you can see which step fails.

The flip-flop's pins are named D, CLK and Q in this project. Check the pin names on the Wokwi part's documentation page when you edit the connections.

"What is the difference between a latch and a flip-flop, and why do synchronous designs use flip-flops?" Answer out loud in 60 seconds, then compare.

Model answer

A latch is level-sensitive: it follows its input for as long as its enable is high. A flip-flop is edge-triggered: it copies its input only at one clock edge and holds otherwise. Synchronous designs use flip-flops so that all state changes happen at known instants, and the designer can check that logic settles between edges. The setup and hold times around the edge are the timing rules that must hold for the copy to be reliable.
