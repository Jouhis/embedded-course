Bit fields, unions, packing, and endianness

A sensor sends bytes, and a register holds bits. C offers bit-fields, unions and packed structs for both, but the standard leaves much of their layout to the compiler. Shifts and masks are the portable way.

By the end of this lesson you can parse a big-endian 16-bit value from a byte buffer with shifts, explain why a bit-field is not a portable register layout, and say what __attribute__((packed)) does and does not change.

The idea

A bit-field is a struct member with a width in bits: unsigned mode : 2;. It looks like a register map, and it is tempting for hardware work. The C standard does not fix its layout. The order of bit-fields within a storage unit, whether a bit-field can straddle a unit boundary, and whether a plain int bit-field is signed are all implementation-defined or unspecified. cppreference, bit-field layout The same code can give different bit positions on two compilers, or two versions of one compiler. Your register map would then depend on the toolchain, which is the opposite of what a register needs.

Do not describe a hardware register with bit-fields in portable code. Use a fixed-width integer and named mask and shift constants. The mask is exact, and the same expression works on every compiler that follows the standard.

Shifts instead of casts

A sensor usually sends its values big-endian: the high byte comes first on the wire. To build a 16-bit value, combine the bytes with shifts. Each byte is promoted to int first, so cast it to uint16_t before you shift the high byte up, which keeps the arithmetic in the type you intend (lesson 45). 

/* frame[1] is the high byte, frame[2] the low byte: big-endian on the wire */
uint16_t temp = (uint16_t)(((uint16_t)frame[1] << 8) | (uint16_t)frame[2]);

This expression gives the same result whatever byte order the CPU uses, because it works on values, not on memory. The alternative, copying the two bytes into a uint16_t with memcpy or a cast, copies them in the host's byte order. Whether that is right depends on the CPU, so it is not portable.

Endianness on the Cortex-M

Endianness is the order of bytes in a multi-byte value in memory. Little-endian puts the least significant byte at the lowest address. The toolchain used in this course predefines __ARMEL__ and __BYTE_ORDER__ as little-endian for both the Cortex-M0+ (RP2040) and the Cortex-M3 (STM32F1). Compiling a file with -dM -E prints those macros, so you can check your own target. Little-endian is the default for these cores, so a plain memcpy of a big-endian wire value gives the wrong number on them. Code that must also run on a big-endian target needs the shift form.

Unions

A union puts all its members at the same address. It can overlay a 32-bit register on four bytes, which looks convenient. In portable C, though, reading a union member other than the one last written is subtle, and the result depends on the rules you rely on. Use shifts to convert bytes to a value. Use a plain struct for a register block, as lesson 47 shows.

Packing

A compiler adds padding inside a struct so each member sits at its natural alignment. A packed struct removes that padding. GCC documents the attribute on a struct, which applies to every member. GCC manual, common attributes: packed 

typedef struct __attribute__((packed)) {
    uint8_t  header;      /* offset 0 */
    uint16_t temp;        /* offset 1 with packing; offset 2 without */
    uint8_t  status;      /* offset 3 with packing; offset 4 without */
} WireFrame;

Packing describes the layout of the struct in memory. It does not change the byte order, and it does not make a shift unnecessary. A packed uint16_t at offset 1 is an unaligned access, and on some cores that faults or runs slowly. Use packing when you need a struct to match an agreed layout, and still parse the value with shifts.

"How would you parse a 16-bit big-endian value from a byte buffer in portable C, and why not cast the buffer?" Answer out loud in 60 seconds, then compare.

Model answer

Read the two bytes with explicit indices, cast each to uint16_t, shift the high byte left by eight, and OR in the low byte. That works on any CPU. Casting the buffer to a uint16_t pointer depends on alignment and byte order, and on some cores an unaligned load faults or gives the wrong value. A bit-field struct for the same data depends on the compiler's layout, so it is not portable either.
