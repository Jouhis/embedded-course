DMA

A DMA controller moves bytes between a peripheral and memory while the CPU runs other code. It is how a UART can receive a whole frame, or an ADC can scan six channels, without an interrupt per byte.

By the end of this lesson you can set up a DMA transfer on paper: choose the direction, the count and the increment settings, use circular mode with half-transfer and transfer-complete interrupts to build a receive buffer, and explain when cache coherence matters.

The idea

Without DMA, a UART receive interrupt runs for every byte. The CPU fetches the status, reads the data register, stores the byte and returns. With DMA the peripheral raises a request, and a DMA controller performs the transfer as a bus master, reading the peripheral's data register and writing into RAM. The CPU is involved only at the end, or at a half-way point you choose. The DMA controller shares the bus with the CPU through the bus matrix (lesson 37). When both want the same memory, an arbitration rule decides who waits. The CPU usually waits a few cycles, not a whole transfer.

A transfer is defined by a few registers: the peripheral address, the memory address, the number of items, and a control word. In the STM32F1 CMSIS header each channel has these fields in a DMA_Channel_TypeDef structure, with the control bits DMA_CCR_CIRC (circular mode), DMA_CCR_HTIE (half-transfer interrupt), DMA_CCR_TCIE (transfer-complete interrupt), DMA_CCR_MINC (memory increment) and DMA_CCR_PSIZE (peripheral size). Channels and requests

The STM32F1 DMA controllers have several channels. Each channel serves a fixed set of peripheral requests, so the programmer picks a channel that matches the peripheral. The mapping table is in the DMA chapter of RM0008 and is not repeated here: read it for the part you use, rather than trusting a number from memory. The CMSIS header defines an interrupt for each channel, for example DMA1_Channel1_IRQn through DMA1_Channel7_IRQn (stm32f103xb.h).

Circular mode and the ring buffer

In normal mode a transfer stops when the count reaches zero. In circular mode the counter reloads and the transfer starts again from the beginning of the buffer. The receive buffer then never runs out: the DMA writes into it forever, and the CPU reads behind the write position.

Two interrupts tell the CPU how far the DMA has got. The half-transfer interrupt says the first half of the buffer is full, and the transfer-complete interrupt says the second half is full. The handler processes the half that is ready, while the DMA fills the other half. This is the same ring-buffer idea as lesson 70, but the producer is the DMA rather than an ISR.

If the CPU is slower than the DMA, the DMA overwrites data that has not been read yet. The handler must finish one half before the DMA fills the other. Size the buffer so that the worst-case handling time is shorter than the time to fill half of it.

UART receive and ADC scan

For a UART, the peripheral request fires once per received byte. With a 256-byte circular buffer and a receive at 115200 baud, a frame of 10 bits per byte (one start bit, eight data bits, one stop bit) gives the time to fill half the buffer. The ADC uses the same idea in scan mode: the DMA stores one sample per channel into an array, and the buffer holds whole scans, so the array index is the channel number.

Cache coherence: an M7 issue, not an F1 issue

A DMA writes to RAM directly. If the CPU has a data cache, the cache can hold an old copy of that RAM, and the CPU reads the stale value. The fix is a cache invalidate before the read, or a non-cacheable memory region for the buffer. The Cortex-M3 on the STM32F1 has no data cache, so this issue does not arise on the course's Blue Pill. It does arise on Cortex-M7 parts, which have a data cache, so the habit is worth learning now.

You can lay out a DMA receive transfer on paper: the direction, the count, circular mode, the half and full interrupts, and the buffer size that keeps the handler in time.

Exercises

Work these with pencil first, then check the answer in the quiz. The numbers are examples for practice, not device limits.

"You receive a 1 kHz sensor stream over UART. Why would you use DMA with a circular buffer instead of a receive interrupt per byte?" Answer out loud in 60 seconds, then compare.

Model answer

Per-byte interrupts cost a context switch for every byte. At a few kilobytes per second that is a lot of entries, and each one adds latency to everything else. With DMA the hardware moves each byte without the CPU. A circular buffer with half-transfer and transfer-complete interrupts means the CPU wakes twice per buffer, and it processes a whole half at a time. The trade-off is buffer sizing: the handler must finish one half before the DMA fills the other, and the DMA cannot tell you about a framing error on its own. Use the UART error interrupt as well, and check the handler's worst-case time against the fill time.
