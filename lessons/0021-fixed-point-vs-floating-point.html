Fixed-point vs floating-point

Your sensor gives you 0.37 of something, and your Cortex-M0+ has no floating-point hardware. Fixed-point arithmetic is how firmware handles fractions on such a core, and you need to know it before you write a PID loop or a filter.

By the end of this lesson you can store a fraction in Q15 or Q16.16, convert a value to and from its stored integer, and explain why a Cortex-M0+ or M3 is better served by fixed point than by float.

Where we are and why it matters

Lesson 19 showed you how an integer register is read as bits, and lesson 20 showed you how to shift and mask those bits. Fixed-point arithmetic is built from exactly those two things. It stores a fraction as an ordinary integer, and the programmer keeps track of where the point is. Lesson 22 gave you the logic gates, and lesson 23 will give you the adder that does the work.

The problem appears as soon as a sensor value has to be filtered or combined with a gain. A temperature in degrees, a motor speed scaled to 0 to 1, or a PID controller's error term are all fractions. A PID loop that runs 1000 times a second on a 125 MHz RP2040 has about 125,000 cycles per pass to share with everything else. If each multiply costs a software float routine, the loop can overrun. Firmware engineers therefore decide the number format before they write the first line of the filter, and fixed point is the usual answer on a core without a float unit.

A fraction stored as an integer

A computer stores a fraction in one of two ways. The first is a plain integer that the programmer scales, so the value 0.37 is stored as the integer that is 0.37 times some power of two. The second is a float, which stores a sign, an exponent and a mantissa, so the binary point moves with the size of the number. The first way is fixed point. The binary point stays in one place, and only the programmer knows where it is.

A Q format names the split. Qm.n has n fraction bits, and the stored integer x means x ÷ 2n. Some authors write the sign bit separately, so Q15 is written Q1.15. The convention in this course counts the sign in the integer bits, so Q15 is a 16-bit signed value with 15 fraction bits, and Q16.16 is a 32-bit signed value with 16 integer bits (including the sign) and 16 fraction bits. The table shows what the two formats hold. The "Q" stands for quotient, which is the common name in the DSP literature.

The conversion is one multiply and a round. To store a value v in Qn, compute v × 2n and round to the nearest integer. To read it back, divide the stored integer by 2n. The rounding is the only error at the moment of storing, so the precision of a Q15 value is 1 ÷ 32768, which is about 0.00003.

Worked example: store 0.37 in Q15

  1. Multiply by the scale: 0.37 × 215 = 0.37 × 32768 = 12124.16.
  2. Round to the nearest integer: 12124. The rounding error is 0.16 counts.
  3. Write the stored integer in hex: 12124 is 0x2F5C, which is 0010 1111 0101 1100. This is the value the register or variable holds.
  4. Read it back: 12124 ÷ 32768 = 0.3699951. The error is 0.0000049, which is about 0.0013 per cent of the value and far below any sensor's noise.

The same number in Q16.16 would be 0.37 × 65536 = 24248.32, which rounds to 24248. The stored integer changes because the scale changes, not the value. Using the wrong scale for the format is a common slip.

Adding fixed-point values

Two values in the same Q format add with one integer add, because their binary points are in the same place. The CPU does not know there is a point at all. 0.25 plus 0.5 in Q15 is 8192 plus 16384, which is 24576, and 24576 ÷ 32768 is 0.75. This is why fixed point is cheap: addition costs exactly what an integer addition costs.

Addition has a hazard that is easy to miss. If the sum is larger than the format can hold, the integer wraps around silently. In Q15, 0.9 is stored as 29491, and 29491 + 29491 is 58982. That does not fit in a signed 16-bit integer, so it wraps to 58982 − 65536 = −6554, which reads as −0.2. The code keeps running and the answer is wrong by more than a whole unit. The fix is to check the range, or to saturate, which means clamping the result to the largest or smallest value the format holds. The code section below does that.

Multiplying: widen, multiply, then shift

A multiply is where fixed point needs thought. The product of two Qn numbers has 2n fraction bits, because each input carried n of them. So the stored product is in Q2n, and you must shift it right by n to return to Qn. The intermediate product is also wider than either input. Two 16-bit values need up to 32 bits for their product, so the intermediate must be a 32-bit integer, or the high bits fall off before the shift. 

// Q15 multiply: the product of two int16_t needs 32 bits, so widen first.
static int16_t q15_mul(int16_t a, int16_t b) {
    int32_t p = (int32_t)a * (int32_t)b;   // now Q30
    return (int16_t)(p >> 15);              // back to Q15
}

Worked example: 0.5 times 0.5 in Q15

  1. Store the inputs. 0.5 is 16384 in Q15, for both a and b.
  2. Multiply the integers: 16384 × 16384 = 268435456, which is 228. This is Q30, because 0.5 × 0.5 = 0.25 and 0.25 × 230 = 228.
  3. Shift right by 15 to return to Q15: 228 ÷ 215 = 213 = 8192.
  4. Check: 8192 ÷ 32768 = 0.25. The answer is right.

Now see what the widening is for. If the product is stored in an int16_t before the shift, the program keeps only the low 16 bits of 228, and those low bits are all zero. The result is 0 instead of 0.25. The same product stored in an int32_t keeps all 29 bits, and the shift then gives 8192. A multiply that quietly returns zero is a real symptom of this mistake, and the fix is the widening in the line above.

Floating point: the cost of a flexible point

A float stores three fields. The sign is one bit. The exponent is eight bits, stored with a bias of 127. The mantissa is 23 bits, and together with an implied leading 1 it gives 24 significant bits. The value is (−1)sign × 1.mantissa × 2exponent − 127. The point floats to keep the precision roughly constant over a huge range, which is the advantage of floats. The IEEE 754 single-precision format is what C's float uses on most compilers, and the RP2040 datasheet says the ROM library uses the IEEE single and double formats throughout (RP2040 datasheet, section 2.8.3.2, Fast Floating Point Library).

Worked example: what is inside 0x3F800000?

  1. Write the 32 bits in groups: 0 01111111 00000000000000000000000.
  2. The sign bit is 0, so the number is positive.
  3. The exponent field is 0111 1111, which is 127. Subtract the bias: 127 − 127 = 0.
  4. The mantissa is all zeros, so the value is 1.000… × 20 = 1.0. That is the float for 1.0.

Now the float for 0.37 is 0x3EBD70A4. Its exponent field is 125, so the power is 125 − 127 = −2, and 2−2 = 0.25. The mantissa then carries the rest of the value, and the stored result is 0.3700000047683716. Compare that with the Q15 value of 0.3699951. The float is more accurate here, but it cost 32 bits and an unpacking step every time you use it.

The cost of a flexible point is paid in the arithmetic. A float add or multiply is a long sequence of integer steps: separate the sign, exponent and mantissa, align the exponents, add or multiply the mantissas, normalise, and round. Without a floating-point unit the compiler calls a library routine for each operation, and the routine runs all those steps in software. The RP2040 bootrom contains an optimised single-precision library, which the SDK uses for the C operations, but it is still a routine, not one instruction.

The RP2040 has a hardware integer divider in the SIO block, which is an 8-cycle divider and not an FPU. The datasheet says that when the SDK's default divider support is enabled, it maps C's / and % operators to the hardware divider (RP2040 datasheet, section 2.3.1.5, Integer Divider).

Which cores have a float unit

The Arm Cortex-M processor comparison table lists the floating-point unit for each core. The Cortex-M0, M0+, M1, M23 and M3 have no FPU at all. The Cortex-M4 has an optional single-precision FPU, and the cores after it in the table list an FPU option too. The same table shows that the M0+ has no hardware divide and no DSP extension, while the M3 has a hardware divide. For this course the rule is simple: the RP2040's Cortex-M0+ and the STM32F103's Cortex-M3 both need software for float (Arm Cortex-M processor comparison table, rows "Floating-Point Unit (FPU)", "Digital Signal Processing (DSP) Extension" and "Hardware Divide").

Why fixed point on a Cortex-M0+ or M3

The fixed-point operations are integer operations, and the core does them in one or a few instructions. A Q15 multiply is a 32-bit multiply, a shift and a store. The M0+ has no hardware divide, and the M3 has one, but neither has a float unit. So the choice is between a few cycles of integer work and a software float routine that can cost many times more, with the code size to match. A filter or a PID loop that runs 1000 times a second has to fit the budget, and fixed point is the usual answer.

Fixed point has costs too. You must choose the Q format for each value so it neither overflows nor loses all its precision, and you must add the shifts yourself. Lesson 107 (PID control) and lesson 106 (digital filters) use fixed point for exactly this reason.

Choosing a format: a value from −5 to +5

Suppose a control signal must hold any value from −5 to +5, and you want to store it in 16 bits. Count the integer bits first. You need 3 bits for the magnitude up to 5, and one for the sign, so you need 4 integer bits in the Q notation of this lesson. That leaves 12 fraction bits, which is Q4.12. Its range is −8.0 to 7.99976, so it covers ±5 with room to spare. Its resolution is 1 ÷ 4096, which is 0.000244. A Q15 value would overflow at 1.0, and a Q2.14 value would stop just short of 2. The right format is the one whose integer part covers the largest value and whose fraction part is as fine as the algorithm needs.

Saturation: clamp instead of wrap

The overflow in the addition section wraps, and that is almost never what a controller wants. A saturating add clamps the result to the largest or smallest value the format holds. It widens the sum, so the sum itself cannot wrap, and then it clamps. The stdint.h constants INT16_MAX and INT16_MIN give the limits. 

// Q15 add with saturation: widen, add, then clamp to the 16-bit range.
static int16_t q15_add_sat(int16_t a, int16_t b) {
    int32_t s = (int32_t)a + (int32_t)b;   // the 32-bit sum cannot wrap here
    if (s > INT16_MAX) return INT16_MAX;      // clamp at just under +1.0
    if (s < INT16_MIN) return INT16_MIN;      // clamp at −1.0
    return (int16_t)s;                     // in range: the cast is exact
}

Line by line: the first line widens both inputs to 32 bits before the add, so the sum of two 16-bit values always fits. The two if lines compare the sum with the format's limits and return the limit instead of the wrapped value. The last line is reached only when the sum is in range, so the narrowing cast loses nothing. With this function, 0.9 + 0.9 gives 0.99997 instead of −0.2.

An overflow in fixed point is silent. 0.9 + 0.9 in Q15 wraps to a negative value, and the code keeps running. Check the range of each intermediate result, or saturate it, before you rely on the sum.

Common mistakes and how to spot them

Five mistakes account for most fixed-point bugs. Each has a symptom that shows up in the output or the timing.

  1. Multiplying into a narrow type. The product of two Q15 values stored in an int16_t before the shift keeps only the low 16 bits. For 0.5 × 0.5 that is zero. The symptom is a multiply that returns zero, or a small wrong value, whenever the product has high bits set. The fix is the widening to int32_t.
  2. Forgetting the shift after a multiply. Without the shift, the 0.5 × 0.5 product reads as 268435456 ÷ 32768 = 8192.0 when it should read as 0.25. The symptom is a result 32768 times too large, which saturates the next stage of the controller. The fix is one shift by the Q format's fraction bits, after every multiply.
  3. Mixing formats. Adding a Q15 value to a Q16.16 value as plain integers gives nonsense. Take 0.5 in Q15 (16384) plus 0.5 in Q16.16 (32768). The integer sum is 49152, which reads as 0.75 in Q16.16. The right answer is 1.0. The symptom is a sum that is wrong by a factor that depends on the formats. The fix is to shift one operand so both share a format before the add.
  4. Silent overflow. The 0.9 + 0.9 example above gives −0.2 with no warning. The symptom is a controller that suddenly drives the output the wrong way at a large input. The fix is the saturating add, or a range check that you test at the extremes.
  5. Choosing float because it is easier. A float version of a 1 kHz filter may pass every unit test on the PC and then overrun its time budget on the board. The symptom is a loop whose period grows with the input, which you see with a timer or a logic analyzer. The fix is to measure the loop period first, and to move the arithmetic to fixed point if the budget is exceeded.

In real projects

Motor-control and audio firmware use fixed point almost everywhere on small cores. Engineers keep a table of the Q format for every variable, often in a comment at the top of the file, and they review each multiply for the widening and the shift. A reviewer who sees a multiply of two int16_t values without a 32-bit intermediate will ask for it to be changed before the code is merged. The same reviewer checks that every add either cannot overflow or saturates.

On the RP2040 the Pico SDK provides float and double routines through the bootrom, so float code works. Teams still choose fixed point for inner control loops, and they measure the loop time with a GPIO pin and a logic analyzer before they decide.

Summary

  • Fixed point stores a fraction as an integer scaled by 2n. In Qm.n, the stored integer x means x ÷ 2n.
  • To store a value, multiply by the scale and round. To read it back, divide by the scale. The rounding error is the only error at the store.
  • Adding two values in the same format is one integer add. Overflow wraps silently, so check the range or saturate.
  • A product has twice the fraction bits. Widen the intermediate to 32 bits and shift right by n to return to Qn.
  • A float stores a sign, an 8-bit exponent with bias 127 and a 23-bit mantissa, and each operation is a long integer routine on a core with no FPU.
  • The Cortex-M0+ and M3 have no FPU. The RP2040 divider is an 8-cycle integer unit, not a float unit.
  • Choose the Q format from the largest value that must fit, then give the rest of the bits to the fraction.
