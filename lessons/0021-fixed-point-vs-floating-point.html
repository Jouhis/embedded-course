Fixed-point vs floating-point

Your sensor gives you 0.37 of something, and your Cortex-M0+ has no floating-point hardware. Fixed-point arithmetic is how firmware handles fractions on such a core, and you need to know it before you write a PID loop or a filter.

By the end of this lesson you can store a fraction in Q15 or Q16.16, convert a value to and from its stored integer, and explain why a Cortex-M0+ or M3 is better served by fixed point than by float.

The idea

A computer stores a fraction either as a plain integer that the programmer scales, or as a float with an exponent. In fixed point, the binary point stays in the same place. A Q format names the split: Qm.n has n fraction bits, so the stored integer x means x ÷ 2n. Q15 is a 16-bit signed value with 15 fraction bits. Q16.16 is a 32-bit signed value with 16 integer bits and 16 fraction bits. The "Q" stands for quotient, which is the common name in the DSP literature.

Adding two values in the same Q format is a plain integer add, because the binary point lines up. Multiplying needs care. The product of two Qn numbers has 2n fraction bits, so you shift the product right by n to return to Qn. Use a wider intermediate type, or the high bits fall off. 

// Q15 multiply: the product of two int16_t needs 32 bits, so widen first.
static int16_t q15_mul(int16_t a, int16_t b) {
    int32_t p = (int32_t)a * (int32_t)b;   // now Q30
    return (int16_t)(p >> 15);              // back to Q15
}

Floating point: the cost of a flexible point

A float stores a sign, an exponent and a mantissa, and the binary point floats to keep the precision roughly constant. The IEEE 754 single-precision format is what most C compilers use for float. The RP2040 datasheet describes both the single and double formats in its ROM float library. RP2040 datasheet, section 2.8.3.2 (Fast Floating Point Library).

Floats are convenient, but a float add or multiply is a long sequence of integer steps: align the exponents, add the mantissas, normalise, round. Without an FPU, the compiler calls a library routine for each operation. The Arm comparison table lists no FPU for the Cortex-M0, M0+ and M3, and the only FPU options are on the M4, M7 and later cores. Arm Cortex-M processor comparison table, row "Floating-Point Unit (FPU)".

The RP2040 has a hardware integer divider in the SIO block, which the Pico SDK uses for / and %. It is an 8-cycle divider, not an FPU. RP2040 datasheet, section 2.3.1.5.

Why fixed point on a Cortex-M0+ or M3

The fixed-point operations are integer operations, and the core does them in one or a few instructions. A Q15 multiply is a 32-bit multiply and a shift. The M0+ has no hardware divide, and the M3 has one, but neither has a float unit. So the choice is between a few cycles of integer work and a software float routine that can cost many times more, with the code size to match. A filter or a PID loop that runs 1000 times a second has to fit the budget, and fixed point is the usual answer.

The costs are real. You must choose the Q format for each value so it neither overflows nor loses all its precision, and you must add the shifts yourself. Lesson 105 (PID control) and lesson 104 (digital filters) use fixed point for exactly this reason.

An overflow in fixed point is silent. 0.9 + 0.9 in Q15 wraps to a negative value, and the code keeps running. Check the range of each intermediate result, or saturate it, before you rely on the sum.

"Why would you use Q15 instead of float on a Cortex-M0+ filter?" Answer out loud in 60 seconds, then compare.

Model answer

The M0+ has no FPU, so each float operation becomes a library call with many integer steps. Q15 keeps the work to a multiply, a shift and an add, which are cheap on the core. The cost is that I must track the binary point, check the range of each value, and widen the intermediate product so the high bits survive.
