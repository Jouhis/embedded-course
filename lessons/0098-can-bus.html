CAN bus

CAN joins the engine controller, the brakes and the door modules of a car on one pair of wires. Several nodes can talk at once, and the bus decides who goes first without losing a message. This lesson is concept only, and you work through the bit-level rules by hand.

By the end of this lesson you can predict which node wins CAN arbitration from the identifiers, and explain why bit stuffing and the error states keep a bus with many nodes reliable.
Why this lesson has no simulator task. Wokwi does not simulate CAN, and the STM32 in the simulator has no CAN or USB device (NOTES.md). The exercise below runs the arbitration rules in the page instead. To see real frames, you need a Blue Pill, a CAN transceiver board and a second node, which is lab-bench work for later.

The idea: two wires, dominant and recessive

CAN runs on two wires, CANH and CANL, and carries a bit as a voltage difference between them. In the quiet state both wires sit near 2.5 V. A dominant bit drives CANH up to about 3.5 V and CANL down to about 1.5 V, which is a logic 0. A recessive bit leaves the wires quiet, which is a logic 1. The difference between the wires cancels out common-mode noise, which is why CAN tolerates a noisy car better than a single-ended wire does (TI SLOA101, section 7 and Figure 7). Dominant is 0 and recessive is 1, the opposite of the pull-up convention you know from lesson 16. A recessive level is what the bus rests at. Any node can make a dominant level, and a dominant level wins the wire.

The bus behaves as a wired AND. If one node sends dominant (0) while another sends recessive (1), the bus reads 0. This is the same idea as an open-drain line with a pull-up, and it is the key to arbitration.

Arbitration: the lowest identifier wins

Several nodes may start a frame in the same bit time. Each transmitter reads the bus while it sends. If it sends a recessive bit and reads a dominant one, another node is sending a dominant bit at that position, so it stops and waits. The message is not destroyed: the winner keeps going, and the loser retries later (TI SLOA101, section 4.1). Arbitration is on the identifier only, and it happens bit by bit, from the most significant bit down. It costs no extra time, because the identifier is sent anyway.

The identifier is the message's priority. Because a dominant bit overwrites a recessive one, the node with the lowest identifier has the most zeros at the first bit where the IDs differ, so it keeps the bus. Work the rule with the exercise below.

The frame: what goes on the wire

A standard data frame, in the 11-bit identifier format (CAN 2.0A), has these fields in order: a start-of-frame bit, the 11-bit identifier, the remote-transmission-request bit, the identifier-extension bit, the 4-bit data length code (DLC), 0 to 8 data bytes, a 15-bit CRC followed by its delimiter, an acknowledge slot and its delimiter, and the end of the frame (TI SLOA101, sections 2 and 3). The TI text gives the lengths of the CRC field and the ACK field, and the Bosch CAN 2.0 specification, which defines the format, is the reference for the rest.

FieldBitsWhat it does
Start of frame (SOF)1A dominant bit that tells every node a frame has started

ACK1, plus a delimiterEvery node that received the frame correctly overwrites the recessive ACK bit with a dominant one

The data field is at most 8 bytes in classic CAN. The ACK slot is the receiver's acknowledgment: a sender that reads a recessive ACK knows nobody received the frame correctly, and it retransmits (TI SLOA101, section 3).

Bit stuffing: keeping the clock alive

CAN has no separate clock line. Each node resynchronises on the edges of the bits it receives, so a long run of identical bits would let the clocks drift apart. To prevent that, the transmitter inserts one bit of the opposite level after every five identical bits in a row. The receiver removes those stuff bits. A sixth identical bit in a row is a stuffing error (TI SLOA101, section 6). Stuffing applies from the start of frame up to the CRC. The CRC delimiter, the ACK field and the end of frame are not stuffed, because they have fixed forms.

Errors, and the three error states

CAN checks each frame in five ways (TI SLOA101, section 6): the bit monitor (a node compares what it sent with what it reads), bit stuffing, the CRC, the fixed-form delimiters, and the ACK. An error frame, six dominant bits in a row, breaks the normal pattern on purpose so every node sees the error. Each controller counts its own errors in two counters, the transmit error counter (TEC) and the receive error counter (REC).

Those counters move a node through three states: error-active, which sends normal error frames; error-passive, which may send only passive error flags; and bus-off, which takes the node off the bus until it recovers. The thresholds are in the Bosch CAN 2.0 specification. Check the numbers there before you rely on them, because this lesson did not open that document.

CAN FD and the transceiver

CAN FD keeps the same arbitration and adds a faster data phase and payloads up to 64 bytes per frame. Its specification is a separate document, and this lesson does not cover its details. The transceiver is the analogue part between the controller and the wires: it turns the controller's logic-level TX and RX into the differential CANH and CANL levels, and it limits the fault current when a wire is shorted. A microcontroller with a CAN peripheral needs one.

The STM32F103 bxCAN controller

The Blue Pill's STM32F103 has one CAN controller, bxCAN. The CMSIS header in this workspace gives its base address and its shape. CAN1 is at 0x40006400 (third_party/cmsis-device-f1/Include/stm32f103xb.h, the CAN1_BASE definition). The CAN_TypeDef structure has three transmit mailboxes, two receive FIFOs and fourteen filter banks. The mailboxes are why the controller can queue three frames and send the one with the lowest identifier first. The reference manual RM0008 describes the bxCAN registers in full. 

/* stm32f103xb.h: the controller's shape, not a driver */
typedef struct {
    CAN_TxMailBox_TypeDef sTxMailBox[3];   /* three transmit mailboxes */
    CAN_FIFOMailBox_TypeDef sFIFOMailBox[2]; /* two receive FIFOs */
    CAN_FilterRegister_TypeDef sFilterRegister[14];
} CAN_TypeDef;

"Two ECUs start transmitting at the same time. How does CAN decide who wins, and what happens to the loser?" Answer out loud in 60 seconds, then compare.

Model answer

The bus is a wired AND: a dominant 0 overwrites a recessive 1. Each transmitter compares what it reads with what it sends, bit by bit, starting with the identifier's most significant bit. The node with the lowest identifier never sees a dominant bit overwrite its own zero, so it keeps the bus. A node that sends a 1 and reads a 0 stops at once and retries later, without corrupting the winner's frame. The identifier is therefore also the priority.
