1. "Trace GPIOC->BSRR = GPIO_BSRR_BR13; from the C line to the LED."

Model answer

The preprocessor expands the macro to (0x1UL << 29) written through a pointer at GPIOC base 0x40011000 plus the BSRR offset 0x10. The compiler and assembler emit a 32-bit mov.w for the constant and a 16-bit str to [r4, #16]. The store goes over the bus to the APB2 bridge and reaches the GPIOC block, where bit 29 resets pin 13. The Blue Pill's LED is driven low, which lights it, if the board's active-low wiring is right, which you should check on the schematic.

2. "Why must a Cortex-M3 set flash wait states before it raises the clock, and what does the HAL do?"

Model answer

Flash cannot deliver data at a higher clock without extra wait states, so reading flash at the faster clock with the old latency returns bad data. The HAL raises the LATENCY field of FLASH_ACR first, verifies it, and only then changes the clock source and the PLL. The order is part of the recipe, and the vendor's reference manual gives the thresholds.

3. "Walk from reset to main(), and say where a global variable lives."

Model answer

The core reads the initial stack pointer and the reset vector from the vector table, then jumps to Reset_Handler. The handler calls SystemInit for the clock, copies .data from its flash load address to RAM, zeroes .bss, runs the library initialisers and calls main. A global with an initial value lives in RAM in .data, with its starting value stored in flash. A zero-initialised global lives in RAM in .bss. A const global stays in flash in .rodata.
