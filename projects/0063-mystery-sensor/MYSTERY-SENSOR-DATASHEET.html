MYS-1 digital temperature sensor

A fictional I2C sensor for lesson 63. Its behaviour is what this page says, and the Wokwi chip in chip/mystery.chip.c implements exactly that.

Teaching part. The MYS-1 is invented for this course. It is not a real product, so you cannot buy it. The layout follows the style of a real datasheet, so that you practise reading one.

1. Overview

The MYS-1 measures temperature with an on-chip sensor and reports it as a signed 16-bit number over I2C. It has one identity register, a control register that starts measurement, a status register with a data-ready flag, and a pair of temperature registers.

  • Supply: 3.3 V (VCC), ground (GND).
  • Interface: I2C, standard mode (100 kHz) and fast mode (400 kHz). The MYS-1 is a target device, so the master starts every transaction.
  • Temperature: −40 °C to +85 °C, resolution 1/64 °C.

3. Register map

3.1 Registers

AddressNameAccessResetFunction
0x0FWHO_AM_IR0xA7Fixed identity value. Use it to check that the right part answers at the address.
0x20CTRLR/W0x00Bit 0, MEAS_EN: 1 starts periodic measurement, 0 stops it. Bits 7 to 1 are not implemented and read 0.
0x27STATUSR0x00Bit 0, DRDY: 1 means a new temperature sample is ready and has not been read yet.
0x28TEMP_LRundefinedLow byte of the temperature. Reading it latches the newest sample (see section 4).
0x29TEMP_HRundefinedHigh byte of the latched temperature. Reading it clears DRDY.

Any other register address reads 0x00. Writes to read-only registers are ignored.

3.2 Transactions and the register pointer

The MYS-1 has a register pointer. It is set by the first byte the master writes in a transaction. After that, every byte is data for the register at the pointer, and the pointer increments after each byte. A read returns the byte at the pointer, and the pointer increments too.

OperationBus sequence
Write one registerSTART, address + W, pointer, data, STOP
Read one registerSTART, address + W, pointer, RESTART, address + R, data, STOP
Read TEMP_L and TEMP_HSTART, address + W, 0x28, RESTART, address + R, low byte, high byte, STOP
The read must use a RESTART (repeated start) after the pointer, not a STOP followed by a new START. The MYS-1 accepts both, but a STOP lets another master use the bus in between, and it costs time.

4. Temperature data and timing

4.1 Data format

The temperature is a signed 16-bit two's-complement value in units of 1/64 °C. TEMP_L is the low byte and TEMP_H is the high byte. To convert: 

temperature (°C) = (int16_t)((TEMP_H << 8) | TEMP_L) / 64.0

Examples:

TEMP_HTEMP_LRaw (decimal)Temperature
0x050xA0144022.50 °C
0xFF0xC0−64−1.00 °C
Convert with a signed type. If you divide the unsigned value 0xFFC0 by 64, you get 1023.0, not −1.0. Lesson 45 explains why.

4.2 Timing

  • Measurement starts when CTRL bit 0 (MEAS_EN) is set. Before that, DRDY stays 0 and the temperature registers hold the reset value.
  • A new sample is produced every 500 ms while measurement is enabled. The first sample appears 500 ms after MEAS_EN is set.
  • Each sample sets DRDY. Reading TEMP_L latches the newest sample, so TEMP_L and TEMP_H always come from the same sample. Reading TEMP_H clears DRDY.
  • If you do not read a sample before the next one arrives, the older value is lost. Samples are not queued.
A driver that reads the temperature without checking DRDY may read the same sample twice, or read a value that was not yet ready. Wait for DRDY, and time out so that a missing sensor does not hang the firmware.

5. Typical usage

  1. Read WHO_AM_I (0x0F). Expect 0xA7. If you get anything else, the part is missing or is not a MYS-1.
  2. Write CTRL (0x20) with 0x01 to enable measurement.
  3. Wait for DRDY. Poll STATUS (0x27) every few milliseconds, and give up after about 2 s.
  4. Read TEMP_L and TEMP_H (0x28, two bytes, one burst). Reading TEMP_H clears DRDY.
  5. Convert the value with the formula in section 4.1.
  6. Repeat from step 3 for the next sample.
