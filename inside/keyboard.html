Inside a keyboard

From a pressed key to a letter on the screen

A keyboard looks like the simplest computer peripheral there is, and it hides a small embedded system that does a surprising amount of work. Inside it a microcontroller reads the keys hundreds or thousands of times a second, cleans up what the metal contacts do, decides which keys are really down, and answers the computer over USB. On this page we follow one key press through all of that, and you can poke at each stage and see the signals.

You do not need to know any of it yet. Every term links to the glossary, and every stage names the lesson where the course teaches it properly, so treat this page as a map of what is coming.

A key as a switch on a pin

Each key is a switch with two metal contacts, and the microcontroller reads it through one GPIO pin set up as an input. A pull-up resistor inside the chip connects the pin to 3.3 V, so while the key is up the pin reads 1. Pressing the key connects the pin straight to ground, which overpowers the weak pull-up and makes the pin read 0. A pressed key reading 0 is called active low, and lesson 16 explains why the pull-up has to be there at all: without it the pin would be a floating input and read noise.

Hold the key below and watch the pin. The contacts are springy metal, so when they meet they hit, separate and hit again for a millisecond or two before they settle. That burst of edges is called bounce, and a program that types a letter on every falling edge types several letters for one press. Turn the debounce off and try it.

The fix is a debounce, and the one shown here is the integrator you write yourself in lesson 52. The firmware reads the pin once per millisecond and keeps a counter that climbs while the pin reads pressed and falls while it reads released. The key only counts as pressed when the counter reaches the top, which takes 10 pressed readings in a row by default. A bounce is too short to get there, so one press gives one letter, at the cost of about 10 ms of delay. Try the worn switch with a 2-sample window to see what happens when the window is shorter than the bounce.

Sixteen keys on eight pins

A full keyboard has around a hundred keys, and a microcontroller does not have a hundred spare pins. Keyboards solve this with a matrix: the keys sit at the crossings of row wires and column wires, so 4 rows and 4 columns reach 16 keys with 8 pins, and 8 by 16 would reach 128 keys with 24. The price is that the firmware can no longer read all keys at once. It has to scan them one row at a time.

The scan below drives one row low and leaves the other rows at Hi-Z, which means the pin is switched to an input and neither drives the wire high nor low. Each column has a pull-up, so a column reads 0 only when a pressed key connects it to the driven row. The firmware stores the four column bits of each row in a byte of RAM, and after the last row it knows the state of every key. Slow the scan down, press a few keys and step through the loop line by line.

Now press Q, W and A together. The firmware also sees S, a key nobody pressed. With row 2 driven low, current can flow from the S column up through W, along row 1, which floats, down through Q and back through A to row 2. A key that appears because of such a path is a ghost key, and the three real keys are the corners of a rectangle whose fourth corner is the ghost. A diode on each key lets current through in only one direction, as lesson 9 explains, which closes the backward path. Keyboards without diodes have to detect the rectangle in firmware and refuse to guess.

Two details in the loop are worth a closer look. Releasing the row to Hi-Z instead of driving it high matters, because with two keys down in the same column a high row and a low row would be shorted together through them. The short wait before reading gives the wires time to settle, since a line pulled up through a resistor rises slowly. Lesson 16 covers both, and the masks and shifts in ~(pins >> COL0) & 0xF are the subject of lesson 20.

The report the computer receives

The keyboard does not send letters. It sends a report, which for a standard keyboard is 8 bytes. The first byte holds one bit per modifier key such as Shift and Ctrl, the second is reserved, and the last six list the keys that are down as usage IDs, numbers the USB HID specification assigns to every key: A is 0x04, Q is 0x14 and 1 is 0x1E. The computer turns those numbers into letters using the keyboard layout chosen in its own settings, which is why the same keyboard can type on a French or a Finnish layout.

Six fields means six keys at once. Press 7 keys in the matrix above and the report fills with 0x01, which the specification calls ErrorRollOver. It tells the computer that too many keys are down to report, and the specification asks for the same answer when the keyboard cannot tell real keys from ghosts, which is what the ghost check option does.

Latency from finger to computer

The last stage is the trip over the cable, and it has a rule that surprises most programmers: a USB device never speaks first. The host computer asks the keyboard for a report at a fixed interval, set by the endpoint descriptor the keyboard sends when it is plugged in, and a new report waits in the keyboard until it is asked for. Lesson 102 explains how this interrupt transfer works.

The total delay is therefore the debounce time plus the wait for the next poll, and the wait depends on when in the polling cycle you happened to press. Press the key a few times, then press it 1000 times and compare the poll intervals. A 10-sample window always costs about 10 ms, while the poll adds anything from almost nothing to a whole interval.

The two parts of the delay are a design choice, and a firmware engineer trades them off against each other. A shorter debounce window is faster but has to stay longer than the bounce of the switch the keyboard uses, so the number comes from the switch's datasheet. A shorter poll interval is faster for the user but makes the host ask more often. A battery-powered keyboard also wants to sleep between scans to save energy, which is the subject of lesson 75.
