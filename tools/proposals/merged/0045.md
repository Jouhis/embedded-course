## GLOSSARY.md additions

Add a new group after `## Firmware and tools` and before `## RTOS`:

`## Embedded C`

**Integer promotion**:
The implicit conversion of a small integer type (such as uint8_t) to int, or to unsigned int if int cannot hold every value, before an arithmetic operator runs.
_Avoid_: Widening (informal; promotion is a rule of the language, not a cast)

**Undefined behaviour**:
A program action that the C standard does not define, so the compiler may do anything, including assume it never happens. Signed integer overflow is one example.
_Avoid_: Undefined (too short on its own in a review)

**Unsigned wraparound**:
Unsigned arithmetic is performed modulo 2 to the power of the type's width, so a value above the maximum wraps to zero. It is defined behaviour in C.
_Avoid_: Overflow (for unsigned types, which is defined)

**Usual arithmetic conversions**:
The rules that convert both operands of a binary operator, including comparisons, to a common type. A signed operand compared with an unsigned one is converted to unsigned.
_Avoid_: Implicit cast (informal)

**Volatile**:
A type qualifier that makes every access to an object an observable side effect, so the compiler reloads it and does not remove or merge the access. It is not atomic and gives no synchronisation between threads or ISRs.
_Avoid_: Atomic (volatile is not atomic)

**Atomic write**:
A single store that changes a register or bit without first reading it, so no other code can interleave between a read and a write. The STM32 BSRR register is an example.
_Avoid_: Thread-safe (broader and not the same claim)

**Read-modify-write**:
Three steps on a register or variable: load it, change bits, store it back. An interrupt between the load and the store can lose its change.
_Avoid_: Bit banging (a different, slower technique)

**Register struct**:
A C struct whose fields match a peripheral's registers at their offsets, so that a pointer to the block gives named access to every register. The CMSIS GPIO_TypeDef is an example.
_Avoid_: Register map (a map is the documented address layout; the struct is the C code that follows it)

**Bit-field**:
A struct member declared with a width in bits. Its layout within storage is implementation-defined, so it is not a portable register layout.
_Avoid_: Bitfield (the standard's spelling is two words)

**Endianness**:
The order in which the bytes of a multi-byte value are stored in memory. Little-endian puts the least significant byte first, which is the default on the Cortex-M cores used in this course.
_Avoid_: Byte order (acceptable in conversation, but the course uses endianness)

**Packed struct**:
A struct declared with the packed attribute, which removes padding so that members sit at the smallest possible alignment. It changes layout, not byte order.
_Avoid_: Compact struct (not a standard term)

**Function pointer**:
A variable that holds the address of a function, so calling it jumps to that function. A table of function pointers is the basis of callbacks and the vector table.
_Avoid_: Callback (a callback is the use; the pointer is the mechanism)

**Callback**:
A function registered with other code, which that code calls later when an event occurs. Outside the ISR context, a callback is a function pointer stored for later use.
_Avoid_: Handler (acceptable for one specific event handler)

**Include guard**:
A preprocessor pattern (`#ifndef` and `#define` around a header) that makes a header's contents take effect only once in each translation unit.
_Avoid_: Header guard (acceptable in conversation)

**X-macro**:
A macro that takes a list macro as an argument, so one list of names generates several declarations, such as an enum and a string table, that cannot drift apart.
_Avoid_: Table macro (informal)

**Static inline function**:
A function declared static and inline, so it has file-local linkage and the compiler may expand it at each call. It evaluates its arguments once and follows the usual conversion rules, which a function-like macro does not.
_Avoid_: Inline macro (a macro is text substitution, not a function)

## RESOURCES.md additions

Add to `### Vendor primary sources (most trusted: cite these for any hardware fact)`:

- [RM0008 reference manual, GPIO registers (ST)](https://www.st.com/resource/en/reference_manual/rm0008-stm32f101xx-stm32f102xx-stm32f103xx-stm32f105xx-and-stm32f107xx-advanced-armbased-32bit-mcus-stmicroelectronics.pdf)
  Already listed above; the section numbers to use are 3 (memory map) and the GPIO register section for CRL, CRH, IDR, ODR, BSRR, BRR and LCKR. Use for: lesson 47, the register struct and the BSRR bit numbers.

Add to `### Books (the canonical texts)` or a new `### Language references` section after `### Protocol and topic specifications`:

- [cppreference: Fixed-width integer types](https://en.cppreference.com/w/c/types/integer)
  The C page on uintN_t: exact width, no padding bits, and the rule that each type is defined only when the implementation provides it. Use for: lesson 45, and the integer rules in checkpoint 3.

- [cppreference: Conversions](https://en.cppreference.com/w/c/language/conversion)
  Integer promotions, usual arithmetic conversions, and conversion to unsigned types (modulo 2 to the power N). Use for: lessons 45 and 48, and checkpoint 3.

- [cppreference: Arithmetic operators, overflows](https://en.cppreference.com/w/c/language/operator_arithmetic)
  Signed integer overflow is undefined behaviour; unsigned arithmetic is modulo 2 to the power N. Use for: lesson 45.

- [cppreference: volatile](https://en.cppreference.com/w/c/language/volatile)
  Accesses to volatile objects are observable side effects, and volatile gives no atomicity, synchronisation or memory ordering between threads. Use for: lessons 46 and 47.

- [cppreference: Storage duration and linkage](https://en.cppreference.com/w/c/language/storage_duration)
  Static storage duration (initialised once, lasts the program) and internal linkage for file-scope static. Use for: lesson 46.

- [cppreference: Bit-field declaration](https://en.cppreference.com/w/c/language/bit_field)
  Which bit-field layout details are implementation-defined or unspecified. Use for: lesson 48.

- [cppreference: Replacement of macros](https://en.cppreference.com/w/c/preprocessor/replace)
  Function-like macros replace text, and the argument count must match. Use for: lesson 50.

- [GCC manual: Common attributes (packed)](https://gcc.gnu.org/onlinedocs/gcc/Common-Attributes.html)
  The packed attribute removes padding and gives members the smallest alignment. Use for: lesson 48.

- [CMake: target_compile_definitions](https://cmake.org/cmake/help/latest/command/target_compile_definitions.html)
  Adds definitions to one target, with PRIVATE, PUBLIC or INTERFACE, and the NAME=VALUE form. Use for: lesson 50 and the multi-target builds.

Add to `### Protocol and topic specifications` or the Tools section:

- [CMSIS-Core documentation (Arm)](https://arm-software.github.io/CMSIS_5/Core/html/index.html)
  The CMSIS core API reference. Use for: lesson 47, the register access conventions. Note that the reference pages do not define the __IO macro: it is in the header, core_cm3.h.

## Reference sheet proposal

The planned sheet `reference/stm32-registers.html` ("STM32F1 register cheat sheet", `tools/build_reference.py`) would be the natural home for lesson 47's facts. Proposed contents, as tables, not prose:

- GPIO port register offsets: CRL 0x00, CRH 0x04, IDR 0x08, ODR 0x0C, BSRR 0x10, BRR 0x14, LCKR 0x18.
- Base addresses: GPIOA 0x40010800, GPIOC 0x40011000 (verified in `third_party/cmsis-device-f1/Include/stm32f103xb.h`).
- BSRR bits: set pin n = bit n; reset pin n = bit n + 16. PC13 set is bit 13, reset is bit 29.
- PC13 configuration field in CRH: bits 23 to 20 (CNF13, MODE13).

I did not create this sheet, because it is planned for another author and needs a single owner for the register tables.
